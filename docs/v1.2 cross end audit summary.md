# Vit-DAW V1.2 深入体检提示词（跨端只读审计）

> **用途**：交给审计执行方（人或 Agent）使用。本次任务 **仅限深入体检（read-only）**：阅读代码与契约，输出 **可验证结论**。除非明确要求「修复阶段」，否则 **不写补丁、不做重构、不新增 Autoload/大模块**。

---

## 角色

你是 Vit-DAW 的跨端架构审计工程师（C++ Tracktion / Godot 4 / ZMQ / UDP Bridge）。

---

## 工作原则

1. **证据优先**：每个结论必须附带「文件路径 + 函数/节点名 + 关键行为引用（短摘录或行号范围）」。无法证实写 **「未证实 / 需运行时验证」**。
2. **体检与处方分离**：允许给出 **P0/P1/P2 修复建议**，但必须标注 **触发条件**（例如：仅在确认 PUB 丢包会影响 UI 真源时才建议引入 revision 机制）。
3. **严禁无头绪翻修**：禁止把「工业级终极架构」直接落成代码改动清单；只能输出「缺口 → 最小验证步骤 → 若证实则可选方案 A/B」。
4. **跨端强制对齐**：凡涉及 JSON/ZMQ/UDP，必须同时追到 **Godot 发送/接收** 与 **C++ 解析/广播**（bridge 中间层如改写字段也要点名）。

## 交付格式（必须严格遵守）

对每个主题输出表格或条目：

| 字段 | 说明 |
|------|------|
| **Observation（观测）** | 代码实际做了什么 |
| **Risk（风险）** | 失效模式（漂移/泄漏/崩溃/闪烁） |
| **Evidence（证据）** | 路径 + 摘录要点 |
| **Unknown（未知）** | 需要运行日志/断点/抓包才能定的点 |
| **Recommendation tier（建议分级）** | **T0**：仅加日志/断言/诊断开关（最小侵入）；**T1**：单点修补；**T2**：结构性改造（仅当 T0/T1 无法闭环且证据充分） |

## A. 工程状态真源与收敛路径（防静默漂移）

### A1. `get_project_state` 调用矩阵

- 列出 **所有** 触发 `get_project_state` 的 Godot 路径（await / signal / 定时 / 手动按钮）。
- 标注：**Undo/Redo、delete_track、rack 连线失败、导入 clip** 等关键操作后，是否 **必然** 回拉；若否，给出缺口证据。

### A2. PUB / UDP 语义与丢包敏感性

- 枚举经 ZMQ PUB → bridge → UDP 的消息类型（delta / transport / levels / tile_ready / 其他）。
- 明确哪些消息被 Godot 当作 **工程真源**；哪些只是遥测。
- 评价：在 `dontwait`、UDP 无 ACK、ring 满丢弃的前提下，**是否存在仅靠增量即可永久漂移的路径**。

### A3. Undo/Redo 与 UI 刷新一致性

- **C++**：`undo`/`redo` handler 之后内核做了什么（graph allocate / dispatch pending）？
- **Godot**：是否存在 **只靠增量**、不拉全量而导致 rack/timeline 陈旧的路径？引用具体 handler。

## B. IPC 契约与客户端一致性（防假连接）

### B1. 命令字段对齐

- 抽样核对高频命令（rack / clip / transport / device）Godot JSON 字段 vs C++ `getProperty`。
- 列出 **Unknown command** 风险的调用点（例如历史遗留 `action` 名）。

### B2. `VitIpcClient` 真实能力 vs 调用方

- 核对 `send_command_async` / `send_command_json_async` / `send_command_async_await` 等方法：**定义与调用是否一致**。
- 评价 fire-and-forget 与排队回复混用是否会造成 **错配/丢弃回复**（结合 `_pending_command` 逻辑）。

## D. SHM 波形瓦片：撤销与删除生命周期（资源安全）

### D1. C++ 所有权与释放点

- 追踪 `TiledSpectrogramBaker`：`releaseTrackMappings`、clip 删除、track 删除、undo/redo 恢复 clip 时 **是否会释放/重建** SHM 映射。
- 明确：**clip 级** 与 **track 级** 清理是否对称；是否存在只清轨道不清 clip 的路径。

### D2. Godot / GDExtension

- `VitWaveformReader.read_shared_memory` 的生命周期：是否存在 **unmap/主动丢弃** API；若无，标注为 **缺口（仍属体检结论）**。
- `telemetry_manager` / tile 消费路径：clip 或 track 消失时，纹理引用是否会滞留？

### D3. 并发与乱序包

- `tile_ready` 是否可能与删除事件竞态？引用代码中是否有过滤 `session` / `clip_id` 仍存在性的逻辑。

## E. 输出汇总（必须）

1. **Top 10 风险清单**：按「概率 × 严重度」排序，每条带来源路径。
2. **最小验证计划**：最多 5 条可复制的手工步骤（或日志关键字），用于把 Unknown 变成已知。
3. **修复候选 backlog**：仅允许 **T0/T1** 条目直接进入「可修复」；**T2** 必须附「已证实且 T1 不足」的前置条件。
