## §1 诉求与问题定性

观察问答（用户自然语言提问 → queryengine/CCB/RLM 披露 → LLM 组回复）的证据密度已被 M1 证实充分，但**全量细节直接铺陈**不适合作最终呈现：日常使用视觉轰炸、演示场景信息淹没结论。目标不是删信息——证据可追溯性是产品核心价值——而是**分层披露**。

## §2 事实基线（2026-09-30 勘察锚点）

1. 观察问答回复 = 助手**文本消息**（LLM 组稿，含 dB 数值等证据细节）+ 可能的结构化副作用（mix_observation 信封面板、artifacts、project_result 卡）。"过详细"问题在**文本正文**面。
2. webui 已有原生折叠先例：`<details>` 两处（capability-proposal-details，App.tsx:4974；mix-board-diagnostics，App.tsx:5423）——分层交互模式有码内范式。
3. 结构化面板（mix_observation，App.tsx:5211+）自带 observation_path/context_pack_path 工件路径——**追溯层入口的原料已在**（部分消息）。
4. 消息水合（history 回放、/agent/events）以 content+结构化字段重建——呈现层改动不得破坏水合等价性（同消息刷新前后渲染一致）。
5. 助手消息的辅助形态丰富（交互卡/回执卡/artifacts 摘要）——分层只作用于**纯文本正文**，不动既有卡片体系。

## §3 核心设计判断

**高质量摘要层（2-3 行真结论）必须由 LLM 产出**——机械截取首段不可靠（中文回复首段常为应答语/复述问题）。因此分期：

- **P1（webui 单侧·呈现重排）**：不造摘要，做**长度治理**——长观察类回复默认折叠，首段可见+「展开全部 N 行」。零 agent 改动，立即消解视觉轰炸；天花板=不是真摘要。
- **P2（agent 结构化配合·真三层）**：观察问答路径回复带结构化分层标记（LLM 按指令产出 summary），webui 渲染真三层。M8/答辩演示态的完全体。

## §4 三层结构与两期规格

### 4.1 目标形态（P2 完全体）

| 层 | 内容 | 默认态 |
|---|---|---|
| 摘要层 | ≤3 行结论（LLM 产出） | 常显 |
| 证据层 | 观察条目引用（条目=一句观察+来源投影/指标名），逐条可展开 | 折叠（`<details>`） |
| 追溯层 | 完整投影引用入口（工件路径/观察 id——复用 §2.3 原料） | 折叠，与证据层并列或嵌套尾 |

### 4.2 P1 规格（webui 单侧）

1. **适用判定谓词**（保守，宁漏勿滥）：`role=assistant && 无 pending 交互 && message_kind 不属回执/交互卡族 && 正文长度 > 阈值（默认 600 字符或 14 行，常量可调）`。错折叠回执=缺陷；漏折叠观察问答=旧体验，可接受。
2. **呈现**：命中谓词的消息渲染为「首段（或首 N 行）可见 + `<details>展开全部</details>`」；展开后与现行渲染完全一致（同一渲染函数，只是容器折叠）。
3. **水合等价**：折叠是纯 UI 态，不进 content、不进持久化；刷新/回放后默认态重新计算（不记忆展开状态，v1 不记忆）。
4. **不打扰**：交互卡、回执卡、project_result、artifacts 摘要、mix_observation 面板一概不动。

### 4.3 P2 规格（agent 结构化）

1. **回复结构扩展**（观察问答路由路径，非全量聊天改造）：回复新增可选 `presentation` 块——`{summary: string（≤3 行）, evidence_entries: [{text, source, ref?}], detail_mode: "layered"}`。锚点：观察问答路由的 final reply 组装（chat/goalrunner 侧，实现卡实锚具体文件）。
2. **持久化兼容（AGENTS §11）**：旧消息无 `presentation` = fail-open 退化 P1 呈现（不报错不升级）；未知 `detail_mode` 值按无块处理。补旧记录反序列化测试。
3. webui 侧：有 `presentation` 渲染真三层；无则走 P1 谓词。

### 4.4 演示态 / 日常态

v1 不做全局模式开关——分档由**折叠默认态**单参数承载（日常=细节默认折叠；答辩彩排可临时全展开，交互即点即开）。真"演示模式"留 v1.x 与 DEFENSE-SHOW-1 节目设计合流（届时按节目脚本定制披露密度）。

## §5 挂点设计（webui 侧）

- 渲染改造点：App.tsx 助手文本消息渲染段（content 输出处）外包裹分层容器；复用 `<details>` 既有样式族。
- messageLifecycle.ts **不动消息结构**（P1 纯呈现）；P2 仅消费新增可选字段。
- 判定谓词与阈值常量集中单文件（可测试），不散落渲染分支。

## §6 实现拆卡

| 卡 | 域 | 内容 | 引擎 |
|---|---|---|---|
| OPT-IMPL-1 | webui | P1 呈现重排：判定谓词+折叠容器+水合等价回归 | flash 可接（规格已定） |
| OPT-IMPL-2 | agent+webui | P2 结构化三层：agent presentation 块（观察问答路由）+webui 真三层渲染+旧消息兼容反例 | GLM 首选（跨域+schema 兼容） |

依赖：OPT-IMPL-2 依赖 OPT-IMPL-1（P1 是退化路径）；两卡不同文件域但 IMPL-2 含 webui 段，与 IMPL-1 串行。
