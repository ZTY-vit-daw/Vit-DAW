# Agentic Observation 架构路线图（AGENTIC-OBSERVATION 蓝图，2026-09-25）

> **状态：规划（未实现）**。本文档是 2026-09-25 决策会话（用户 × 决策侧）架构共创讨论的固化，作为中期检查收口版本之后全部开发的现行计划来源。文中全部内容为设计决策与排程，**不代表当前系统现状**；现状以各子系统实际代码与 [CURRENT-STATE.md](../CURRENT-STATE.md) 为准。各组件进入实现时随卡片推进更新状态标注。
>
> 一句话定位：把 coding agent 的 pull 式上下文获取模式引入 DAW 域——观察投影层已完成"信号→符号"的翻译（最难的前提），在此基础上建立统一寻址、物化索引、毫秒级查询、可变上下文窗口、音频编译器、质询-确权协议与用户 memory，将 agent harness 从"固定相位轮次推送装配"（curated context assembly）升级为"LLM 主动检索"（agentic observation），使超大工程（几十至上百轨）无需依赖固定编排即可运行自由态工作流。

---

## 1. 背景与动机

- 当前"观察投影 + CCB 装配 + 相位轮次"设计在小型工程（数轨贴唱、五六分钟）完全够用；超大工程目前靠混音能力层固定编排兜底，自由态无法覆盖。
- coding agent 面对超大代码库的方式是 pull 式按需检索（grep/read/RAG），上下文窗口可滑动（稳定前缀 + 句柄重拉 + 退场摘要）。该模式与 DAW 任务同构：**投影层的结构化输出就是"可 grep 的源码"，原始波形才是"二进制"**。
- CCB 的"按显式 view 请求披露，不做自动选择"已经是 pull 模型雏形；缺口不在范式，在四件事：view 参数化（尺度）、即席查询谓词、跨 view 组合与自动披露、上下文退场。

### 与 coding 的对齐表（长期参照）

| coding 域 | Vit-DAW 对应物 |
|---|---|
| AGENTS.md 稳定前缀（KV cache 命中） | 四层稳定前缀（agent 规则 / 用户偏好 / 环境实例 / 工程账本） |
| grep / glob 粗定位 | 物化投影索引查询（audio-grep） |
| read(file:line) 定点深读 | evidence ref 句柄展开 / 参数化 view |
| 编译器 / 测试套件 | 音频编译器三层 + FXM 差分回归 |
| 用户级 memory / skill 文档 | 用户经验层（贝叶斯画像 + 蒸馏文档） |

### 速度分层（与 coding 对齐，不追求全部毫秒级）

| 动作 | 量级 | coding 对应 |
|---|---|---|
| observe / grep（索引查询） | 毫秒级 | grep / read |
| compile（结构断言） | 亚秒级 | lint / 类型检查 |
| probe（定向 render + 差分） | 秒级 | build / 跑测试 |

## 2. 核心设计决策

### D1 统一 ref schema（寻址语言，第一块积木）

所有观察产物、问题、决策、变更、memory 条目共用一套全局唯一、不可变、可重放、格式统一的寻址：

```
ref := (projection_kind, scope_id, time_window, snapshot_id, content_hash)
```

- `scope_id` 钉拓扑版本；`snapshot_id` 钉数据版本（F5 snapshot freshness 方向的延续）；`content_hash` 走 CAS（vsphub 既有能力），任何时刻重拉同一 ref 得到同一内容——语义等价 `read(file@commit)`。
- **实现顺序有硬依赖：先统一 ref schema（主键），再建物化索引（以 ref 为主键），最后做退场机制（靠句柄重拉）。** 反序必返工。
- 迁移面：现存 evidence refs 由各环节自行生成、格式不一（近期修 bug 已撞上此痛点），需逐投影层归一。

### D2 多维坐标集（统一寻址语言，不统一存储引擎）

坐标轴清单：

| 轴 | 内容 |
|---|---|
| 轨道 / 拓扑 | 单轨、轨组、总线子树、send/insert/sidechain 路径 |
| 时间 | 三层标尺（见 D3） |
| 频域 | 频段、掩蔽关系对 |
| 信号域 | 时域 / 频域 / 动态域 / 立体声域（声像、相位、相关性） |
| 版本 | snapshot / commit / diff（回归断言的地基，CAS 天然支持） |
| 语义角色 | 寻址层用轨道名即可（见 D11，不自动判定） |
| 聚合粒度 | 帧级 / 窗级 / 段落级 / 全曲级——观察尺度的正式化，窗口大小控制参数 |
| 对象类型 | 轨道、段落、问题（issue）、决策、变更、**memory 条目（预留）** |

架构裁定：**ref schema 统一的是寻址语言，不是存储引擎**。各投影层自建局部索引（倒排/立方体各随其便），查询引擎面向 ref 谓词跨层路由——同构于 coding 域 grep/git/LSP 多引擎共存、共享路径坐标。

### D3 时间坐标三层

- **采样点/帧 = 权威底座**（机器原生、零歧义，ref 内部存储用）；
- **秒 = 通用人类层**（无网格工程的默认标尺）；
- **小节:拍 = 条件启用的语义覆盖层**（工程有可靠 tempo map 才开启，tempo 变化由 tempo map 映射）。

查询语言接受三种标尺输入，内部一律归一到权威层。不设"乐理时间为主坐标"——自由节拍、无 BPM 电子乐、影视/播客任务没有可靠网格。

### D4 投影物化 + 增量失效（make 模型）

- 投影输出从"按请求现算"改为"事件驱动物化"：装载、变更、render 时增量写入可查询存储。
- 声明投影依赖图（哪个投影依赖哪些轨/总线/时间窗）；变更事件沿依赖图做脏传播，只重算受影响投影，不碰全工程。
- **失效正确性是本组件的验收重点**：漏标脏传播会产出静默错误数据，比崩溃可怕，需要专项测试（构造多级依赖链上的中途变更，断言下游全部重算）。

### D5 查询引擎与 audio-grep 工具面

- 对物化索引做谓词查询：过滤 / 排序 / topK / 聚合，毫秒级（FTS5 同构）；支持尺度参数（scope × time_window × 粒度）。
- LLM 侧暴露为工具面（observe / query / diff.evidence），与 memory 检索共用同一套设施。
- 冷热分离纪律：贵的操作（真实 render）隔离在冷路径，工具面明示成本分级，agent 知道哪个动作便宜哪个贵。

### D6 上下文管理：四层稳定前缀 + 退场机制（可变窗口）

- **四层前缀**：agent 规则（全局）/ 用户偏好（跨工程、随用户走）/ 环境实例（机器+版本指纹，不跨设备同步）/ 工程账本（append-only 决策账本 + TOM 概览 + 总线拓扑 + 交付目标）。
- 决策账本只追加不重写，保证跨轮次 KV cache 命中不断裂。
- **退场机制**：轮次结束后投影原始内容出窗，只留结论 + evidence refs 入账本；ref 是重拉句柄——**只要每个观察都带可重拉句柄，窗口就可以激进滑动**。这是可变窗口的枢纽。

### D7 工程前缀生成器（VIT.md，机器写人可改）

- 权威源 = 工程包内由生成器维护的结构化数据（从投影层渲染：TOM 概览、拓扑、RLM 目标、决策账本）；盘上导出 `VIT.md` 为人类可读层 + 明确标记的 override 区，人工改动回灌权威源。
- 结构 = 生成主体 + 补丁层 + 合成器；生成机制保证它永不过期（手写文档会过期，过期前缀以 100% 置信度污染每一轮）。
- 与 coding 的 AGENTS.md（人写机器读）方向相反（机器写人可改），本质是同一条"人机共同维护谱系"上机器派生段占比更高。

### D8 音频编译器（三层，把"能播放=通过"的错误二分拆开）

1. **结构合法性（编译级，确定性断言，不用听）**：路由完整性（无意外反馈环/死路）、信号卫生（无削波、无 NaN/Inf、DC offset 界内）、true peak ≤ 目标、采样率/块长/延迟补偿一致、插件合法装载。承载者：TIM 扩展为完整断言器。
2. **回归不变量（测试级，差分断言）**：FXM 机制复用、语义新建——差分对象从"效果器 on/off"（原初衷：评估效果器好坏）换成"变更前/后"，成为变更影响面断言器。不变量清单 = 每条「谓词 + 作用域 + 容差 + 失败动作（block/warn）」，可增长，像测试套件。
3. **品味验收（review 级）**：不可编码的部分，留给 LLM 观察推理与人；不假装客观。

- **裁判不下场（硬规则）**：编译器只做红绿灯（warn 接近界 / block 出界阻止交付），修正一律走 agent 闭环（诊断 → 调整 → 复检），防止"为过检而调"的 metric gaming（响度战争即人类版）。
- 全局不变量（总线 headroom、低频总能量、全局 LUFS）住常驻前缀或强制披露规则，**不依赖 LLM 的检索自觉**——音频域漏看串音路径没有编译器会报错。

### D9 交付 profile（RLM 进化）

- 各行业标准（Apple Music / Spotify / AES / 广电 R128 / Sony 等）= 参数向量（integrated LUFS、short-term max、momentary max、true peak、声道配置）+ 各自特殊规则（如 Spotify 二次响度化 → headroom 策略不同）。
- UI 可做成菜单，内核是参数化不变量组；**一个 render 挂一个 profile**（响度标准是目标带不是单向门槛，"按最严的做自动满足其他"不成立——落点必须在带内）。
- 多交付物（同工程出流媒体版/电台版）属交付物分支管理，不是不变量并存，另位实现。
- 计量是流式计算，render 后或播放中实时监督均便宜——常驻总线观察助手，结构上是"自动总线观察"的可编码部分的归宿。

### D10 段落投影：发现与命名分离

- **发现层（确定性信号处理）**：self-similarity matrix（重复性）、novelty curve（能量/谱变化点）、onset 密度——成熟 DSP 方法，段落边界是可复核事实，不依赖 LLM 猜全曲结构。
- **命名层（语义，可竞争假设）**：段落先拿中性 ID（S1…Sn），"这段像 hook"是挂证据的假设标签，由 LLM 质询 / 用户确权，可推翻。
- 不预设曲式模板：没有 intro/bridge 就没有对应标签，中性 segment 坐标照样存在、照样可寻址。
- 与 DAD 的 evidence 哲学同构：事实（边界）与解释（命名）分层，解释永远带证据引用。

### D11 角色身份层：寻址与身份分判

- **寻址层（称呼）**：轨道名、segment ID 就是地址，零判定成本，直接进坐标集。
- **身份层（处理模板）**：需要判定的东西，流程 = 证据生成假设 → 惰性质询 → 用户确权 → 固化入账本（一次性成本终身享用，下次会话不重问）。
- 证据融合（仅用于生成候选，不自动拍板）：轨道名强先验 + 声学特征兜底（基频范围/频谱重心/瞬态/立体声宽度）+ 上下文（编组/相邻轨/颜色惯例）；多标签不互斥（808 同时是 bass 与 kick 职能）。

### D12 模板瘦身原则（上下文只装模型参数里没有的东西）

模板/身份层只写三样，**处理知识一行不写**（归模型参数）：

1. **身份**（确权事实）：用户确认"这是低音轨"；
2. **语境**（工程事实）：曲风、参考轨、交付目标；
3. **规定**（硬约束）：目标响度带、true peak 上限、采样率。

"低音轨在 trap/爵士/金属里怎么处理"是通用知识，模型参数里更全、更随语境自适应；写进模板 = 雇资深混音师再塞一本自编小册子，且软约束随模板细化退化为事实硬围栏（越界警报高频化 = 警报疲劳）。瘦身后越界报告的哨兵只剩交付规定（客观、情境无关、低频精确），恰好归位到编译器不变量层。

### D13 质询-确权协议（全线贯通的统一协议）

```
证据 → 假设 → 质询 → 确权 → 固化 → （冲突触发）再确权
```

- 质询三要素：**假设 + 证据引用 + 低成本反馈形式**（二选一/确认）。不带证据的质询是让用户盲猜。
- 质询时机惰性化：用到才问（不做冷启动大批发问）；高信息密度时刻优先（画像冲突、画像空白首次出现）；冲突触发再确权，不做定期骚扰。
- 与 PCA evidence-backed control admission 同构：证据开路、人类确权、留痕固化。适用于：段落命名、角色身份、知识缺口（长尾曲风模型不确定时问而不是预写）、memory 主观偏好。

### D14 Memory 系统（四层上下文的用户层与环境层）

**三种记忆三种键**（键错位 = "换台机器就不灵"类故障的根源）：

| 记忆类型 | 聚合键 | 协议 |
|---|---|---|
| 用户偏好 | 按"人"（跨设备同步） | 质询确权（D13） |
| 客观经验（插件 bug、流程踩坑） | 按"环境"（机器+版本指纹；.local 同构，**不跨设备同步**） | 环境指纹失配 → 降权待验证 → 复验通过才退役留痕 |
| 工程事实 | 按"工程"（工程账本） | append-only |

- **内部结构复用观察投影架构**：原始记忆流（append-only，evidence 层）+ 蒸馏文档（投影层，算法升级可对全历史重蒸馏，原始流永不删）。
- **画像数学：逐维贝叶斯**。画像形态 = 「默认（后验众数）+ 条件化例外集合」；例外不覆盖默认、例外挂条件；重复观测越过置信阈值才升级主动行为；近期反馈权重高于远古（折扣因子）；用户成长 = 概念漂移，画像跟踪移动目标，永不完全收敛是特性。
- **例外升格、默认降格**：例外加权累积超过默认存量时触发一次轻量确认后迁移；旧默认降格为条件化例外（保留周期性偏好——夏冰美式冬拿铁不被新默认覆盖）。
- **透明性底线**：过程零打扰，结果全透明——画像用户可见可删改（机器写人可改）。
- **垂类结构性优势**（相对通用 agent）：域纯（无跨域记忆串味）、语义坐标系统一（键空间对齐、检索命中率高）、验证闭环密度高（每次记忆指导的调整过编译器/probe/听感三道反馈，错误记忆被自然淘汰）。参考 Hermes Agent 的机制形态（markdown 蒸馏产物、SQLite+FTS5 原始流、consolidation loop），但架构不照搬：其自主巩固仅适用于客观经验类，主观偏好必须确权制。
- memory 条目本身进坐标集对象类型轴（D2 预留），按需检索不全文塞前缀；前缀只放蒸馏后的高频强偏好 core。

### D15 新 harness 与既有资产处置

新形态：pull 模式 agent loop + 工具面（observe / query / diff.evidence / compile / probe）+ 四层前缀与退场 + 编译器与质询协议。

| 处置 | 资产 |
|---|---|
| 保留（核心资产） | 观察投影层（信号→符号翻译）、CAS/VSP 幂等执行、evidence refs 概念（格式统一）、FXM/TIM/RLM（语义升级复用） |
| 降级（不删除） | 混音能力层 → 快路径库（模式化高频任务仍走编排，路由由 planner 决定）；相位轮次 → 冷启动第一轮（保证每会话共同底座） |
| 新建 | 查询接口层、物化索引与增量失效、退场机制、编译器三层、质询协议、memory 系统 |

- 切换策略：新旧 harness flag 并存，至少跑一个完整工程 A/B 对比后切换（见 §4 质量门）。
- **观察预算与止损线从第一天进入设计**（AGENTS.md §8 纪律延伸）：pull 探索深度受 probe 物理成本约束，工具面明示成本，超预算止损。

## 3. 排程：两线五段一汇合

排程原则：关键路径最先流动；两线在汇合点前零交叉等待；每个组件就位即有真实消费者；功能开发（时域、编曲）一个不砍，只重排顺序使依赖自然满足。

### 线 1：地基与工具面（关键路径，串行推进）

| 段 | 内容 | 关键验收 |
|---|---|---|
| L1-1 | 统一 ref schema 定版（含 D3 时间三层、D2 对象类型轴、memory 预留）+ 各投影层迁移 | 设计评审决策侧亲自把关（质量门 G1）；迁移后全量测试绿 |
| L1-2 | 投影物化存储 + 变更事件 + 依赖图增量失效 | 失效正确性专项测试（质量门 G2） |
| L1-3 | 查询引擎 + audio-grep 工具面（谓词/尺度/topK，毫秒级） | 索引查询延迟与正确性基准；工具面成本分级标注 |
| L1-4 | 上下文退场 + 四层稳定前缀 | 轮次退场后句柄重拉一致性；前缀 append-only 的 cache 命中验证 |
| L1-5 | 新 harness 骨架（pull 模式；相位轮次降级冷启动；能力层挂快路径） | 新旧并存 A/B（质量门 G3） |

### 线 2：独立组件与功能载体（与线 1 完全并行）

| 段 | 内容 | 关键验收 |
|---|---|---|
| L2-1 | 编译器第一层（TIM 结构断言器）+ 交付 profile（RLM 参数化） | 对现有收口版本工程即刻增值：监督报警路径端侧烟测 exit 0 |
| L2-2 | 段落发现层 DSP（self-similarity / novelty / onset） | 边界检测可复核（确定性重放一致） |
| L2-3 | 质询-确权协议最小版 + 段落命名层 + 角色身份层 | 协议首战：段落/角色确权全流程走通 |
| L2-4 | 混音时域效果器接入，以 FXM 差分 + 回归不变量为验收载体 | 接一个效果器配一套差分断言；时域闭环完成时编译器第二层自动成型 |

### 汇合与收尾

- **汇合**：编曲/AIGC 能力在新 harness 上开发——大颗粒、长时程、需要全局曲式结构的任务，是 pull 模式最苛刻的试金石（段落投影此时就位供曲式结构）。
- **收尾**：memory 系统（D14 全量）——依赖全部就位后的拼装；ref 已预留对象类型，无返工。同时是论文/答辩叙事的压轴章。

## 4. 质量门

1. **G1 ref schema 评审**：全局规范，定错返工最大，设计评审由决策侧亲自执行（L2 深度）。
2. **G2 失效正确性专项测试**：多级依赖链中途变更，断言下游全部重算；漏标即 fail。
3. **G3 新旧 harness 并存 A/B**：至少一个完整工程在两种模式下各跑全流程，对比质量与成本后裁定切换。
4. 其余组件验收照仓库既有纪律：Go/webui 全绿 ≠ 可交付；agent 侧改动过真实栈烟测（`dev_agent_smoke.ps1` 体系）exit 0 为门槛；涉渲染面/用户旅程显式声明端测覆盖边界。

---

## 5. 风险与非目标

**风险**：
- ref schema 定版失误 → 全线返工（缓解：G1）；
- 增量失效漏标 → 静默错误数据（缓解：G2 + 失效证据可追溯）；
- pull 模式探索成本失控 / 检索迷路（缓解：观察预算、止损线、工具面成本分级，第一天进设计）；
- 全局耦合遗漏 → 局部最优全局失衡（缓解：全局不变量常驻前缀 + 涉改自动附路由影响面——后者依赖拓扑轴，在 L1-3/L2-4 间接线）；
- 画像过拟合（用户成长，移动目标）（缓解：折扣因子 + 冲突再确权）。

**非目标（明确不做）**：
- 编译器不做自动修正（裁判不下场，防 metric gaming）；
- 不做多标准"同时满足"（一 render 一 profile）；
- 不做曲式模板强套（段落是中性坐标 + 假设标签）；
- 不丢弃/重置当前收口版本链路——本路线图全部为增量演进，收口版本保持可交付。
