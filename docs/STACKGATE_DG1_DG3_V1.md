## 0. 使用规则（先读）

1. 本文件冻结的是**断言面、退出码语义、工件契约、引用语法**。装置实现细节（扩展参数名、腿命名、脚本内部组织）由实施卡在既有烟测体系内落——不得弱化、删减或绕过本文件断言面；加强（多断言）不需改本文件。
2. 能力卡引用语法见 §6；卡面验收标准中出现 `DG1-A/B/C`、`DG2`、`DG3` 字样时，其完整含义**只有本文件**，卡面不得另行定义或缩水。
3. 本文件不执行任何关卡（非目标，卡面同）；执行发生在各实施卡，执行回执必须回指本文件条目号（如「DG1-A A7 PASS，run 工件 coord/runs/<卡ID>/run_…」）。
4. 「机械可判定」定义：每条断言可被脚本以布尔判定（DOM 属性/JSON 字段/哈希/阈值/计数），不存在"看起来对"的人工判读；唯一例外是 §5.2 显式标注的用户手测节点（人耳/人眼），它们单独编号（M1-M4）且永远不被自动断言替代。

## 1. 口径总则（所有关卡共用，逐条引用时写 §1.x）

1.1 **真实栈定义**：三件套=VitApp 内核 + Go agent（含 webui）+ Godot 前端；进程链与端口面=7878（agent HTTP）+7879（VitShell status）+8787（hub）+5555/5556（内核 ZMQ）+4445（内核 UDP IPC）+9333（CDP，仅 127.0.0.1）。确定性内核腿可用「kernel+agent berth」形态（`dev_agent_smoke.ps1 -StartKernel -RestartAgent`，无 UI）——与 edu/legame/yue 既有腿同型；凡涉 UI 渲染面的腿必须走 VitShell 三件套形态（vitshell_full_smoke 装置）。腿形态选择在卡面声明。
1.2 **证据等级四条**（AGENTS §7 落成机械判据）：`go build`/`npm run build` exit 0 只证可构建，不算关卡 PASS；单元测试绿不算关卡 PASS；日志出现阶段名/事件不算断言通过；关卡 PASS 唯一判据=烟测脚本 **exit 0** 且工件齐全（§1.4）。
1.3 **退出码语义总表**：0=PASS（全部断言绿+工件齐+隔离还原亲证）；非零=不通过，且 run 工件中必须有对应 `failure_class` 记录，二分类——`assertion_failure`/`face_defect`（产品缺陷，取证上交，**禁止原样重跑**）与 `env_interrupt`（环境：端口占用/引擎/内核启动失败/还原失败/VRAM 超限等，排除后可按剩余轮次继续）。各脚本既有码表照旧声明于脚本头（journey1 系 0/1/2；edu/legame 系 0/2/4；vitshell_full_smoke 系 0/1），新腿沿用宿主脚本码表，不新造第二套语义。
1.4 **工件契约**（AGENTS §9 全量）：每次运行新建独立 run 目录（`coord/runs/<卡ID>/run_<时间戳>[_<用途>]/`，不覆盖旧 run）；工件至少含：run_id、开始/结束时间 UTC、被测仓 HEAD（`git rev-parse HEAD`）+`git status --short`、前端仓 HEAD（涉前端腿时）、被测二进制 sha256（agent/内核/hub/VitShell/前端导出物，适用者逐个）、`-SkipBuild` 时二进制 mtime+哈希（且必须先证含被测改动）、agent 原始日志、关键开关（env/参数）、fixture 源哈希前后对账、隔离还原（recents/Workspace/drafts）哈希亲证结果、每腿判定 JSON。真栈回执记录占用登记 commit 与释放记录（§1.5）。
1.5 **占用与隔离**：VitApp/Godot/agent 三件套栈按 `coord/resources/PC-RUNTIME-STACK.md` 六步（净空亲核→登记+推 main→fetch 重读+≤60s 即时复核→启动→测试→TEARDOWN_ALL_ZERO 亲证+释放回填）；YuE2 引擎独立进程不登记该记录（沿 `run_yue_dialect_smoke.ps1` 头部引擎所有权说明），但启动前仍须与三件套占用记录错峰。隔离契约按 AGENTS §10：recents 快照→还原哈希亲证（mismatch=环境中断非零退出）；`VIT_PROJECT_XML`/`VIT_HISTORY_DRAFT_ROOT`/草稿根重定向到 run 目录；fixture 一律先复制进 run 目录（源哈希 before/after 对账）；用户工程/教材材料只读指纹（rehearsal-copy 规则）；封存集不碰。
1.6 **概率运行与止损**（AGENTS §8）：运行前在卡面/脚本头声明——运行次数与轮数、成功条件（本文件 §1.3）、失败分类（§1.3 二分类+腿级细分）、止损线（同确定性断点连续两次失败禁原样重跑，先补代码锚点/缩小假设/拆取证卡；环境中断须有原始日志才可排除出有效轮次）；LLM 与生成预算逐腿声明（零计费腿必须以遥测断言 stayed-zero，沿 `edu_jam_smoke.py` 模式）。一次 exit 0 只证存在成功路径；宣称稳定须另行声明样本量/比例（审计 §7「不把一次成功当稳定率」）。
1.7 **不变红线**：不得弱化既有断言/改 sealed 期望/硬编码易变轨道标识/加领域动词凑通过（AGENTS §10）；不得把链路进度写成端到端完成（§7 证据等级）；断言失败不许"改脚本预期"自愈——只能修产品或取证上交；投影 peer 关系与 CCB 不自动选 view 等架构红线不受本文件影响。

## 3. DG1 单栈能力关（每能力一条真实栈 exit 0 口径）

### 3.0 通用骨架

每子关=一条真实栈烟测腿，形态：宿主脚本（既有体系内扩展，见 §7 映射）+ 卡面声明的运行次数/预算/止损（§1.6）。断言面编号 `DG1-X-<断言号>`，PASS=全部断言绿且工件齐（§1.4）且隔离还原亲证（§1.5）。腿必须驱动**生产缝隙**（agent HTTP/tool face、内核 ZMQ 命令面、真实 UI 事件），不得开测试后门直改状态。

### 3.1 DG1-A 谱面编辑回读出声关

- 目标：证明选定的谱面库/记谱模型能完成「编辑→数据→内核回读→重绘→出声」真实闭环（审计 G0-1/W04/W05；H4）。
- 装置锚：确定性内核腿挂 `dev_agent_smoke.ps1` 同模式（berth 形态，编辑经 agent HTTP/tool face 到内核 ZMQ）；渲染/回刷 UI 面留 DG3/DG2 断言。出声断言用内核离线渲染探针面（`l2_render_probe` 命令面，`scripts/dad_probe.py` 驱动模式）产出 WAV 工件。
- 断言面：
  - A1 写读一致：谱面编辑写入的音符事件逐一回读比对（音高/起点/时值/力度/休止），逐事件相等。
  - A2 映射稳定：谱面音符 ID↔内核 clip/note 映射在编辑/保存/重开三步后不漂移（同 ID 同对象）。
  - A3 符号覆盖：附点、切分、休止、延音四类符号在 2/4 拍下真实往返（写入→回读值相等，非仅渲染）。
  - A4 双拍号：4/4 材料谱例往返成立，且工程 2/4 拍号不被材料导入改写（两层拍号语义，H4）。
  - A5 保存覆盖：保存=整段覆盖 clip 音符，回读比对一致后才允许面显「已保存」（W05 acceptance）。
  - A6 重开往返：save/reopen 后回读与保存前一致（roundtrip）。
  - A7 真实出声：赋音高后离线渲染探针 WAV 合法（格式+时长合理窗）且**非静音**（RMS/峰值≥阈值，阈值在脚本头声明并随工件记录）。
  - A8 改音差分：改一音/时值后渲染探针与改前探针差分超阈值（证明声音真实随编辑变化，排除恒定垫音假阳性）。
- 失败分类与止损：A1-A6 断言失败=`face_defect`；A7/A8 探针失败=`face_defect`（不得降级为"仅图形证据"维持通过——审计红线「不能只有渲染截图」）；渲染探针机制在当前栈不可用=`env_interrupt` 取证上交，不自行另造出声判据。
- 工件：§1.4 全量 + 探针 WAV（改前/改后一对）+ 回读 JSON + 差分报告 + 符号覆盖矩阵（A3/A4 逐符号×逐拍号）。
