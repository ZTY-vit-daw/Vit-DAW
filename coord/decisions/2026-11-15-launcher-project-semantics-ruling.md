# 裁定：启动台-工程语义四条（用户批量裁定）

- 日期：2026-11-15 晚（SHELL-4/361/362 合入后用户复测反馈）
- 裁定人：用户（产品所有者）
- 记录：GLM 主管决策流

## 用户原话（要点）

1. 「左侧的工程列表应该用磁带流的 icon 造型来显示，就是之前旧启动页的磁带 logo 型来显示，这是 v5 版本样图设计时也确定的」
2. 「我点击新建时，应该是直接触发手动新建一个新的工程，并且对话流窗口应该自动进入新建的工程内进行工作。而不是现在我点击新建然后对话流问我是否要新建工程。如果我要通过对话流新建工程我肯定会直接对 agent 进行输入提示词的啊」
3. 「现在依然无法通过对话流新建工程……它只会重复回答，而且这个回答的速度和结果，应该是你写的预设回答而不是正确触发了 agent 调用工具……后续的这些指令是不是都没能正确连接 LLM？你认真检查一下」
4. 「左侧的工程列表，在进入工程后就会被收起，这一点我重复问过很多次了，你都说你知道，务必要确定你有这方面设计……在没有进入任何工程前 agent 的上下文不该带有任何工程的范围内容，它现在的位置就是在『启动页』而不是任何未知的工程……在进入任何工程或新建工程后，它才进入那个工程进行工作，并且对话流窗口要随之切换，工程列表页收起，进入工程内的对话流窗口形式」

## 主管取证（2026-11-15 21:19 现场）

- 3 的诊断：新建立图词被 launcher 确定性路由拦截→预设应答（21:19:03 `http.chat` 2.4s/75 字符回复，未走 LLM）；非匹配措辞落 LLM 且调用成功（遥测 21:19:09/21:19:11 deepseek-flash 115/176 tokens error 空）——**LLM 连接无罪；两条路都不能完成真实新建**（确定性路径出 directive 等手动按钮，LLM 路径无执行权）。
- 4 后半坐实：`agent_last.log:30` 启动台阶段 `workspace activated project=…drafts\draft_…\Unsaved.vit`——SHELL-4 boot 草稿把 agent 绑进「未知工程」，违背「启动页=无工程范围」语义。
- 4 前半核验：进工程=surface 整体切换（App.tsx:303-306），ProjectSurface 无工程列表残留（ProjectSurface.tsx:6 注释明示）——**机制已在**，需回归守卫防退化。
- 1 现状：recents 用 `ProjectBadge`=SPEC-V5 §7.3.1 的 48px 以下简化标志，非磁带 cassette 造型——用户裁定列表用**完整磁带造型**，修订该 48px 简化规则在此处的适用。

## 裁定内容

1. **工程列表头像=磁带 cassette 造型**（旧启动页磁带 logo 型；氛围色按 §7.4 工程名哈希）；§7.3.1 的 ≤48px 简化规则不适用于启动台工程列表。
2. **「＋新建」按钮=直接手动新建并自动进入工程**（不经对话问询）；对话流输入=对话语义（agent 执行）。
3. **对话流新建/打开意图=自动执行**（directive 不再等待「让 Vit 新建」手动按钮；治理确认按 337 语义仅在需要时出现）；回复呈现须可区分「Vit 正在执行/已执行」与确定性应答。
4. **启动页阶段 agent 上下文=无工程范围**（位置=「启动页」）：boot 草稿不得作为 agent workspace/对话上下文激活；进入或新建工程后 agent 才绑定该工程，对话流窗口随之切换为工程内形态、工程列表收起（现有 surface 切换机制保持+回归守卫）。
