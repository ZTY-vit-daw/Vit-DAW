# webui 产品形态定调：独立控制台愿景+codex 三区布局+三步走（2026-10-02 用户裁定）

来源：用户两轮讨论（DAW 简易视窗去留→独立 web ui 愿景）；记录人=决策侧。

## 用户愿景（原话要旨）

未来 agent web ui 可能成为独立视窗：①用户不在 PC 前，经云端控制界面直接接入 agent；②不打开 DAW GUI，只用 web ui 完成大部分工作。

## 决策侧分析（用户采纳）

1. **愿景与架构同向**：kernel headless 化已就绪（VitHeadlessServer 在跑），agent 全能力走内核协议、零依赖 Godot GUI——"只用 web ui 干活"在架构上已是事实，缺的只是 web ui 入口完整度；云端接入=同愿景+网络/鉴权层。
2. **关键辨析：独立 web ui ≠ 把 DAW 搬进浏览器**。正确形态=「透过 agent 的眼睛看工程」（证据/观察读数/渲染对比/轨道状态卡），不是低配 DAW 编辑器。简易视窗三件套两头不靠（本地输给真 GUI、远端撑不起编辑）——**删除决定与愿景互为论证而非冲突**。
3. **能力边界**：已覆盖=观察问答/诊断/提案确认/装载写参/采纳回滚/保存（服务端能力全在，webui 缺入口）；真缺口=**人耳试听的远端化**（解法=A/B 卡内嵌可播放渲染对比，FXM 渲染对路径已有）；永远留给 DAW GUI=编曲/MIDI 创作/手工细调。
4. **布局目标（codex 三区）**：左=会话流侧边栏（可折叠，轻量新建/切换/重命名/归档，**不建工作树**——会话流与工程分支/工作树解耦；note 流首期不进侧边栏）；中=对话流+确认卡/A/B 卡；右=证据/轨迹抽屉（保留）。

## 三步走（用户裁定「可以，把卡添加上」）

- **一期（WEBUI-IA-REDESIGN-1，即卡）**：删简易视窗三件套+左列改会话流侧边栏+STATUSBAR-ID-1 并入。
- **二期钩子（登记不实施）**：工程概览证据卡（TOM/ui-state 投影只读，放右抽屉）+A/B 卡内嵌可播放渲染对比（联动 JUDGMENT-SETTLE 修复后的判定链，远端可判）。
- **远期（答辩后探索）**：云端接入（隧道/鉴权/多端）；demo 叙事="不开 DAW GUI 完成一次完整混音判断闭环"可作二期后亮点。
