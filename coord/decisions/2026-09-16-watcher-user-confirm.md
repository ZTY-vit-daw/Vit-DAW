# 决定：watcher 启用须经用户确认（2026-09-16）

- 背景：用户澄清治理边界——watcher 事件唤醒机制保留（功能有价值），但双端不得自行决定启用；一般任务一律由用户携口令到各端对话流发起。

## 裁定内容

1. watcher 只能在**用户激活的值班流**内启动（「值班」口令，或用户粘贴备用开流提示词的等价激活）；值班上下文之外任何会话不得启动 watcher。
2. **跨端不得代启/代停对端 watcher**：决策侧经 SSH 对 Mac watcher 只做只读状态核查；启停只能由用户在 Mac 侧对话流激活。原 PROTOCOL §9「Mac 侧 watcher/环境维护可由决策侧远程执行，用户无需在 Mac 侧开口令」中的 watcher 部分废止。
3. 值班流内的 watcher 自运维（唤醒处理完毕后的重启、值班交互中的死亡自愈）含于该次「值班」授权；流关闭即停，不跨流存活、无心跳兜底。
4. watcher 唤醒只产生汇报；任务执行授权只来自用户口令或流内批准（report-first 不变，与 [2026-09-16-report-first-mode.md](2026-09-16-report-first-mode.md) 一致）。

## 修订落点

- PROTOCOL §4：新增「watcher 启用授权」条款；自愈措辞收窄为值班流内交互或新开「值班」口令。
- PROTOCOL §9：远程维护权收窄（watcher 仅限只读核查）。
- BOOTSTRAP.md：硬性护栏增补；Mac 端注记残留心跳描述清理。
