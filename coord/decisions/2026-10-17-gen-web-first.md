# 决策记录：生成源通道以网页侧为主（2026-10-17 第三轮，用户裁定）

## 裁定

- **用户裁定（2026-10-17）**：生成能力接入以**网页平台兼容为主路线**。理由（用户论点，决策侧采信）：
  1. **必有网页平台**=最普遍且最抗商业风险的接口——API 是各家的商业策略筹码（MiniMax 2026-08-20 关新用户付费 API 为眼前实证），网页是各家命根子不会关；
  2. 各家网页机器接口的差异本质上是**可参数化的浅层差异**（端点/字段/认证形态），"都是 HTML 接口，背后原理（提交→轮询→下载）趋同"；
  3. **主流程解耦**（关键论点）：Vit 的产品流程只需统一抽象——机架输入→生成请求→网页端产出→下载→导入回 Vit 落轨；对面接口复杂度被封装在"站点适配 profile"层内部，不影响主流程设计与接通。
- **本记录同时如实记档**：决策侧此前建议"API 为主、网页兜底"（见 reports/2026-10-17 §四）被用户上述论点推翻——技术契约稳定性（API 不碎）不敌商业存续性（通道不被砍）+主流程解耦论证；AGENTS §0"决策模型必须允许证据推翻自己的方案"行使一次。

## 架构落位

- **网页平台化边车=主路线**：通用流程引擎（登录态管理/拟人化节流/任务监听/下载校验/导入回 Vit）+ 每家一个**薄站点 profile**（五槽位：认证形态/提交端点/轮询协议/下载路径/风控参数）。Suno=第一个 profile（GEN-SUNO-WEB-DESIGN-1 设计件按此方向定稿）；HappyShrimp 视 API 确认结果为第二个候选；未来跟风新产品=新增 profile。
- **API provider 降为并行通道保留**（不删除）：genapi 已实现三 dialect+fal 聚合通道零维护成本，选型期横向对比与应急使用。
- **三条工程约束入设计件**（成本显式化，非反对）：①profile 非零工作量（认证/轮询差异比"改名"深一层）；②契约自检腿（每次调用轻量验证适配存活，失效明确上报不静默坏——Suno 六周三变实证）；③风控节流默认低频拟人化（ToS 风险用户已知情裁定）。
- 对 GenShell 链路的映射：主流程抽象=GenShell GUI/agent 提交 → 边车引擎携 profile 驱动网页源 → WAV 下载校验 → `bridge_ingest_generated_asset` 落轨（与既有 HOST/AGENT 卡语义不变，provider 层可插拔）。

## 补充裁定（2026-10-17 第五轮）：登录形态路线 3（Vit 内嵌 CEF）+ 多站点多开

- **用户裁定**：登录采用路线 3=Vit 内嵌 CEF 登录页（不选外部浏览器提取/边车弹窗向导），理由=多平台统一体验+未来用户切换模型+多配置多开（如吉他轨用 A 模型、bass 轨用 B 模型）。
- **多开架构核对（决策侧，大部分自然成立）**：多 provider 数组（genapi 配置原生）✓；GUI provider 选择区（卡 4 规格已规划）✓；多壳实例（VST3 每轨一实例+HOST 注册表多实例）✓；每站点一档案一凭证一登录页（CEF 组件按站点参数化）✓。
- **设计件三补充（131 定稿要求）**：①按多站点书写（档案/凭证/登录页三件套每站点一套，Suno 首个）；②实例绑 provider 形态留给卡 4 接口说明；③CEF cookie 导出落盘给边车读=待核实技术锚点（gdcef cookie 存储访问面，实现卡前置勘察，不预设零成本）。
- **并行语义**：多开隐含并行生成——拟人化节流按站点全局计算（同站点内排队慢速，跨站点真并行），入引擎设计约束。
- **时序（工程顺序，用户终态无感）**：边车后端先行（凭证先手动填，主仓域独立验证）→CEF 登录页=前端仓增强卡随后——两域不互相阻塞。登录三案实现均为"人工输密码+程序取凭证"，永不代登录（风控原则）。
