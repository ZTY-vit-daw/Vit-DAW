# 用户裁定：产品式手测标准 + 乐局产品形态方向（2026-11-08 晚，M-2 手测首验反馈）

- 记录：GLM 主管决策流 / 2026-11-08 晚窗（用户五条反馈原文要点+主管落档）
- 性质：**长期标准两条+事故账一笔+设计方向一件+优先级重排一条**

## 一、产品式手测标准（长期，用户裁定原意）

**手测=产品式用户体验测试**：用户从 Godot 拉起 GUI 后能完成**所有功能体验**——零终端指令、零环境变量手设、零手动服务启动。类比=游戏/产品开发完成后的 UX 测试。

**2026-11-08 首验暴露的三个违例（事故账，主管认领）**：
1. `VIT_EDU_LEVELS_DIR` 环境前置=开发者模式入口（edu_jam_chat.go:1109 fail-closed 依赖 env，前端拉起场景不可达）——**主管在 311 卡面接受了该前置并写进步骤清单，方向错误**；
2. 旅程 B 要求用户手动起 YuE2 引擎+配 providers——同上违例；
3. **311 前置腿在用户目标工程上实跑了 enter→n0→exit**——用户打开的是被预演过的工程（非从头开始），且进入后无引导不知下一步。预演应使用副本或演后重铺（§10 防污染精神同源，主管派单未加此约束）。

**推论（长期入 AGENTS 候选）**：凡交付用户手测的体验，前置腿只验「副本/旁路」，或在交验前重铺干净态；开发者态前置（env/手动服务）不得出现在用户手测路径上。

## 二、乐局产品形态方向（用户提出，转设计卡）

用户首验后表述的正确形态：**进入工程 → LLM 自动开场执行 → 用户与 LLM 交互**（乐局内容制定好后无需咒语词启动）。并追问：最初设计的 **agent 命名/人格制定环节**（persona_slot 的 {model_name}/{user_name} 消费方）现在是否具有？是否需要 Grok-bot 式 personal-agent GUI？

**现状如实**：①自动开场=不具有（现需「开始乐局」命令词）；②命名/人格制定环节=不具有（无 onboarding GUI，persona 块 v1.1 已定稿但注线未接——运行时不把它注入系统提示词）；③personal-agent 式 GUI=不存在。

**处置**：转设计卡 **LEGAME-UX-1（池序 313）**——分层设计（L1 即修件/L2 最小 onboarding/L3 完整 personal agent 壳），L2/L3 分界（12 月窗口 vs 产品线）待用户裁定。

## 五、乐局产品设计讨论首轮裁定（2026-11-08 深夜续）

1. **壳=内嵌（用户裁定）**：乐局是一种**工程形式**（Vit 的一种模式/工程类型），不做独立 companion app；
2. **Onboarding 归属（用户裁定）**：搭档**全局继承**，settings 可切换，新建工程时可选；
3. **人格塑造=问题引导共塑（用户裁定，否决纯预设方案）**：预设可作底版/加速器但非最佳——最佳=通过关键问题引导用户自行创建人格（比喻原型：音乐培训机构里老师的人设由机构经理等中介试探而出——他叫什么/喜欢什么/一般怎么学）；
4. **L2+HUD 进 12 月（用户裁定）**：先讨论好设计再定，不以「进」为默认。
