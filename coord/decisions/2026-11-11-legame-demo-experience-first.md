# 用户定向：教学乐局先交付展演体验，完整安全权限后置

- 日期：2026-11-11；记录：Codex 辅助设计会话。
- 授权依据：用户明确“暂时以展演目标作为主要目标”，若安全权限开发任务量较大则“暂时先不考虑它，先把展演乐局需要的实际体验交互所需的内容先实现”。
- 判断依据：本轮只读勘察确认完整作答隔离需跨内核、前端/桥接、agent 工具、工程恢复与来源记录，属于独立开发阶段；不是现有卡中补一个只读标志。尚无逐卡工期测量，不给出交付日期承诺。

## 1. 当前目标与范围

当前设计目标为教材《音乐编创》第二单元模拟课的实际乐局体验：固定格式设计文档 → 设计/导入入口 → 工程关联并自动加载 → LLM 按目标引导 → 用户创作/试听/修改 → 检查并自然推进 → 作品与过程摘要。

完整安全权限体系不作为本次展演体验前置：教师/学生账户与角色系统、可信调用源贯通、内核全写面作答区隔离、防旁路、防伪检查回执、防篡改证据和严格受控回答出口均后置。此前可行性及护栏文档保留为后续设计，不构成当前必须同时开发的范围。

保留普通功能正确性：从真实工程读取提交片段、检查题目规定的可核查条件、记录检查结果再推进；不让一句模型自称“通过”成为完成依据。此处是现有程序流程的功能检查，不要求先建签名/跨身份可信回执体系。

## 2. 仍须保留的体验与证据

- 自定义入口采用可用的最薄形态，优先复用启动页对话：外部 agent 按统一格式起草可行，Vit 内讨论至少覆盖现有草稿的查看/修改，导入后可创建并进入；不以拖拽编辑器、完整课程市场为前置。
- 工程进入后自动提供选定文档版本和当前节点，LLM 真正引用材料并引导用户动手；仅显示固定过场文案不算教学体验完成。
- 示例/参考、模型示范和学生练习区在布局和引导上区分；尚无强隔离时明确这只是教学组织，不能宣传为模型无法越权。
- 留存原始对话、关键工具执行/检查结果与关键工程快照；生成作业报表和关键上下文摘要的最小版本，缺来源证据处如实标注。
- 用户实际走完课程后再录制。材料预制可用于准确呈现谱例和已有示范；实际交互中的回答、编辑和检查不可由后期伪造。

## 3. 与历史排期的关系

用户本轮指定教材模拟课为主要展演目标，覆盖 2026-11-09 裁定中“乐局素材可不进本次展演”的范围口径。此记录不自行改动正在执行的卡、跨机器任务归属或主管全局队列。具体实现由主管按当前目标拆卡并协调依赖，不自动领取旧 EDU 卡或重启其全部范围。

课程所需播放、MIDI 编辑、短片段示范按实际可用能力选择；不因“乐局”名称就将完整通用编曲、音频生成服务或旧拍谱功能全部设为本课前置。若某教学动作确实缺能力，应提供缺口与缩范围方案交裁定。

## 4. 推荐实施顺序（辅助设计建议）

先确定最小源格式与“进入工程自动按文档工作” → 用该格式完成模拟课内容和材料 → 打通一轮真实“提问—创作—检查—反馈—修改” → 接通整课 → 最小报表/摘要 → 真栈与渲染/旅程检查 → 用户从 Godot 启动录制。

第一次贯通不携带完整防作弊证明；展演以“一份可设计的音乐任务如何在 DAW 中成为可互动乐局”为主线。

## 5. 用户续论：音乐控件为展演必需

用户明确 Tap 速度/节拍面板、编辑 MIDI 的五线谱、播放音频/MIDI 的随谱交互为展演必需，不作为可选候选裁剪；其他好用控件可以评估追加。实现优先级可以分先后，不能未经用户同意把上述需求降为选做。

用户提出组件预先实现、模型仅调用以控制 token。推荐将音乐控件注册到组件目录，模型传简短参数/引用，前端处理连续交互，完成或提问才回流必要结果。具体选择 A2UI 或现有 Vit 声明式卡扩展未定，不以迁移整个聊天框架作为前置。

## 6. 用户续论：同时支持界面组合与音乐控件调用

用户明确采用“基础控件拼所需界面”和“预制音乐/Vit 控件调用”两种方案；模型可以在一张界面中组合文字、布局、选择/输入、按钮及音乐控件。固定控件不能取代全部动态组合，动态组合也不要求模型反复生成控件源代码。

本轮要求提前统计/设计控件，产出[目录讨论稿](../reports/2026-11-11-legame-widget-catalog-draft.md)。除已确认的三类必需控件，旋律线、节奏条、A/B 等仍为辅助设计建议，未自动升为用户批准的全部开发范围。技术框架安装和实现卡尚未启动。

## 7. 用户续论：控件合并与已有资源复用

用户明确普通音频是轻量文件试听体验，提出随谱播放并入五线谱、在同一谱面先写节奏再编辑旋律，并要求核对复用已有混音 A/B 及整理 agent 资源。

辅助设计本轮建议：三个主要组件（audio_player/music_score/beat_pad），A/B 作为共享比较模式；节奏格不另建、旋律线作谱面叠加。已有资源只做相关播放器/状态/适配的有界整理，不自动扩为 App.tsx 全面重构。现有 A/B 有源码与既往验收依据，但课堂偏好不得直接复用混音回滚语义；实施前补课堂上下文/候选材料适配设计。详见[收敛盘点](../reports/2026-11-11-legame-widget-consolidation-and-reuse.md)。

## 8. 用户续论：A/B 拆成播放器组合

用户提出不沿用现有整体 A/B 界面，可拆为与播放器关联的 A/B 组件，询问“两个播放器”形态是否合理。辅助设计采纳该组件方向：两个通用播放器实例＋比较控制（播放互斥、位置规则、范围、结果回流）；播放比较、偏好与采用/回滚分开。可替代旧前端整体卡，既有预览/音频准备能力按需复用，旧混音接入回归后再退役重复 UI。本轮无生产代码修改或删除授权执行。

## 9. 用户续论：乐局内按学生谱生成成曲

用户确认交互卡和音乐控件为需要开发的内容，要求前半段教学暂不讨论，先设计收尾：学生节奏谱→节奏答题轨 MIDI＋鼓/打击乐音源试听；旋律谱→另一答题轨 MIDI＋旋律音源试听；调用 YuE2 依谱生成完整作品，改提示词生成不同版本并试听。用户已手测确认 YuE2 乐谱跟随准确，采用该验证路径作为集成基础。

本会话问询后用户明确首版为**纯器乐完整编曲，突出学生旋律**。这将 YuE2 最小可用接入纳入本次乐局实际体验，覆盖旧 11-09“生成仅作局外成品”的展演范围；不要求先完成全生成产品线。最低引擎就绪须遵守既定 Godot 用户入口与零手工服务前置。当前只完成设计，不自动重启引擎或领取卡。

现有 genapi 已有 `yue_local` 方言、ABC 输入、job 轮询、音频/replay 以及结果落轨路径；谱面→特定方言、音源配置、版本/提示词/输出关联和 UI 状态仍需接线并实测。设计及 YAML 尾段在[收尾方案](../reports/2026-11-11-legame-student-score-to-yue2-finale.md)；课堂独立创作证据与模型辅助成曲分别记录。

## 15. 用户续论：工程包语义与统一意图文档（2026-11-12，ZCode 会话记录）

用户澄清产品构想：Vit 工程为目录级**工程包**——工程文件＋意图文档＋材料资产＋agent 状态为一体，可整体导出/迁移/分发，不回归传统 DAW 单一工程文档。乐局即"携带乐局设计 YAML 的工程包"：允许外部编辑文档，新建乐局时携带文档建立工程，文档在包内生效并受工程保护。M1 入口范围同时裁定为**方案 A（导入已定稿 YAML＋启动页文本微调）**；Vit 内完整设计对话放 M2。开工定为 **11/14 下午（额度重置后）**，G0 三关探针随开工顺延为 11/14 下午派卡、11/15 晚出结论；首版窗口相应压缩为约 5 天半，11/19 按三条件口径管理预期（G0 无阻塞、M1 范围已收窄、谱面线无 ≥1 日返工），锚点 11/30 不变。W00 共享提交随开工首位执行，不提前抢做。

意图文档格式裁定为**统一 YAML，不设 agent.md 双格式**：非乐局工程同样携带 YAML 意图文档，乐局与非乐局的差异仅是文档内容详略。分层要点：schema 分层（最小意图层字段全可选；乐局层追加 objectives/materials/regions/checks/flow 等必填段），具体规则由 W01 冻结契约定义；**本次实现与验收仍只覆盖乐局链路**，非乐局 YAML 允许携带、发现与解析，其每轮注入生效后置（M2+），不进 11/19 关键路径。加密内嵌按既定后置；首版以 manifest 哈希做完整性校验（防意外损坏与版本错配，不冒充防篡改）。
