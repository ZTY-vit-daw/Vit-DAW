# 裁定：意图词表全量退役+命令面原则（2026-11-01，用户裁定）

## 裁定内容

1. **意图词表全量退役（「全拆」）**：不止于自动化/包络线族（229-234 链进行中），澄清流（225）与通用 DAW 命令词表（conversation/intent.go 的 SynthesizeLocalDAWCommands/SynthesizeClipRangeSplitCommands，~21 匹配器/830 行）一并退役——按既有四阶段方法（①闸开②重验③降兜底④退役）分批推进。
2. **命令面原则（「命令归/命令」）**：用户显式声明意图的确定性通道=斜杠命令面（/命令，对标 Claude Code/Codex 的 slash command+快捷键形态），作为新工作面立项；自然语言意图一律归 LLM（承 2026-10-30 判断权归属裁定）。
3. **一条干净的分界线入律**：**语法归确定性，语义归模型**——显式声明（/命令、确认按钮、审批）永远确定性；自然话语（意图理解）永远 LLM。确认卡 acceptText=同意协议（consent protocol，非意图识别）永久保留；治理门/审批面永久保留。
4. 通用 DAW 词表退役后，零风险高频操作（静音/加轨等）的即时通道=/命令面+既有 UI 按钮；自然语言「把这条轨静音」走 LLM（一次调用的延迟与成本=主流同款权衡，接受）。

## 事实依据（2026-11-01 主管检索）

- 主流 2026 形态：显式命令语法（/plan、Shift+Tab、@引用）全部保留且标配；自然语言意图的词表方案已消失，全由 LLM 承担。早期工具的关键词启发式（用户记忆中的 Codex「plan 触发询问」形态）属过渡期拐杖，演化终点=命令语法+LLM 理解两分。
- 大规模场景（数百意图）工业界有「规则→向量→LLM 重排」级联回流，但本系统数十意图规模不适用。

## 历史账（诚实留档）

- 218（10-29）以词表为路由权威建自动化链时，终态架构裁定（10-30「意图层全 LLM 无词表绕道」）尚未作出——词表是当时可用的最快确定性路径，其存在使下游机器（确认卡/治理门/写入读回链=终态架构资产）得以在零 LLM 变异性下建成并测试。
- 但以终态视角回看：主流 LLM 意图方案在 2026 年中已成熟可鉴，10 月底仍新建意图词表=为拆而建，五张重验卡的退役账即该选择的成本。用户判定「当时用这种方式就是不对的」——成立，留档。
- 词表退役拆除的只是意图层；词表时代驮进场的执行/审批机器全部保留（它们本来就是终态组件）。
