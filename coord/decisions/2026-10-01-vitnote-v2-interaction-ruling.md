# VITNOTE V2 圈搜式交互 · 用户裁定八项（2026-10-01 决策会话对齐）

来源：用户手测反馈（M8 第四轮）+两轮选项对齐；记录人=决策侧。V2 设计卡的权威输入。

1. **触发方式**：修饰键+拖（Alt+左键）全局圈选；轨道时间线保留现有直接框选兼容；胶囊+[N] 快捷键双出口保留。
2. **解析模型（用户原语，第一原则级）**：圈选层只产生屏幕坐标矩形；「坐标→枚举命中窗口及占比→各面解析域对象→合并辖区摘要」向下命中；**GUI 命中仅用于最初圈定任务范围，载荷必须是域对象引用（哪个轨/哪个 clip/哪个效果器）**——agent 任务消费不在 GUI 层（用户原话：「真实的 DAW 处理尤其 agent 处理并不是由 GUI 进行的…它要完成任务要的信息其实就只是这是哪个轨道哪个 clip 哪个效果器要做什么」）。
3. **实现架构**：全局圈选层（仅圈选时活跃）+面级供给器；供给器契约=「这是什么（identity）+这能干什么（affordance）」（用户原语一般化：圈到先识别是什么、再知道能干什么）。新面接入=注册全局矩形+实现供给器。
4. **v2 覆盖面**：轨道时间线（现 lane 通知路径改造入全局层）+机架+资料库+控制面（走带/轨道头=状态快照供给器：BPM/播放位置/循环区/轨参数当前值）。
5. **跨面框选**：命中复数面时枚举各面占比进摘要，合并为单 note（按用户需求消费，不强制主导面）。
6. **便签容器**：窗口式保留（用户：「肯定还得是窗口式，我没说这个是错的，只是刚才有恶性bug」）；便签池维持 IMPL-6 后置。
7. **输入 bug 处置**：面板不可交互 bug 并入 V2 修复（不单开 INPUT-1）。
8. **条件卡终裁**：VITNOTE-IMPL-1 与 VITNOTE-DOCK-MOUNT-1 两张条件卡**改挂 V2 验收同场销**（V2 手测一场销三卡；M8 终裁时间跟随 V2 排期）。

设计默认项（决策侧拟定，验收时异议再改）：空白/无供给器区=空辖区 note 允许（现状语义）；note→正式任务升级通道 v2 不做（远期）；圈选视觉反馈=截图工具式（半透明遮罩+亮框）；V2 交付时 9 步手测清单按新交互重写。

关联裁定：2026-09-29 vit-note 概念定案（VITNOTE_V1_DESIGN）、2026-09-30 便签池 A+B（IMPL-6 既有排期不变）。
