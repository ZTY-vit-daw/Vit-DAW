3. **单内核所有权+内核生命周期归属主窗**：进工程时 Godot/装载链附着到已运行内核，不得出现双内核并存（领取时先锚定当前打开链上内核由谁拉起：agent 还是 Godot，再定实现位）。**内核仅随 VitShell 主窗退出而退出，关 DAW 回启动台后内核留存**（手测 v6 证据：18:35:15 用户发消息→18:35:17 内核随关 DAW 死亡→agent 循环 capability_unavailable 失败；LLM 调用本身成功——遥测 `agent_llm_telemetry.jsonl` deepseek-flash error=""，勿把该失败误归因 API）。回主窗后最近工程/对话须继续可用。
3b. **失败文案与状态区分**：内核不可用与 LLM API 不可用是两回事，UI/回复文案必须让用户能区分（手测中用户把「内核/能力不可用」读成「API 配置没连上」）——归入目标 2 的诚实呈现。
4. **文案对齐**：agent 回复中「磁带流」词汇对齐 v5.1 UI（现 UI 无磁带流元素；磁带 icon 已功能化）——launcherKernelUnavailableReply/launcherNoRecentsReply 等（launcher_flow.go:548-549）与 webui 同类文案一并修。

### 现状锚点（实现要点 1：内核由谁拉起——领取时已定）

**VitShell 链下，内核（VitApp.exe）与 VspHub.exe 由 Godot 前端拉起，时机=打开/新建工程的直启动作**，不是 VitShell、也不是 agent：

- VitShell（`VitShell/agent_manager.cpp` `CreateProcessW(agent)` + `godot_manager.cpp` `CreateProcessW(godot)`）只拉 agent 与 Godot；main.cpp:725 注释「kill-on-close job also clears kernel/hub children」自证内核挂 Godot job 下。
- 直启契约（`start_page.gd:144-147`）刻意不设 `VIT_FROM_LAUNCHER` → `_run_vitshell_direct_launch` → `_bootstrap_runtime_and_request_recent_projects()`：`_ping_local_ipc_once`（UDP 4445→agent 转发内核 ZMQ）失败 → `_try_boot_local_kernel_if_needed()`（dev 候选 `<dev_root>/VitApp/build/VitApp_artefacts/Release/VitApp.exe`）+ `_try_boot_local_vsp_hub_if_needed()`（`<dev_root>/agent/bin/VspHub.exe`）spawn 并经 VitIpcClient `register_autostart_child_process` 登记。
- **关 DAW=内核死的机制**：`vit_ipc_client.gd` `_exit_tree` → `_cleanup_autostart_child_processes` OS.kill 已登记子进程（SHELL-2 PROGRESS.md §1 逐字记载）——手测 v6 18:35:17 内核随关 DAW 死即此机制。
- 启动台阶段（直启前）无人拉内核：greeting/recents/按名打开/新建走 `launcherRecentProjectPaths`→`KernelSendCommand`（launcher_flow.go:372-394）必然降级（手测 v6 观测 3/5；SHELL-3 正式 run 三轮 greeting 均降级模板）。

### 实现位决策（据锚点）

- **内核+hub 的 spawn 所有权移交 agent**：VitShell 给 agent 设委派 env（新增，仅 VitShell 拉起时）；agent 启动序=HTTP listen 成功后 → 探测（内核 ZMQ ping / hub /health）先行，未达才 spawn（候选与 start_page.gd 同一 dev 布局），children 挂 agent（在 VitShell job 内）→ 主窗退出全树退；agent 自身退出兜底 kill children。旧链（Godot-first/dev_agent_smoke）不设 env → 零行为变化。
- **Godot 零改动**：直启 bootstrap 的「IPC 已就绪→跳过 spawn」是既有行为（start_page.gd:844-847），内核先行在线时自然附着，无双内核；装载协议不动（停止条件规避）。
