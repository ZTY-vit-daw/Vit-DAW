## 勘察点（每点产出 = 锚点/工件引用 + 结论）

1. **YuE2 能力面**：已部署形态与调用方式（YUE2-PC-DEPLOY-1 工件在 coord/runs/）；输出形态——整首混音还是分轨？人声/伴奏可分性？**乐器独奏模式已确认可行（用户），重点查：仅人声模式或双轨输出（人声轨/伴奏轨）是否存在**；ABC 引导边界（YUE2-ABC-ADHERENCE-1 结论复述：可引导范围、歌词/风格输入形态）；时长/延迟/显存约束、批量可用性；**乐谱调整→稳定统一重生成**的复现性（展演安全资格，用户定位）。可选探测腿：本地跑 1-2 个样例听输出结构（临时目录落盘）。
2. **Suno-MCP 面**：接入形态（现成 MCP server 选型还是自建薄壳）；工具面（生成/stems 分轨/时长/风格参数）；凭据与计费形态。
3. **agent 侧接入模式**：MCP 套壳进工具目录的形态（与 catalog/policy 的关系；对照仓库既有外部工具先例 browser_fetch/browser_search）；YuE2 本地直跑（进程/CLI 调用）vs MCP 化的取舍；一句话评估"MCP 作为外部能力通用接入模式"的可行性。
4. **人声路径（裁定输入·决策梯子已定序）**：三层需求（整首歌人声 / 工程内人声轨 / 可编辑精细合成）× 现有源覆盖矩阵；**按梯子出证据：① YuE2 仅人声模式/双轨（用户已知乐器独奏可行）→ ② Suno stems 可得性 → ③ demucs 类分离一句话选型 → ④ 专用人声模型套壳（仅前三全败且人声成关键需求时，默认不排）**；**GEN-VOCAL-SYNTH-1 归置建议**（大概率取消——专用人声合成套壳不做，"生成+分离"路径覆盖）。
5. **生成线分工草案（用户定位已到位）**：YuE2=展演中需要生成环节时使用的主力模型，资格=乐谱调整→统一性稳定重生成（可编辑性/演示安全）。**候选接入点（建议非定案）=乐局终局导出**：最终变奏 MIDI→ABC→YuE2 按谱渲染成品音频（展演脊柱=符号域一条龙：拍谱入→教学共创加工→按谱出成品）；勘察给该接入点的工程形态（转换链、时长、失败兜底=直接用工程内渲染音频）+ 若不采用给答辩后产品线卡序。
