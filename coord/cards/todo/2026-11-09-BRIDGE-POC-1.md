## 背景（一段）

322 run9 r3 证明模型可自含编码（单锚点+世界知识，315Hz→0.430906 等八个值精确对数刻度吻合）；但 T4（H-Delay 250ms）0/3 证明参数面选择/联动对是真实失败面。改革方向 C=物理值提案（模型）+通用编码桥（机器确定性反演 display probe）。本卡验证桥的核心假设：**display probe 数据足以反演任意参数编码**。

## 目标

1. **数据定位**：Pro-Q 3 与 H-Delay 的 display probe 多点数据（value_text↔normalized 对）——先找缓存/工件（pluginprobe 产物、run9 readback、320/307 系列装置工件）；不可得则申请一次轻栈窗口用 `plugin.get_parameters` 面采样导出（写入 run 工件）；
2. **反演最小实现**（throwaway 脚本，落 `coord/runs/BRIDGE-POC-1/`）：曲线族拟合（log/线性/幂/enum 查表/toggle），每参数产出编码描述（kind+量程+曲线+置信分级），置信不足→fail-closed 标记不可反演；
3. **双锚验证**：
   - **T4 锚**：H-Delay delay 参数 250ms → 反演归一化值与已知正确值 **0.5263**（B-R1 payload 解剖在卷）偏差换算回 ms 误差 < 2ms；
   - **r3 锚**：Pro-Q 3 八参数（315Hz/-2dB/Q1.1；9kHz/+2dB/Q0.7 等）→ 反演值与 run9 readback 已知归一化值偏差 < 0.002；
4. **失败面清单**：enum/toggle/联动对/probe 低置信参数如实列边界（不可反演=诚实声明，不硬造）；
5. **报告**：拟合方法、置信分布、两锚结果、对改革设计 M1 的输入（编码描述 schema 建议）。

## 文件域

`coord/runs/BRIDGE-POC-1/`（脚本+工件+报告）；零 agent 源码；零内核；只读消费既有 run 工件与 `~/.vit` 缓存（写前备份，不动原件）。

## 验收标准

- 两锚通过（T4 ms 误差 <2ms；r3 偏差 <0.002）→ 方向证实，报告产出 M1 schema 建议；
- 或如实负结果（拟合不收敛/probe 数据质量不足）→ 报告修正方向建议（负结果同样验收通过——本卡买的是判断，不是通过率）；
- 零 LLM 零计费（纯确定性计算）；若走栈窗口，栈协议两条登记照旧。

## 停止条件

- probe 数据既无缓存又无法轻栈采集 → 上交接判（不硬造数据）；
- 拟合系统性偏差（同族参数全偏）→ 停手记录，防止在错误曲线族上凑锚点。
