# L2-1-RLM-1：交付 profile 参数化 v1——参数向量+内置 profile+一 render 一 profile（数据结构层）

- 优先级 / 预估 / 依赖：P1 / 0.5 天 / 路线图 D9（AGENTIC-OBSERVATION 蓝图）；与 L2-1-TIM 线并行零交叉
- 模型分级：L2 / GLM 亲自或强督导（RLM 是现行生产投影，改结构须保旧记录兼容）
- **执行侧（PC 会话，agent/internal/rlm 域）**
- 背景：路线图 D9——各行业标准=参数向量（integrated LUFS / short-term max / momentary max / true peak / 声道配置）+各特殊规则；一个 render 挂一个 profile（响度标准是目标带，"按最严的做自动满足其他"不成立）。
- 目标（v1 范围钉死=**数据结构+选择/校验层，不接渲染链**）：
  1. **profile 数据结构**：参数向量定义（字段+单位+区间+带语义：target band 而非单向门槛）+ 特殊规则扩展位（如 headroom 策略标记）；序列化格式（旧状态缺省语义：无 profile 字段=现行为不变，fail-closed 未知枚举——§11 纪律）。
  2. **内置 profile 集（4-6 个）**：Apple Music / Spotify / AES streaming / EBU R128 / 广电（数值按公开标准落，来源注记）。
  3. **选择与校验**：render 级 profile 绑定接口（一 render 一 profile，多交付物=分支管理不属本卡）+ 参数合法性校验（带内一致性：short-term max ≤ momentary max 等）。
  4. **红绿测试**：修前红=profile 结构/校验/往返序列化断言（新测试，无旧断言可红则红=构造非法 profile 必须被拒+旧记录无 profile 加载不炸）；旧 RLM 测试全量零回退。
- 约束：零渲染链改动（计量/监督挂接=后续卡）；agent 全量 84 包 0 FAIL；旧记录兼容测试至少一份真实旧工件往返。
- 验收：①结构+5 个内置 profile+校验落地红绿 ②旧记录往返测试 ③agent 全量 exit 0 ④回执带 HEAD+diff stat
- 停止条件：RLM 现结构与 profile 向量语义冲突（发现旧字段语义不可兼容）→ 停止实现，冲突实证上交决策侧裁定
