## 背景（SHELL-4 遗留边界，如实）

SHELL-4 已实现新建链端到端，但内核 `new_project` 命令面**不接受工程名参数**——「新建工程《X》」最终落草稿 `Unsaved.vit`（正式 run 三轮 `new_project_context_name=Unsaved.vit` 亲证）。用户语义期望：新建即得名。

## 目标

1. 内核侧：`new_project` 命令面接受可选工程名（或等价 save_as 命名链），落盘文件名/工程身份携带该名；旧调用缺名=现行为（草稿 Unsaved.vit）零回退。
2. agent 侧接线：launcher 新建指令（launcher_flow.go 已带 ProjectName）透传内核；回执/工程面显示名实相符。
3. 边界③一并裁定：空白 boot 草稿是否豁免首开治理三键卡（SHELL-4 验收采纳「语义正确」，本卡定夺豁免与否并实现）。
4. 持久化兼容（AGENTS §11）：新增字段/命令参数的旧状态缺省语义+旧记录往返测试。

## 非目标

- 模板/参数化新建（后续）。
