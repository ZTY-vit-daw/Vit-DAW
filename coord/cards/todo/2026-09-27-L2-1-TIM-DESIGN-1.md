# L2-1-TIM-DESIGN-1：编译器第一层 TIM 结构断言器 v1 设计（断言清单+实现锚点）

- 优先级 / 预估 / 依赖：P0 / 0.4 天 / 路线图 D8 第一层（AGENTIC-OBSERVATION 蓝图）；实现卡（L2-1-TIM-1）依赖本卡产出
- 模型分级：L1 / flash 可接（只读勘察+设计文档，零代码改动）
- **执行侧（mac 会话，VitApp 域）**
- 背景：路线图 D8 编译器第一层=结构合法性断言（编译级、确定性、不用听），承载者"TIM 扩展为完整断言器"；关键验收=对现有收口版本工程即刻增值（监督报警路径端侧烟测 exit 0）。
- 目标：
  1. **TIM 现状盘点**：`tim.projection.v0_2` 现有结构、数据源、产出时机、消费方（agent 侧 contextruntime/CCB 怎么用它）——锚点到文件:行。
  2. **断言清单 v1 定义（3-5 个，范围钉死不贪）**，候选池按数据可得性选：路由完整性（意外反馈环/死路——若 v1 数据不足可延后）、信号卫生（削波/NaN/Inf/DC offset）、true peak ≤ 目标、采样率/块长一致性、插件合法装载状态。每个断言器给出：**谓词（精确到可写测试）+ 作用域（轨/总线/全局）+ 数据源（现成投影字段 or 需内核新增输出——新增的标注"内核腿"）+ 判定位置（内核 VitApp vs agent 侧）+ 失败动作（warn/block，v1 全部 warn）**。
  3. **实现锚点与测试计划**：每个断言器的主要落点文件（VitApp/Source/Service 的 TIM 扩展位 or agent/internal/tim 装配位）+ 红测试方案（修前应红的最小构造）+ 端侧烟测断言草案（监督报警路径：WARN 行出现在哪、谁消费）。
  4. 设计文档落 `docs/TIM_ASSERTER_V1_DESIGN.md`（现行索引登记：规划态）+ 摘要回执。
- 约束：零生产代码改动；断言器选择以**数据可得性优先**（现有投影/内核字段能支撑的先进 v1，需新增内核输出的一律标注"内核腿"留给实现卡评估）；裁判不下场原则写入设计（断言器只红绿灯，不做修正）。
- 验收：①TIM 现状锚点完备 ②断言清单 3-5 个每个五要素齐（谓词/作用域/数据源/判定位置/失败动作） ③每个断言器有红测试方案 ④设计文档入库+CURRENT-STATE 登记（回执注明，登记合入由决策侧收口）
- 停止条件：候选断言器数据可得性全部存疑 → 现状盘点成稿+数据缺口清单上交，不开空设计
