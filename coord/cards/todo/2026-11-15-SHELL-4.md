## 目标

1. **内核生命周期前移**：VitShell 拉起的 agent 在启动时即拉起 headless 内核（VitApp headless 服务）+ VspHub 并完成连接——冷启动后启动台阶段进程树即含 VitApp；内核/装载不再挂在「打开工程」动作上。
2. **启动台功能真数据化**（内核在线后应自然可用，逐项断言）：
   - greeting 带真实 recents（非降级模板）；
   - 「最近工程」列表加载出真实条目（无无限转圈）；
   - 按名打开（「打开 X」/「继续」）命中真实工程；
   - **新建工程端到端**（当前缺口，launcher_flow.go 新建链 → 内核 create → 进工程）；
   - 内核不可达时的诚实呈现：明示「列表暂不可用，仍可从文件打开」，替换无限转圈与误导文案。
3. **单内核所有权+内核生命周期归属主窗**：进工程时 Godot/装载链附着到已运行内核，不得出现双内核并存（领取时先锚定当前打开链上内核由谁拉起：agent 还是 Godot，再定实现位）。**内核仅随 VitShell 主窗退出而退出，关 DAW 回启动台后内核留存**（手测 v6 证据：18:35:15 用户发消息→18:35:17 内核随关 DAW 死亡→agent 循环 capability_unavailable 失败；LLM 调用本身成功——遥测 `agent_llm_telemetry.jsonl` deepseek-flash error=""，勿把该失败误归因 API）。回主窗后最近工程/对话须继续可用。
3b. **失败文案与状态区分**：内核不可用与 LLM API 不可用是两回事，UI/回复文案必须让用户能区分（手测中用户把「内核/能力不可用」读成「API 配置没连上」）——归入目标 2 的诚实呈现。
4. **文案对齐**：agent 回复中「磁带流」词汇对齐 v5.1 UI（现 UI 无磁带流元素；磁带 icon 已功能化）——launcherKernelUnavailableReply/launcherNoRecentsReply 等（launcher_flow.go:548-549）与 webui 同类文案一并修。
5. **烟测扩展**：vitshell_full_smoke.ps1 同模式加「启动台内核在线」断言腿：冷启动后 VitApp 在树 + get_recent_projects 真数据 + 新建链端到端（fixture 名工程创建→进工程→teardown 清理）。S10 recents 快照还原纪律照旧。
