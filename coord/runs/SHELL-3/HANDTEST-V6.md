# VitShell 手测 v6 放行包（SHELL-3）

- 发卡面：SHELL-3（池序 358）；放行范围=**架构形态**（单窗宿主/进程树/打开-关闭往返/关窗即退）。**视觉保真终验另卡（359）**，本包不判观感。
- 依据：全旅程真栈烟测已过（run IDs 见卡面回执；主腿 3 轮+失败注入腿+legacy 声明腿）。
- 执行人：用户（手测）；预计 10-15 分钟。

## 前置（30 秒）

1. 关闭所有 Vit 相关窗口/进程；任务管理器确认无 `VitShell/VitAgent/VitApp/VspHub/Godot` 进程。
2. 不需要设置任何环境变量（烟测的零计费/直启参数面只属于自动化装置；手测走默认真配置）。

**双击 `D:\Godot\project\vit-daw-frontend\VitShell\build\Release\启动VitShell.cmd`**（包装=VitShell.exe + 开发态装配参数，见「已知边界」第 1 条；被启动的正是同目录 `VitShell.exe`，sha256 bb7066e49c90a7b1…，主检出 @14d1f27 现场构建）。

观测（主窗形态）：

| # | 观测项 | 期望 |
|---|---|---|
| 1.1 | 首帧 | 主窗标题 **Vit** 出现，先见装载态（转圈/「正在启动…」），**无 splash 窗、无 Godot 窗、无第二窗** |

重复第 2 步再开一个（或同一个）工程——上一工程会话仍在 agent 态时，应出现页内三键卡（**保存并切换 / 直接切换 / 取消**）。选「直接切换」→ 新工程直启。

## 已知边界（如实声明，观测到不等于新缺陷）

1. **裸双击 VitShell.exe（不带参数）当前=窗内错误页**——装配链需 `--dev-root`（代码锚点：VitShell main.cpp 497-500 默认 agent 推导依赖 dev-root；arg-free 装配属生产改动，出 SHELL-3 文件域，候后续卡）。故本包用同目录包装 cmd 承载「双击」步骤。
2. **save 选择链**（治理卡「保存并切换」→ IFileSaveDialog）真栈未单测（SHELL-2 遗留）——手测第 5 步如走「保存并切换」即首次真栈覆盖，失败按现象记录。
3. **「＋新建」new_project 链**真栈腿未覆盖（SHELL-2 遗留；与 open 共享执行体）——手测可顺手一试，异常记「352/新开摩擦」类现象即可。
4. **launch-result 语义=IPC open ok 即回执**：dock 内边缘装载失败宿主不感知（SHELL-2 遗留）——如 DAW 窗开了但工程内容异常，记现象。
5. **IFileOpenDialog 真实对话框**此前仅烟测旁路——第 2 步即首次真域验证。
6. **352 首开摩擦如复现**（如首开出现治理卡/按钮禁用/往返卡顿）：记录现象+一句上下文即可，不现场排查。
7. **WebView2 缺失机**：会先弹系统错误框（本卡已注入验证该路径）；正常 Win10/11 自带 runtime，不该遇到。
8. chat 的 LLM 内容质量、混音功能正确性、视觉保真（359 终验）均不在本包范围。
