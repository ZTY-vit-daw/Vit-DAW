## 1. 可以承诺的行为

在 Vit 正常运行、受管教学任务开启、模型仅持被授予能力的范围内：学生继续使用现有编辑器；模型可以读作答、请求用户动手、在许可的示范区操作，但不能通过其任何执行路径改写受保护作答对象。禁止范围含新增、修改、删除、导入覆盖、剪切移动、结构替换和间接修改。

这是一项内核访问控制不变量，不是模型提示词规则。完整实现后，模型即使准确生成一个写作答的命令，实际状态仍不改变。不将其延伸为“学生未使用外部 AI”或“本机管理员无法修改程序”的保证。

## 3. 推荐实现路线

以下均为引擎和运行时必须执行的不变量，不要求教师在 YAML 中配置调用凭据、连接或守门函数；教师只选择哪些区域属于作答、哪些帮助允许发生。学生和模型不能通过编辑规则请求扩大已发布权限。

### 3.1 内核持有规则与对象保护

加载教师发布的工程规则时，建立教学任务 ID、发布版本和受保护轨道/片段的稳定 ID 映射。初版保护整条作答轨，不用名称匹配。轨道重命名、clip 重建和保存重开不能去掉保护；需要修改保护范围只能经教师规则发布路径。

权威规则随工程内嵌保存；打开受管任务后，在规则与对象映射核实前不接受作答写入。规则缺失/绑定不一致时保留工程并提示，不能静默降为普通可写工程。

### 3.2 先确定调用来源，再解释业务命令

由可信入口为调用生成上下文，包含学生编辑能力/模型能力、任务和发布版本；业务 JSON 不能填写或覆盖它。推荐前端与内核建立有认证的编辑连接或受限能力通道，复用现有编辑指令，无需新建教学答题业务 API，也无需学生每次登录/确认。

当前 UDP 桥可继续承担不敏感传输；但若继续作为编辑入口，必须认证并保留前端来源，不能把任何到达桥的包自动升为学生写入。模型无凭据的直连请求同样不得被内核当作学生编辑。具体选用本机受控 IPC、认证传输或能力凭据，由实现勘察选定；验收必须证明不能靠任意 JSON/普通模型工具获得学生能力。

可信服务持有凭据和会话状态，模型只获得其允许的工具。调用经过 VSP 解包、重试、批量分发等层时，上下文必须原样保留，不能在递归分发裸命令时丢失并默认放行。

### 3.3 在实际修改前检查全部影响范围

集中分发做第一道检查，实际写服务解析真实对象后再校验影响范围；两者共用内核规则函数。检查与写入在同一受保护执行序列/事务中完成，避免检查时是示范区、执行时对象已移到作答区。

教学中模型默认仅能调用明确允许的命令；未知写命令和无法判断影响的写操作拒绝。新增命令未声明影响范围时也不能自动获得作答写权。

必须覆盖：

- 音符新增/删除/修改及批量 patch。
- clip 创建、导入、复制、移动、剪切、合并/替换、父轨变更。
- 轨道删除/清空、工程清空、snapshot/历史检出与工程重载造成的状态替换。
- global undo/redo：不能让模型借此撤销学生作答；无法证明局部影响时拒绝模型调用。
- 与题目坐标和判据有关的拍号/速度/时间映射变更，按教师规则处理，不让移动作答或改规则基准绕过检查。

不是所有命令都要重新实现；可复用已有服务，增加可信上下文、影响范围解析与共同守门。缺少安全影响分析的复杂命令可先在教学模型通道禁用，而非为首版开放全量能力。

### 3.4 封住模型工具旁路

受保护任务中，不向模型开放能改工程/规则/日志或伪造学生通道的 shell、任意网络/脚本、文件替换、宿主控制与不受约束的委托。保留的工具必须有明确范围，教师禁令不能通过学生确认解除。读取凭据与修改进程/内存不属于模型能力。

同一 Go 进程包含桥接模块并不自动表示模型能取得桥接权限；但若同时授予模型任意宿主执行/文件读取，就破坏这个前提，不能声称仍有强隔离。需要更广宿主能力时，必须先增加操作系统/服务隔离或让该能力留在教学受管任务之外。

### 3.5 写入记录与状态检查

允许的学生修改与其来源记录绑定到同一工程修订；失败不得生成成功贡献。权限拒绝时，受保护状态不改变，包括处理器产生的部分修改。写入与记录无法完整提交时应停止继续受管操作并保留可恢复状态，不静默留下“成功但无来源”的作答。

模型编辑许可示范区时，受保护作答的内容摘要应保持一致；学生采用示范时，保留模型方案来源而不洗成独立作答。摘要用于比对内容，不把本机摘要本身当作教师身份签名。

## 4. 实现后怎样证明

| 验收组 | 必需结果 |
|---|---|
| 学生正常路径 | 使用现有卷帘新增、拖动、删除、保存作答成功，来源记录与工程修订一致。 |
| 模型直接写 | MIDI/clip/轨道各写面针对作答区均被拒；比较操作前后受保护状态一致，而非只看拒绝文案。 |
| 模型旁路 | 旧裸命令、VSP、直接 invoke、批量操作、导入覆盖、示范转移、历史恢复和 global undo 不绕过保护；未授予的 shell/文件操作不可执行。 |
| 来源伪装 | 自填 student/teacher/origin、重放旧请求、换会话/模型/子代理都不能取得学生编辑权限。 |
| 持久化与重入 | 另存、重开、恢复中断、规则不一致、保护映射缺失时不失效，不静默降级。 |
| 合法模型能力 | 读取作答、播放、许可示范编辑仍可用；模型“请用户作答”只定位编辑器，不暗带写入。 |
| 普通工程回归 | 不绑定教学保护的共创工程仍按原授权工作。 |
| 推进门 | 仅有效检查回执推进对应节点；伪造/旧修订/跨题回执、重复请求不跳关，不新增逐题确认卡。 |

这些检查先在单元/集成层落实，再通过仓库现有脚本体系对真实 VitApp/Godot/agent 栈测试，并覆盖实际渲染与用户旅程，保留原始命令、退出码、工件和版本。所有必需项通过才接受“模型不可写作答区”的产品表述。

## 5. 定稿边界

可冻结的需求：**对象层隔离、学生原编辑方式、模型可读/可委派/可示范、模型不可写作答、有效回执才能推进、无需逐题弹卡、来源与作业报告可回溯。**

待实现证成：可信调用来源贯通、全部写入口覆盖、模型宿主能力限制、规则保存恢复、检查回执与证据记录。接口名称和传输细节可在不削弱不变量的前提下由执行侧设计；若现有架构无法建立可信来源或发现未纳管写者，须上交取证，不能以提示词或工具隐藏代替。
