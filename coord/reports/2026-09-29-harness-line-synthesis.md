## 1. harness 线=蓝图，不是 5 月规划

蓝图一句话定位：把 coding agent 的 pull 式上下文获取引入 DAW 域——统一寻址（ref schema）+ 物化索引 + 毫秒级查询 + **可变上下文窗口（D6：四层稳定前缀+退场机制，即用户所说"浮动上下文窗口"）**+ 音频编译器三层 + 质询-确权协议 + memory 四层，把 harness 从"固定相位轮次推送装配"升级为"LLM 主动检索"，使超大工程不依赖固定编排即可运行自由态工作流。

**用户 09-29 所说"固定编排层退役"= D15 的准确语义**：混音能力层**降级不删除**（快路径库，模式化高频任务仍走编排、路由由 planner 决定）；相位轮次降级为冷启动第一轮；新旧 harness flag 并存、G3 A/B（至少一个完整工程双模式全流程对比）后切换。与论文讨论的"自由态=过渡概念、内部对照转发展叙事"完全一致。

## 3. 与今日两条新线的交叉

1. **宏组件线：不依赖新 harness**——走现行写路径（VSP/PCA/剂量域）+webui 控制车道，与蓝图正交（宏=交互层，蓝图=观察/上下文层）；且 5 月规划的 plugin grabber 宏工具（plugin_map_macro_to_params）是其前身，方向连续。可按既定计划并行（RECON→DESIGN→IMPL）。
2. **编曲/生成线：与蓝图的汇合点存在时点张力**——蓝图明确"编曲/AIGC 能力在新 harness 上开发（大颗粒、长时程任务，pull 模式最苛刻试金石）"；但今日定的 v1 骨架中，**通路层（工程统一性底座/资料库/生成驱动 CLI/外部导入/音频转 MIDI）不依赖 harness 拉取模式**，可先行。排程裁定项：通路层先行到什么程度、核心编曲能力（NL 写入轨道等长时程任务）等 L1-5。ARRANGE-RECON-1 勘察面不受影响。

## 4. 终版排程的输入结论

- 排程框架**不需要另发明**：蓝图两线五段一汇合就是骨架；D 阶段做的是把宏组件线、编曲/生成线、论文写作线（用户审稿+轮 6/7）、实验线（ADAPT→PILOT→MAIN→JUDGE）+双端分工嵌进去。
- 关键路径：L1-3 收段（本周）→ L1-4（浮动窗口）→ L1-5（G3 A/B）→ 汇合（编曲 on new harness）。
- freeze 11-17 与蓝图的边界：论文正文只需混音实验（已定案），L1-4/L1-5/汇合**可以跨 freeze 继续推进**（freeze 管论文写什么，不管开发——质量第一裁定下的自然推论）；展演（12 月中冻结）是汇合编曲的演示时点。
- Mac 端候选：L2 线剩余段（交付 profile/段落 DSP 收尾/质询协议实现）在 Mac 并行最顺（PORT 期间 TIM 面先例）。
