## 1. 要回答的问题与决策顺序

用户的核心假设是：插件抓手已经提供参数控制基础；近月模型升级或联网获取插件知识，可能已使模型能够自主理解参数差异并正确控制效果器。应当先测 Vit 当前实际运行的模型，再决定系统需要增加、保留或简化什么。

若能力成立，运行时辅助可能主要是薄提示词策略：例如形成候选效果器链之后，集中查清具体未知项；知识缺口影响插件选择时允许提前查询；复用已有查询结果，减少重复检索。这是待验证方向，不能提前当成结论。

本方案依次回答四个问题：

1. 当前 Vit 产品路径实际能完成哪些任务，失败卡在哪一层？
2. 直接提供原始参数与通用工具，当前模型本身能完成多少？增加检索、增加现有语义适配各带来多少增益？
3. 正确控制参数以后，模型能否利用实际获得的观察反馈，让声音达到目标？
4. 能力足够时，什么检索时机能在维持任务效果的前提下减少总成本？

先测能力，再根据失败位置设计辅助；保留“无需新增复杂适配”的可能，也保留“检索仍不足”的可能。编写新适配器、建设全插件说明书库、全参数行为扫描，均不是首轮实验前提。

## 3. 两条验证路径：当前产品基线与能力对照

### P：当前 Vit 产品基线

先使用执行时的真实默认模型、默认提示词和默认工具披露路径，跑一组冻结任务，记录完整链路。已有近期工件只有满足相同任务、版本、提示词和评价标准，才可代替对应基线轮次。

记录模型实际收到什么、能否进入工具循环、是否被准入或授权拒绝、调用了哪些语义工作流，以及最终参数状态。基线包含现有系统帮助，不能称为模型裸能力。

### A/B/C：控制辅助的对照

首轮固定插件实例、任务、初始状态和素材，把“诊断问题、选什么插件”暂时收起来，集中测参数控制。三组使用同一个被测模型。

| 组 | 模型可获得的信息和工具 | 主要回答 |
|---|---|---|
| A：原始抓手 | 插件真实身份与版本、原始参数名称/ID、插件提供的单位/范围/枚举/当前值、通用读写和回读工具；不联网 | 现有模型先验加原始接口是否足够 |
| B：原始抓手＋检索 | A 的全部能力，再允许检索和读取官方插件资料；不注入人工答案 | 外部知识能否弥补缺口，且被正确运用 |
| C：检索＋现有语义适配 | B，再提供当前 Vit 已实现的语义解释、角色映射和受控转换/写入工具 | 当前辅助栈在实际成功率与成本上增加多少价值 |

具体约束：

- A/B 必须能访问完整原始参数目录，允许通用分页或按原始文本查找；不能先由族词表选出“正确参数”再交模型，也不能静默截断导致目标参数不可见。每轮记录实际披露量和访问范围。
- 各组原始字段一致。`alias`、`normalized_role`、人工推荐组、族识别结论等语义加工，仅 C 可见。插件原生的单位、枚举和名称均可在 A/B 使用，不能故意削弱原始接口。
- 通用的纯数值转换若已能独立提供，可各组共用，但须列出来源和能力；若只能通过语义解释器取得，则计入 C。不能把其帮助藏进 A。
- PREP 必须检查工具说明、系统提示词和上下文是否泄露语义映射。无法分离时标明污染范围，不能命名为纯 A/B。
- C 同时增加语义与执行帮助，C 优于 B 只能证明整体辅助有用，不能单独归因于参数名映射。必要时追加“同一写接口＋已知正确映射”的诊断组，单独编号。
- C 不支持某长尾插件时，记录 `adapter_unsupported`。共同支持的插件用于三组配对比较；长尾 A/B 扩展单列，不能把 C 不在场算成该组模型失败。
- 各组保留一致的授权、范围、回读和撤销保障。若现有产品门使 A/B 根本不可达，先记录 `capability_blocked`，交主管决定实验入口；不放宽生产门来凑通过。
- 受控原始能力实验若获准通过探针入口，记录入口及边界，不冒充 P 产品路径成功。仍走现有 ps1 冒测体系和真实运行栈，不做独立假宿主。

## 4. 模型、任务与对照控制

### 4.1 先测当前实际部署模型

PREP 从配置、调用位置和可用近期遥测核对模型路由；正式运行以真实调用日志确认 provider、请求 model、响应 model（若返回）、采样配置、token/轮次限制、fallback 和重试。密钥不入报告。驾驶实验的开发会话模型与 Vit 内部被测模型分别记录。

首轮只测当前实际模型。只有主管认为有比较价值且模型可调用时，再增加一个候选模型，复用冻结任务和评价标准。跨组不能中途换模型；发生 fallback 的轮次分列。若服务商不提供版本快照，记录时间与可见标识，承认版本可复现边界。

仅新模型通过，证明其当前能力；要归因“模型升级”，必须有同条件旧模型对照。插件“未用于本实验开发”不等于模型训练中从未见过。

### 4.2 首轮建议六个案例，覆盖至少三件在库效果器、两个族

插件名称、版本、目标值、可达范围与容差，由 PREP 根据真实参数面冻结。下面是任务模板，不是 sealed 答案：

| 案例 | 类型与任务模板 | 独立判据 |
|---|---|---|
| T1 | 名称直观的连续参数：把指定控制设到可达的人类单位目标，保持其他控制不变 | 实际显示值/单位符合容差，非目标项未误改 |
| T2 | 特殊命名并含非线性显示域的控制：完成同类明确意图，不在提示词中点名应选原始参数 | 按插件资料和实际控制验证选项、数值与方向；不能线性猜归一化位置 |
| T3 | 离散枚举：选择指定实际档位，例如可用的 Attack 时间档位 | 回读枚举标签精确匹配；接口接受数值不足以通过 |
| T4 | 模式依赖或两个相互关联的控制：在指定模式下完成一组设置 | 模式与关联参数共同满足，顺序和联动造成的变化符合冻结规则 |
| T5 | 无需修改的对照：当前状态已满足明确目标，要求检查并保持 | 正确识别，无实际 mutation；重复写相同值也须记录 |
| T6 | 不可满足的对照：给定插件无该能力或目标超出可达域 | 明确说明限制或请求必要澄清，无捏造参数、无擅自改目标 |

正向任务 T1–T4 与对照 T5–T6 分开报告，不能靠大量正确拒绝抬高“会控制”的成功率。若候选插件不具备某类型任务，换任务实例并在跑前冻结，不臆造参数能力。

首轮以明确可评估的控制指令为主，避免混入完全开放的“更好听”。冷门和未适配插件作为后续扩展，用于判断泛化；不以知名度冒充真实训练覆盖率。

### 4.3 先确认考题与接口本身可完成

正式模型轮次前，在独立工程副本上用人工核实的正确操作验证正向目标可达、枚举/单位解释正确、回读与恢复有效。负向案例须核实确实无需更改或不可满足。脚本执行这些已知操作不应调用 LLM。

若正确操作也失败，先归类为夹具/接口/执行路径问题，不进入模型打分。评价器的正确参数、目标状态和允许变化集合不进入被测模型上下文。

### 4.4 公平性与独立性

- 同一案例各组恢复同一初始工程、插件状态、素材、时间窗和路由；每轮新会话，清空跨轮学习性缓存；输入和关键 fixture 前后核对哈希。
- 组序按预先固定的轮换或随机顺序执行，记录种子；不能先失败后临时换更容易的提示词。
- A/B/C 的模型总预算、工具预算、观察反馈和授权范围一致；具体预算跑前冻结。B/C 的检索预算相同。工具执行后的错误和回读反馈均可用于预算内修正。
- 把一次“任务开始→预算内操作与修正→终态”定义为一轮。保留首次提案与最终结果，不把一次轮内重试拆成新的独立成功。
- 主比较使用冷的任务知识缓存；提示词前缀的供应商缓存单独计费记录。跨插件复用知识和热缓存效率另做部署情境实验，不污染独立轮次。

## 5. 检索组必须记录什么

B 的主条件建议使用当前可用的联网检索工具，优先官方手册与支持文档；模型自行提出查询。记录查询、URL、访问时间、版本匹配、实际返回片段、内容哈希及进入上下文的长度。官方资料公开可访问情况先核对，但不提前给 B 正确参数映射。

检索失败要区分：没有发起查询、查不到适用资料、工具/网络拒绝、找到资料但未提取到信息、提取正确仍应用错误。`web.search` / `web.fetch` 在工具目录存在，不代表当前运行环境可用，权限与实际结果必须核查。

必要时另设 B-M 诊断：提供冻结的相关官方说明书片段，观察能否完成。这可以区分“找不到”与“读不懂/不会应用”，但不能替换 B 的正式成绩。用录制内容回放的实验应标明固定资料条件，不称为实时联网成功。

手册能够解释功能，不保证提供插件归一化传值规律；映射不足不能靠模型编造。有限回读试探可在各组相同的预算内使用，试探次数与成本计入结果。

## 6. 分阶段规模、预算与推进条件

以下是建议规模，须在 PREP 根据真实调用成本形成 RUNBOOK 后由主管确认；尚未授权批量运行。

| 阶段 | 建议轮次 | 目的与下一步 |
|---|---|---|
| S0：准备与可达性 | 零 LLM 的资料/接口勘察；真栈已知操作在后续获准运行时执行 | 冻结案例、模型、入口、评价器、次数和预算。门不通先交取证，不进行能力归因 |
| S1-P：当前产品基线 | 六案例各一次，共 6 轮 | 定位当前 Vit 的链路边界；单轮只证明该任务的一个样本，不证明稳定 |
| S1：能力 pilot | 六案例 × A/B/C 三组 × 每组 3 次，共 54 轮 | 逐案比较正向控制、正确边界与辅助增益；可按组拆小卡，但开始前固定完整计划 |
| S2：声音目标 | 条件满足后另定规模与预算 | 测固定链的声音改进，再测自主选链，避免一次引入两类不确定性 |
| S3：检索策略 | 能力已有依据后另定规模与预算 | 比较搜索时机、缓存和总成本，不与 S1 同时改提示词 |

S1 上限为 60 个计划模型任务轮次（P 6＋对照 54），不是 60 次 API 调用。一轮可有多次 LLM 调用；提示词、工具返回、续跑、重试和检索均计费，不能写成“脚本腿零成本所以整项零成本”。无独立预算不追加模型矩阵、诊断组或样本。

RUNBOOK 跑前必须写明：每轮最大 LLM 调用次数、工具次数、检索查询和 fetch 次数、输入/输出或累计 token 限制、超时、预计费用与批次费用上限、允许的环境重建次数。无法可靠预估则先申请独立的校准小样本；校准不混入正式成绩。

建议 pilot 筛选线：某组正向成功至少 10/12、各正向案例至少 2/3；两类对照合计 6/6；零越权/越界实际写入。满足只表示值得扩大验证或进入 S2，不证明生产可靠性，也不直接授权删除现有适配。未达线仍交付完整失败证据，不把实验视为必须调到通过。

六个案例只是可行性摸底，同案例三次重复不等于三个独立插件样本。报告逐案原始分数和组间配对差，不对合并轮次假定独立后宣称稳定性。扩大实验时先定义有实际意义的成功率差或可接受退化，再按插件/任务聚类规划样本和不确定性分析；差异未检出不能当作等效。

## 7. 评价、失败分类与停止条件

### 7.1 每轮的判定面

至少记录：入口是否可达、实际披露、首次选择/提案、执行请求与响应、参数独立回读、非目标项变化、恢复状态、最终交付、总调用/token/费用/时长。成功必须由独立评价器核对，模型自述不作判据。

正向成功要求选对控制、目标值达到冻结容差、模式正确、无未允许的附带修改。插件自身联动或自动改值，须在已知操作控制中界定允许变化，不能一概误判，也不能事后扩充白名单。

回读应重新查询实际实例；只比较模型提案与执行回执中回显的请求值不够。参数 ID、归一化值、显示文本/枚举标签并存，防止“写进去了但单位错了”。

### 7.2 失败分类

| 分类 | 判定依据与计分边界 |
|---|---|
| `entry_or_authority_blocked` / `capability_blocked` | 未进入控制工具循环或被产品门拒绝。计入产品路径失败，不能声称已测到原始能力 |
| `parameter_semantics_error` | 参数选错、方向/模式含义理解错误，需要实际提案/操作证据 |
| `value_encoding_error` | 单位、枚举、归一化或显示域转换错误；区分模型请求错误与系统转换错误 |
| `execution_or_interface_error` | 正确提案未落地、回读与实际请求不符、接口无效等；附最小请求和响应 |
| `retrieval_unavailable` / `retrieval_miss` / `retrieval_application_error` | 分列检索不可用、未找到有效资料、资料应用错误 |
| `no_candidate_found` / `model_budget_exhausted` / `model_task_failure` | 保留本来含义，预算耗尽不是环境中断 |
| `acoustic_goal_not_met` | 参数执行正确，但声音指标或盲评目标未达；S2 使用 |
| `unexpected_mutation` / `boundary_violation` | 未授权目标/参数/工程实际被修改；保留证据并立即停止相关运行 |
| `crash` / `environment_interruption` / `harness_invalid` | 崩溃单列；环境排除须有原始日志/退出证据；污染、夹具错误或组别泄露单列无效原因 |

可保留多标签与一个最早确定断点；缺少证据时标 `unresolved`，不凭猜测指定根因。另记模型的应对行为：直接猜测、主动查询/澄清、主动试探、发现错误后修正；不收集或要求隐藏思维过程。

### 7.3 分母、退出码与停止

- 报告分列计划数、已尝试数、已进入模型能力面的轮数、完成评价数、成功数、各类失败和未运行数；同时报告全路径与可达条件下的结果，不静默排除门拦截、拒绝或预算耗尽。
- 原始脚本退出码逐层保留。实验 runner 若将“评估完整”定义为 exit 0，必须另有模型任务 verdict；exit 0 不代表所有任务成功，更不代表产品验收通过。夹具/断言器/栈异常不能被包装成有效模型失败或完成。
- 同一版本在同一确定性断点连续失败两次，停止该故障路径原样重跑，缩小假设或转取证/修复卡。其他不受影响案例能否继续按 RUNBOOK 的预先规则处理，不事后为了凑样本决定。
- 环境中断只有原始证据支持时才可排除；补跑分配新 run ID、保留原结果。补跑上限跑前冻结，默认最多一次环境重建。
- 达到费用、轮次或时间上限即停止，报告剩余未运行。出现 fixture 污染、组别信息泄露或未允许写入，立即停止受影响批次并隔离证据。
- 代码/提示词/评价器修订后形成新批次，不替换旧失败、不把不同版本合并成一组成绩。LLM 随机失败只能使用预定剩余轮次，不能成功为止。

## 8. S2：从“写得对”推进到“声音符合目标”

进入条件是 S1 已证至少一条可用的控制路径，且音频渲染、同窗比较和观察反馈有效；局部控制证据不能代替出声验证。

先固定效果器链，使用“让人声更稳定，同时保留句首力度”等目标，允许观察→调整→再观察。之后再增加自主选链任务，单独评价选型和链顺序。各组使用相同素材、反馈面和总预算。

评价采用跑前冻结的目标指标与副作用约束，音乐偏好部分使用随机顺序、响度匹配的 A/B 盲评，并记录听者、比较单元和偏好/无差别/退化。不以某个观察投影分数代替全部听感，不以 LLM 自评作唯一评价器。

模型实际获得的是音频、特定观察投影还是只有参数表，必须写清；没有向模型提供的反馈不能事后假定它“已经听过”。如需用户参与盲评，另交主管安排，不新增当前既定手测义务；人工体验入口遵守从 Godot 启动 DAW 再进入工程的约定。

## 9. S3：验证“薄检索提示词就够了”的方向

仅在能力路径已有证据后开展。固定模型、辅助能力、任务和预算，只改变检索策略：

| 策略 | 规则 |
|---|---|
| R0：不检索 | 使用已有知识与相同控制/观察工具 |
| R1：逐插件检索 | 每个选中插件在调参前做一次有界官方资料检索，作为费用比较条件 |
| R2：按节点和缺口检索 | 优先形成候选效果器链，再集中检索具体未知项；若知识缺口直接影响选链则可提前查；复用本任务已确认信息 |

R2 的候选提示词，仅用于后续实验，不写入当前生产：

> 优先使用已有知识和当前参数描述。形成候选效果器链后，检查完成任务所需的未知项，仅检索这些未知项，优先官方资料。查询前用一句话说明待查问题及其影响的决定；复用已确认的信息。若知识缺口影响效果器选择，可以提前针对该问题查询。参数含义、单位或枚举不清，或写入回读与预期不符时，重新检查相关依据。

参数元数据缺失、枚举含糊、回读不符是检索/复核信号，不能完全依赖模型自报“不懂”。候选链不是不可更改的硬锁；资料表明不适合时可以在授权范围内修订选择并记录原因。

主指标为任务效果与实际退化，其次是整次任务总 token、费用、耗时、搜索/读取次数、返工和重复检索比例；输入工具返回及失败重试均计入。报告冷/热知识缓存与供应商提示词缓存的差异。

若要认定 R2 在维持质量的同时节省成本，扩大验证前须冻结可接受的质量退化幅度与样本计划；小样本“没看出差异”不等于质量保持。试验结果若支持薄策略，则优先采用并保留回归基准，不因此预建复杂适配栈。

## 10. 结果如何决定设计

| 观察结果 | 优先设计方向 | 还不能据此声称什么 |
|---|---|---|
| A 已能稳定完成，C 增益有限 | 扩大原始控制路径验证，评估精简语义辅助；研究 R2 节省知识查询成本 | 单批成功不足以直接拆生产适配或取消执行校验 |
| A 不足、B 有实际增益 | 优先改善资料获取、版本匹配和有界检索；验证节点策略 | 检索有用不等于每次都需搜索或必须建设全量手册库 |
| B 检索失败，B-M 成功 | 修资料获取/索引/工具可用性 | 不能归因为模型完全不会理解插件 |
| B 不足，提供已知正确映射后成功 | 参数语义或绑定是瓶颈，评估薄映射或可验证的模型生成适配 | C 比 B 好仍不足以单独证明某种映射算法有效 |
| 正确提案被拒绝或写错 | 改善通用数值/枚举/显示域转换、模式依赖和执行反馈 | 不能用更多参数别名替代执行层诊断 |
| 控制准确，声音不达标 | 改善观察、目标表达、受约束的搜索与比较策略 | 控制接口通过不是“会混音” |
| 知名插件可用、长尾不足 | 先验证手册补知识；残差再考虑有限行为探针或适配 | 不能只凭插件知名度判断模型训练记忆 |
| 结果偶发或模型升级后变化 | 扩大跨任务重复、保留常备基准，评估验证/重试/停止成本 | 一次成功不等于可靠产品路径 |

新增辅助都应可回归、可单独开关评估，允许后续模型升级使它变得不再必要。成功知识的复用应标注插件版本、参数面、模式和证据覆盖；局部验证不提升为整个插件的能力保证。

## 11. 开发工作流拆分建议与资源关系

只先登记一张准备卡，池序留给主管；不把整个研究作为一张实现卡领取。后续建议按以下目标拆分，名称仅供主管发卡时使用，尚未创建或授权：

1. **PREP**：只读核对当前模型与工具、字段来源、候选案例、评价口径、可达性缺口和预算，产出可派发实验计划。
2. **RUNNER**：在批准的文件域中复用 `scripts/dev_agent_smoke.ps1` 或同体系现有 ps1 入口，补夹具、组别隔离、评价器、工件和退出码；按需要再拆确定性验证和 test-only 披露缝。
3. **S1-RUN**：主管批准后的已知操作控制、P 基线与 A/B/C pilot；组别/批次拆卡也必须共用冻结计划。
4. **S1-REVIEW**：核实际 diff、日志、回读和费用，给出有证据的辅助层决策，再决定 S2、S3 或取证/修复卡。

PREP 无需占真实栈，可与文件域不相交的在飞任务并行。后续栈腿须核对最新卡池和 `coord/resources/PC-RUNTIME-STACK.md`，与 B3-ABLATION-1、D1D3-REGRESS-STACK-1、KERNEL-OFFRENDER-FORENSICS-1、VSTI-PARAM-PROBE-1 等实际在排/在飞栈腿错峰；名称与状态运行前再确认，不据本文顺序占栈。

音源探针的参数工件、A-F ablation 的隔离和遥测做法可复用，不能把它们并入本实验重复派发。效果器控制实验不自动承接音源控制或渲染缺陷修复。真实栈执行 owner 使用独立 worktree；占用同步、≤60 秒启动前核查、禁止静默复用和完整拆栈按仓库协议执行。

若改生产 agent，必须另过仓库要求的真实栈烟测并取得脚本 exit 0；实验 runner 的完整运行和负结果可以作为取证交付，不能冒充产品修复交付。渲染面/用户旅程未覆盖时明确声明，实验不以用户手测作为第一道验证。
