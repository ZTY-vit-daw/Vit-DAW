# Agent 窗口音乐交互控件：组件选型与展演范围建议

- 日期：2026-11-11；Codex 辅助设计会话。
- 依据：用户在课例内容设计前询问，能否加入类似 Gemini 的网页可视化交互模块，尤其是 tap 速度/节拍、五线谱 MIDI 编辑和随谱播放。
- 状态：只读源码勘察与官方资料核对，**未安装依赖、未做嵌入兼容试验、未实现**。候选不等于选型定稿，本文不启动生产实现。
- 当前目标仍为[展演体验优先](../decisions/2026-11-11-legame-demo-experience-first.md)。
- **用户最新范围确认**：Tap 速度/节拍面板、五线谱 MIDI 编辑、音频/MIDI 随谱播放均为本次展演必需功能；其他好用控件可评估追加，不将这三项降为可选。
- **交互方式已确认**：同时采用基础组件动态组合与预制音乐组件调用。具体目录/组合约定见[控件目录讨论稿](2026-11-11-legame-widget-catalog-draft.md)；不是只保留预制单卡。
- **最新控件收敛**：普通音频文件用轻量播放器；谱面显示/节奏输入/旋律编辑/随谱播放合为工作台；不单独做节奏格，A/B 复用既有实现并适配课堂语义。[资源盘点](2026-11-11-legame-widget-consolidation-and-reuse.md)取代分建六控件的建议，以下库能力对照仍有效。

## 1. 结论

可以做，并有可复用框架和音乐组件；没有已经核实的“一键装入 Vit 即可完成全部教学”的套件。需要补的主要是三部分：模型调用组件的协议、组件与内核的双向数据同步、与当前任务和过程记录的绑定。

当前已有网页承载，不需要先在 Godot 从零绘制全部音乐控件。初版建议在 agent 网页窗口里加入预先实现的音乐组件，由模型按结构化参数选择和调用。

## 2. 本地事实

- `agent/webui/package.json`：React 19、TypeScript、Vite；目前未安装下述音乐组件。
- `agent/webui/src/interactionCardKit.tsx`：已有 `interaction_card.v1` 声明式交互卡，支持 text/number/range/select 和 actions。它不是现成的谱面/节拍控件，但可复用挂载、提交与回流模式。
- 前端 `vit_dock/scenes/vit_dock_root.gd` 的 `_activate_agent_webui_host/_ensure_agent_webui_host`：通过 `VitWebViewHost` 导航到 agent WebUI。此次目标窗口能够承载网页组件；启动页的 Godot 原生对话与工程内 WebUI 不应混为同一种 renderer。
- MIDI 内核已有创建 clip、读音符、批量写入/修改和播放相关命令；前端控件仍需接线与回读，不以网页局部状态冒充工程已保存。

## 3. 类似生成式 UI 的框架

| 框架 | 官方说明及许可 | 对 Vit 的意义 |
|---|---|---|
| [Google A2UI](https://github.com/google/A2UI) | 声明式 UI 数据协议、组件目录与渲染器，Apache-2.0；npm `@a2ui/react` 声明支持 React 18/19 | 可让模型选择并组织已注册控件；音乐 tap/乐谱仍需自行注册与实现 |
| [CopilotKit](https://github.com/CopilotKit/CopilotKit) | 开源核心 MIT，提供 agent chat、生成式 UI、共享状态与人机交互；不同产品层的能力范围各异 | 有现成 React 交互模式，但适配现有 Go agent/事件与状态仍有成本，不建议仅为三类控件先迁移聊天运行时 |

本轮不声称 Gemini 用户看到的某个具体版本就是用这些框架实现。它们能实现相近的“对话中展示可交互工具”的产品形态。

A2UI 同时有协议规范、Agent/Renderer SDK、React 等框架适配及基础目录的组件实现。基础组件与布局可复用；没有发现其基础目录包含本课所需的音乐记谱编辑/Tap 专用模块。官方 [Catalogs](https://a2ui.org/concepts/catalogs/) 明确支持将应用自己实现的组件注册进目录，模型只生成组件类型和属性，渲染器负责真正呈现。因此“协议”和“现成控件”两者都有，具体音乐组件仍需接入。

用户已要求支持模型组合基础组件并嵌入预制音乐组件；A2UI 或 Vit 声明式扩展的选型需按这两种形态一起评估，不将自由组合后置为可有可无。安装框架本身不会自动具备音乐交互能力。

## 4. 音乐组件候选（本轮核对官方资料）

| 组件 | 能力与边界 | 许可 | 适合用途 |
|---|---|---|---|
| [abcjs](https://docs.abcjs.net/) | ABC 到五线谱、浏览器合成播放、选音和拖动回调、文本编辑联动；拖动本身不修改底层音乐，应用需更新数据并重绘 | MIT | 短旋律教学、可播放例子、限定范围的自建编辑器 |
| [VexFlow](https://github.com/vexflow/vexflow) | 乐谱排版/绘制基础；编辑操作、曲谱模型、播放和保存需上层实现 | MIT | 对教学界面布局和有限编辑进行精确控制 |
| [OpenSheetMusicDisplay](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay) | MusicXML 显示、数据与 cursor；官方明确其不是完整编辑器，核心库不能直接假定附带完整播放功能；部分播放器等为赞助功能 | BSD-3-Clause 核心 | 准确展示预先核实的教材谱例，与 Vit 播放位置联动 |
| [Smoosic](https://github.com/Smoosic/Smoosic) | 完整浏览器记谱应用，实时编辑、采样播放、MIDI/MusicXML 导入导出及 library mode；当前 npm 带 Vue 等依赖 | MIT | 优先试用现成五线谱编辑能力；需验证嵌入、功能裁剪、数据改动事件与内核映射成本 |
| [alphaTab](https://alphatab.net/docs/introduction) | 交互谱面、MusicXML 等输入、内置合成播放及跟随光标；官方说明是 SDK，工具栏和应用交互由上层装配 | MPL-2.0 | 显示和随谱播放的另一候选，不把 SDK 等同完整现成编辑器 |
| [wavesurfer.js](https://wavesurfer.xyz/) | 音频波形、区域和播放交互；不是五线谱或音频转谱工具 | BSD-3-Clause | 对照试听、选择音频区间 |
| [Tone.js](https://tonejs.github.io/) | 浏览器音频合成与调度；不是谱面编辑器 | MIT | 独立短例子预览或节拍器；不是必须替换 Vit 音频内核 |

资料和 npm 元数据核对仅确认公开能力/许可；发布时需固定实际包版本，并核对字体、音色样本等附带资源。此次未开展安装、打包或渲染试验。

## 5. 四个用户需求分别怎样做

### 5.1 Tap 速度与节拍面板

建议自行实现，体量相对小。支持大按钮/键盘敲击，本地高精度时间戳、间隔记录、异常间隔处理、BPM 估计、拍击稳定程度显示、重拍标记或拍号选择，并一次确认应用到工程。

不要把每次敲击发给 LLM 计算；本地完成时序计算，结束后回传 taps、所选拍单位、拍号、估计 BPM 和用户是否应用。节拍声若在浏览器发出，用音频时钟调度，不能靠网络往返保证节奏。

仅有均匀敲击不能可靠区分 3/4、4/4 或半速/倍速；BPM 必须说明所计单位，拍号由题目给定、用户选择或额外标记重拍。敲击稳定程度只描述该次输入，不直接认定音乐表现好坏。

### 5.2 显示并播放五线谱

短单旋律可用 abcjs；教材已有 MusicXML 时可用 OSMD。显示播放游标需建立音符/小节与工程拍坐标的映射。优先让当前工程使用 Vit 内核播放，网页显示相应进度，避免两套时钟同时发声。

与工程无关的短谱例可用浏览器合成器预览，明确其为谱例试听；网页音色与当前工程插件音色不等价。音色、字体及谱例文件本地打包，展演不依赖临时 CDN 下载。

### 5.3 在五线谱上编辑 MIDI

可做，是本批控件中主要工作量。先验证 Smoosic library mode 是否能够裁剪成所需编辑器并获得可靠编辑事件；若适配成本高，再用 abcjs/VexFlow 实现限定编辑：单声部、固定拍号/调号、两/四/八小节、选音/改音高/改时值/休止符/删除/试听/提交。

不要从零绘制完整记谱排版引擎，也不要求先完成多声部总谱、自由连音和印刷出版功能。但须明确首课需要的附点、切分、休止、跨拍/跨小节延音等范围，不将会用到的符号悄悄排除。

工程音符/拍位置是保存与判定依据；谱面另需调号、音名拼写、时值、休止、连线/跨小节拆分等记谱信息。单靠 MIDI 的音高和时刻不足以唯一还原正确记谱。首课材料须核实转写，用户作品在明确的节奏网格下记谱。

学生编辑 → 向内核提交真实修改 → 内核回读 → 更新谱面及作业记录。不能只让网页保存一份 ABC/MusicXML，而 DAW 音符仍是旧版。保留 note/clip/region ID 与工程修订对应；第三方编辑器产生新 ID 时需要映射。

abcjs 官方 [Selecting and Dragging](https://docs.abcjs.net/visual/dragging.html) 明确拖动只改变视觉，应用应在回调中更新 ABC 并重绘；其 [Interactive Editor](https://docs.abcjs.net/interactive/interactive-editor.html) 主要提供 ABC 文本到谱面的联动。这些能力可以复用，但不等同即装即用的图形 MIDI 编辑器。

### 5.4 音频与五线谱一起播放

已有谱面 + 对应录音：可以做同步播放器，按预先校准的时间/拍位置显示跟随光标，wav/波形和谱面各有组件可用。

任意音频 → 自动生成正确五线谱：属于转写与记谱问题，不包含在这些控件的显示/播放能力中。首课使用已核对的谱例与对应音频/MIDI，不以通用自动转谱为前置。

## 6. 与乐局 YAML / 模型的关系

控件是可以复用的能力；乐局节点声明本环节需要哪个控件、材料和任务，模型可以在当前目标下调用它。组件本地交互不会每一步都触发模型请求；结果或明确问题回流后再进入对话。

拟议调用信息：组件类型、实例 ID、level/node ID、材料或工程 clip/region 引用、只读/编辑用途、初值及约束。结果事件携相同身份与工程修订：tap 完成、选中谱段、学生编辑提交、试听/检查请求等。字段暂是接口设计建议，尚未加入运行卡支持。

模型得到的是“用户 tap 得到多少 BPM”“学生改了哪一段”的实际结果，无需靠截图猜控件状态。组件状态需随消息/节点恢复，重开窗口不丢当前草稿；作答来源记录仍受[展演版范围](2026-11-11-legame-demo-scope.md)限制，不在这里重新开启完整安全隔离。

## 7. 建议的展演优先级

1. 共用音乐控件挂载/事件回流，加 tap 面板或播放谱例验证真实闭环。
2. 可播放且可定位片段的谱例视图，服务讲解和比较。
3. 首课限定范围的五线谱编辑，先小规模比较现成编辑器与轻量自建的集成成本。
4. 按课例确实需要再加波形、A/B、旋律线叠加。无需为“像某网页产品”先引入全部通用 UI 框架。

上述优先级仅表示实现先后，不是删减范围或全局任务排期。用户已明确三类控件必需，课程设计中分别安排实际用途；后续冻结具体符号/编辑范围与材料，其他组件再按价值追加。

## 8. Token 开销与实现方式

组件代码、字体、音色、谱面绘制与本地动画不需要交给模型生成，也不因为画面复杂而直接消耗 token。模型只需知道当前可用组件的简短定义、以少量参数打开或更新实例，再在需要回应时接收结果。

三种方式的区别：

| 方式 | 模型需要输出什么 | 对本课的判断 |
|---|---|---|
| 每次生成完整 HTML/JS | 页面代码、交互逻辑与数据 | 重复生成开销大，不作为必需控件的默认方式 |
| 用基础组件自由拼界面 | 相应布局/组件树/属性；实际大小取决于设计 | 用户已确认采用；A2UI 可支持，按实际任务组合 |
| 调用预注册音乐组件 | 类型、实例/材料/工程引用和少量选项 | 用户已确认采用，与基础组件组合共存 |

示意而非现有 API：`show_music_widget({type:"score_editor", clip_ref:"clip_12", bars:[1,8]})`。服务/前端按引用取得谱面数据；模型不重复输出整个编辑器、音乐 XML、字体或 MIDI 文件。

- Tap 连点、选音、拖音、播放游标与本地校验不触发逐次模型调用；用户完成/提出问题时才回传摘要进入模型轮次。
- Tap 返回 BPM、拍单位、拍号选择、稳定程度等；谱面编辑返回 clip/修订/选段/改动摘要。模型要讲具体音符时，按需读相关小节，不能以省 token 为由隐藏教学必需证据。
- 音频、MIDI、MusicXML 使用材料引用，不把完整二进制/base64 塞进模型上下文；图形绘制在前端完成。
- token 仍包括当前组件目录/工具定义、调用参数、进入模型的结果和相关历史。大型目录和每轮全量状态重传会增加输入开销；只披露本阶段相关组件、按实例增量更新、历史保留摘要可控制它。
- 页面事件、网络请求或服务计算若没有实际触发模型推理，本身不消耗模型 token。原始交互记录照常留存，不必在每次请求中全量重发。

因此用户提出的“组件写好、模型只调用”适合低开销交互；通常可以用短调用和结果代替多轮文字操作指导，但是否整体少于纯语言输出须按同一教学任务实测输入/输出和调用次数。当前未测量具体 token 数或承诺比例。
