## 1. 这一段让学生完成什么

把“这是我写的音符”连续地变成“这是我听得到的作品”：

谱面写节奏（旋律轨 clip 以固定占位音高即时试听；2026-11-12 更正：节奏稿与旋律稿是旋律轨上的同一个 clip）→ 同一 clip 给节奏赋音高/编辑旋律 → 旋律轨音源试听（鼓轨为 agent 依拍号/速度补充的辅助律动，非答题轨）→ 选择当前稿与编曲方向 → YuE2 生成纯器乐成品 → 改提示词形成第二版 → A/B 比较并命名保留。

生成是学生创作之后的作品发展环节，不替代前面的练习与学习检查。报表保留学生的节奏、旋律、编辑记录与由模型补充的和声/配器/结构。

## 2. 同一谱面，三个明确的音乐阶段

### 2.1 节奏稿现场出声

- 学生在 `music_score` 的节奏模式写时值、附点、休止等。
- 选择试听/保存时，将音乐事件真实写入本题旋律轨 clip。首次使用建立 clip，后续按稳定 ID 更新，不每次追加一份重复 MIDI。
- 节奏阶段在旋律轨上以固定占位音高发声；agent 可依工程拍号/速度补充鼓轨作为可选辅助律动（可用按拍号分类的模板库），鼓轨不是答题轨、报表记为辅助内容。
- 谱面的固定显示音高是节奏记谱约定，不把它当作学生已经写过的旋律；"未赋音高"可由全部音符仍在占位音高推导。
- 敲击/拖动/播放不经逐次 LLM；内核执行与回读更新保存状态。

### 2.2 旋律稿现场出声

- 保留节奏稿关键版本，在同一音乐事件（同一旋律轨 clip）上赋音高或继续编辑；版本快照/差分由共用契约机制保留（归 W02）。
- 初版加载一项已核实的清晰旋律音源，例如钢琴；具体插件 ID/预设由材料与实现准备确定，不能凭空假设已安装音源。
- 五线谱显示、内核音符、播放位置保持同版本对应；支持独奏节奏、独奏旋律及需要时合听。作品仍可继续改。
- 节奏稿与最终旋律的节奏若有改变，应显式记录是哪一版，不强行把两个不同节奏叠播。

### 2.3 按谱生成完整编曲

- 学生选定一个已保存的节奏/旋律版本，生成前固定其快照；原答题轨保留。
- 用已验证的 YuE2 谱面条件路径输入，生成纯器乐编曲，主旋律以学生所写为条件。
- 短旋律作为主题时，成曲需要的重复、展开、和声、伴奏、前奏/尾奏由编曲方案补充，并记录为辅助创作。学生给定片段与新增部分可区分。
- “保留学生给定片段”和“允许它如何展开成曲”是不同参数。首版默认保持给定片段，若要改写原旋律需要明确选择；不能以生成全曲为由先让 LLM自由重写学生原稿。
- 若仅有节奏稿，后续旋律属于模型补充，不报告为学生自己写出的旋律；本轮主收尾以学生已完成旋律为基础。

## 3. 工程布局

| 角色 | 内容 | 保存语义 |
|---|---|---|
| 参考/示范轨 | 教材片段或课堂示范，按课例需要配置 | 保留来源与材料版本；当前未声称内核强只读 |
| 旋律答题轨（节奏阶段） | 学生节奏稿＝旋律轨 clip 的占位音高阶段 | 原稿与关键修改版本可回指 |
| 旋律答题轨（旋律阶段） | 同一 clip 赋音高后的学生旋律 MIDI，旋律音源 | 保存后可直接听；与节奏稿同源 |
| 辅助律动鼓轨 | agent 依拍号/速度补充的律动（可选，模板库） | 报表记为辅助内容，非答题轨 |
| 成曲结果轨/版本集合 | YuE2 输出的完整音频 A、B… | 作为新音频/候选版本进入，不覆盖原 MIDI；采用某版时单独操作 |

本地音源试听与 YuE2 成曲各有用途：前者给编辑即时反馈，后者完成整曲呈现。先不要求模型生成物拆成鼓/旋律 stems，现有生成输出按整首音频接收。

## 4. 界面使用现有控件规划组合

谱面工作台内完成节奏/旋律编辑、音源选择、独奏试听和提交。生成环节由基础控件组成交互卡，不必再造独立生成 UI 引擎：

- 当前谱稿/版本，学生主旋律说明。
- 编曲风格与提示词文本，可用少量选项辅助填写；学生能看见并修改实际生效条件。
- 纯器乐标志、主旋律条件、适用的时长/结构设置。
- 生成按钮、真实准备/排队/生成/完成/失败状态。等待时保留谱面和试听，不能假报百分比或冻结全部窗口。
- 完成后出现轻量音频播放器；修改提示词创建新 job，旧版保留。
- 用新的双播放器 A/B 组合比较，听/偏好/采用分别处理。不同生成版本的长度或速度不一定相同，首次比较从各片段开头开始，只有有真实映射时才做同小节同步。

示例风格方向可先选“清晰钢琴＋温暖原声编配”和“活泼电子编配”，两版均沿用同一学生谱稿；最终风格由学生决定，不写死成标准答案。

配套 YAML 暂按展演展示两版的顺序路径组织；通用产品中的第二版生成可选，是否生成更多由用户决定。不将所有学生都生成两版当作学习达成条件；后续整课格式需要明确可选创作支路与收局条件再落运行卡。

## 5. 已有接入与真正需补的链路

本轮只读核对：

- `agent/internal/genapi/genapi.go`：已有 `GenerationRequest.ABC/StyleTags/Lyrics/DurationSeconds` 和生成结果工件；`yue_local` 说明明确以谱为输入。
- `agent/internal/genapi/dialects.go`：已有 `/synth` 提交、job 轮询、multipart 音频＋replay 取回；`yueRequestBuilder` 将 `abc`、`style`、`lyrics`、`duration` 映射给本地引擎。
- `agent/internal/harness/gen_generate.go`：`gen.generate` 接收 `abc`，可沿既有生成资产 ingest 写入结果轨/候选 takes，replay 留作工件。
- `agent/internal/harness/gen_generate_context.go`：当前 harness 入口要求非空用户 prompt；YuE2 builder 的实际风格字段是 `StyleTags→style`。用户改提示词时应显式编译成有效风格/结构请求，不能只改没有映射到引擎的自由文字就声称已生效。
- 既往 `YUE2-ABC-ADHERENCE-1` 工件与 `GEN-RECON-1` 记录支持已验证的特定方言路径；用户本轮明确进一步手测体验为按谱准确。本稿不把历史轮廓相关指标等同每次生成逐音测量。

需补：谱面/实际 MIDI→已验证 YuE2 方言、可用音源自动装载与映射、生成卡与后台 job 状态、学生谱稿/提示词/输出版本关联，以及当前课例的整链验证。不新起另一套 YuE2 网关。

### 5.1 转换不能由 LLM 自由转述

前端记谱可以使用 ABC/MusicXML，当前 YuE2 已验证入口是专用 ABC 方言，两者不自动等价。转换以实际工程快照为源，程序保持学生音符、时值、休止、拍号及坐标；根据既有验证请求补齐所需声部、和弦与段落结构。原稿部分可做符号往返比对，确保不是转换先改错。

纯器乐声部安排沿已有实测路径设计，具体声部映射在集成时用已验证请求对照核实。鼓轨真实节奏若要成为独立生成条件，必须明确该方言能够表达的打击乐/节奏路径；不能把“音色叫 drums”的文字当作已传入学生的全部鼓点。当前稿以学生旋律声部为条件主体（节奏稿与旋律稿同 clip，节奏事实包含在旋律声部内）；辅助律动鼓轨是否进入条件谱待定——不把"音色叫 drums"的文字当作已传入学生鼓点，条件缺口应明示并核对，不默默丢弃。

### 5.2 保留生成版本所需数据

每次生成至少关联：学生谱稿与工程修订、节奏/旋律片段、实际送出的方言谱、用户提示词、实际引擎字段、辅助和声/展开方案、provider/模型版本、可用的 seed/replay、job ID、输出文件和采用结果。

保持谱稿改风格与保持风格改谱稿，是两种可比较的操作。相同提示词重复生成也可新建候选，不能覆盖旧文件；修改源谱不会使旧成曲变成新谱的生成结果。

## 6. 展演范围更新

本轮用户明确将 YuE2 放入实际乐局收尾，覆盖此前“仅局外成品/生成产品化整体后置”的本次展演限制；不据此要求通用生成线所有功能同时完成。

最低产品体验：用户仍从 Godot 进入，选择谱稿并生成，看到状态和结果，不要求用户额外开终端、手设 env 或启动外部服务。应实现/复用最小引擎就绪与错误提示，不把手工操作留作学生前置。

若生成失败，保留学生谱面和内核试听/渲染功能，允许明确重试；不把普通音源渲染或预先生成的录音冒充本次 YuE2 输出。课堂学习检查与成曲生成状态分别记录，模型服务失败不抹掉学生已完成作品。

## 7. 下一轮只需讨论的内容
