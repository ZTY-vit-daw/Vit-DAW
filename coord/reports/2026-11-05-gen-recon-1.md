## ① YuE2 能力面

### 1.1 部署形态与调用方式（工件证据）

- 引擎=yue-server.exe（yue2.cpp c8516db，社区 MIT 实现，YuE2-Studio v3.6.0 portable）+ YuE2-3B-Q8_0 + Vae-F32 + SheetSage2-Q8_0（转谱器）+ tokenizer-v4，已部署 E:\AI\YuE2\；启停脚本 start/stop_engine.ps1（`--max-seq 24576` 模型满上下文）。（[YUE2-PC-DEPLOY-1 results.md](../runs/YUE2-PC-DEPLOY-1/run1_20261019_201652/results.md)）
- 调用=REST：`POST /synth`（UTF-8 JSON，中文歌词必须走 body 不能命令行内联）→ 返回十六进制 job id → 轮询 `/job?id=` → `GET /job?id=&result=1`（multipart=JSON replay + audio/wav）；另有 `/health /props /logs /transcribe /tokenize`。无鉴权、绑 127.0.0.1:8087 不暴露局域网。（同上 + [参数面报告 §2.4](2026-10-22-yue2-prompt-parameter-surface.md)）

### 1.2 输出形态：整首混音单文件；**声部级可分=本次探测实证可行；双轨分轨输出不存在**

- **固定输出=单文件整首立体声混音**（pcm_s16le/48kHz/2ch，wav16/24/32 或 mp3）。引擎二进制字符串与 `/props` 均无 stems/双轨/instrumental 模式开关（本次二进制 grep：无 `instrumental/stems/karaoke/accompaniment` 模式字段；唯一 vocal 相关串=方言示例 `V: Vocal` 声部声明）。"Mode"=cot 档位（full/melody/off），非人声/器乐模式。
- **仅人声模式存在且可行（本次探测 P1 腿实证）**：请求面写法=ABC 方言谱 Vocal 声部保留旋律、Ins 声部全多小节休止（Z），style 用 `a cappella, Mandarin female vocal…`（去掉一切乐器标签）。引擎接受渲染（21s 墙钟出 55.68s 成品），**SheetSage2 转谱回读 Ins=全休止**（转谱器在音频中听不到可转写的器乐声部）；replay 回显 Ins 声部原样接收（Z2/Z4）。
- **纯器乐对照（P2 腿）闭环验证机制**：Vocal 全休止+Ins 保留+`instrumental, solo acoustic piano` style → 转谱回读 Vocal=全休止、Ins 有实际音符（低音声部）。两腿互证：**声部休止→输出端该声部不发声的控制在方言谱层面成立**（与用户已知"乐器独奏可行"互洽，并补上了"仅人声"缺口）。
- **限制（如实）**：转谱回读是弱证据（SheetSage2 无器乐可转写≈无显著伴奏，非人耳终判）；"人声轨+伴奏轨两份文件"不能由一次生成获得——两次生成（P1 式+P2 式）谱面层同源但**声学层不同源**（同 lm_seed 声学渲染不同），不能当采样级对齐分轨用；真分轨走分离工具（见 ④）。

### 1.3 ABC 引导边界（ADHERENCE 结论复述，[YUE2-ABC-ADHERENCE-1 results.md](../runs/YUE2-ABC-ADHERENCE-1/run1_20261019_215818/results.md)）

- **硬控制（可承诺）**：调性精确匹配 15/15=100%；和弦根音均值 0.98；旋律轮廓相关中位 0.99（**方言内**）；拍号跟随。
- **软控制（倾向项）**：速度剂量响应约 19–21%（Q:132→实得 ~111；style 文本 BPM 更软且可压过谱面标记）；duration=上限非保证（模型自行收尾，实测最长 127.7s@请求 360s）。
- **方言是门票**：朴素 ABC（单声部无和弦标注）调性保得住、旋律崩（corr 0.16–0.20）；必须双声部+小节内引号和弦+`% 段落注释`。
- 跨 seed 谱面一致 0.77–1.00（谱面由 lm_seed 主导）；输入谱 29/29 逐字进 replay（引擎如实接收外部谱）。

### 1.4 时长/延迟/显存/批量

- 延迟：60s 歌 21–40s 墙钟（≈0.55×实时；谱越短越快，本次 P1/P2 各 21s 出 ~56s 成品）；replay 重放 12s。360s 请求 49s 墙钟（127.7s 成品）。
- 显存：峰值 ≤6.3GB（含桌面基线），引擎自身 ≈3.4GB；任务间自动卸载回落 ~1.4GB（--keep-loaded 才常驻）——与 Godot 开发/展演前台共存无压力。
- 批量：`--max-batch=1`（本机单首串行）；`synth_batch_size` 1–9（同谱同码声学变体，只花 VAE/flow 段）；style+lyrics ≤65536 字节。

### 1.5 乐谱调整→稳定统一重生成（展演安全资格）

- **谱面层成立**：改 abc → replay 回显原样接收 + 输出谱面服从 corr 0.99 级（①.3）→「按谱统一重生成」有实证。
- **声学层确定性=replay 链路**：semantic_tokens 重放逐字节确定（smoke5a==b），同 lm_seed 重跑不逐字节确定。**展演安全形态=每次生成保存 replay JSON，成品可逐字节复现；改谱后重生成=新 replay 新基线**。
- 结论：用户定位的资格（乐谱调整→统一性稳定重生成）**在谱面层+replay 层成立**，声学层重跑不逐字节一致是已知边界（对展演演示无碍：演示的是"改谱→出新版本"，不是"重跑同谱逐字节一致"）。

> **①最小可用接入路径**：genapi 新增 `yue-local` dialect（base_url=http://127.0.0.1:8087，无 key），GenerationRequest→`/synth` JSON 的字段映射在 DEPLOY/ADHERENCE 工件里有全套已验证请求样例可抄，结果走既有 GeneratedAssetService ingest 落 timeline。

### 3.2 genapi 体系=生成接入的既有主干（GEN-API-ADAPTER 留存，不追改但直接复用）

`agent/internal/genapi/genapi.go`：ProviderConfig（provider dialect/base_url/api_key/model，secrets 不回显）+ GenerationRequest（provider 无关归一输入，不支持字段报 limitation 不静默丢）+ Generate 统一管线（submit/parse/poll/download/错误分类）+ **已有 sunoRequestBuilder**（`dialects.go:145`）+ 产物落 GeneratedAssetService ingest 路径（assets.register_job + assets.ingest_generated_asset，注释明示不新开 kernel 面）。决策 §三"后续生成集成按 MCP 方向另立卡"+参数面报告 §4.5"套壳=genapi 语义上层"与此一致。

### 3.3 MCP 套壳挂接形态（建议）

**MCP 作为 genapi 的一种 dialect/transport**，不是 browser_fetch 式独立工具包：Generate 管线（归一化请求/轮询/错误分类/ingest）原样复用，仅 submit/poll 的 HTTP call 层换 MCP client RPC（stdio JSON-RPC 子进程）；工具面（generate/stems）映射为 dialect 能力声明进 Limitations() 既有机制。治理面照抄 browser_fetch 先例（catalog spec+policy allowlist+artifact 捕获）。这样 YuE2（HTTP dialect）与 Suno（MCP dialect）在 harness 看是同一个既有生成工具的两个 provider。

### 3.4 YuE2 直跑 vs MCP 化 + 通用性评估

- **YuE2=本地直跑**：已是 localhost REST API，genapi dialect 直连是最短路径；MCP 化是给纯 HTTP 服务加一层无收益的间接层（还引入 node/python 子进程依赖）。
- **一句话评估**：MCP 作为外部能力通用接入模式**可行且值得保留为一个 dialect 选项，但不是默认**——它的真实价值是接入"只给 MCP 面/无稳定 API"的外部服务（Suno relay 正是此形态：stdio 免网络暴露、工具 schema 自描述、生态现成），对已有 HTTP API 的服务（YuE2）是冗余；Vit 侧以 genapi dialect 体系为主干即可同时吃下两类，不需要为 MCP 改造既有治理结构。

### 5.1 候选接入点（建议非定案）=乐局终局导出：符号域一条龙

- **失败兜底=直接用工程内渲染音频**：YuE2 超时/引擎未起/渲染失败→回落 VitApp 内核工程内渲染导出（链路已存在），演示不中断；兜底触发与原因在回执可见（genapi 错误分类既有机制）。
