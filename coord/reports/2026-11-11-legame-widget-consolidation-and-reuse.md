## 1. 收敛后的产品形态

| 对外组件/模式 | 包含什么 | 实现策略 |
|---|---|---|
| 轻量音频播放器 | 文件名/播放图标、暂停、进度、时长，按需展开 | 播放器为 UI＋内核后端适配（音频文件经内核预览平面播放，2026-11-12 更正）；无需为了单纯试听强制显示五线谱 |
| 谱面工作台 | 同一谱面里的节奏稿、旋律编辑、只读看谱、跟随播放、循环慢放、选段提问、旋律线叠加、版本比较 | 新增主工作区，复用谱库/现有内核 MIDI 与 transport；按功能模式复用同一份数据，不分别做多个编辑器 |
| Tap/节拍面板 | 敲击、单位/拍号、重拍、速度估计和节拍试听 | 独立可调用，也可嵌到谱面工具条；共享工程速度语义 |
| A/B 对比组件 | 两个通用播放器实例加共享比较控制；可在音频或谱面工作台调用 | 拆出现有整体卡中的播放/比较/判定/采用，前端用组合组件替代；底层音频准备与试听能力按需复用 |

这是三个主要组件加一个共享比较模式。模型仍可把它们与基础文字、选择、输入、按钮/布局一起组合；合并产品形态不意味着将实现写成一个不可拆分的大组件。

## 2. 同一谱面完成节奏到旋律

按用户确定的教学路径：

1. `rhythm`：选时值、附点、休止/连线，先写节奏型；用固定参考音高或单线节奏记谱显示，不要求此时先构思旋律音高。
2. 试听节奏并保存关键版本；时值/休止和小节坐标可检查。
3. `melody`：在同一组音乐事件上赋予/修改音高，原节奏保留；需要调整节奏时仍能操作，记录具体变化。
4. `read` 或 `edit`：同一谱面只读展示/继续创作；随谱播放是它的播放能力，不再另造一个谱面播放器产品。
5. 按需要叠加旋律线或打开对比模式，回看节奏稿、旋律稿和修改稿。

节奏事件到旋律事件保持稳定身份和时长关系；节奏阶段为试听添加的参考音高应有明确语义，不自动当作学生已选择的旋律。谱面 draft 的赋音高状态、实际 MIDI 音高和版本映射需在编辑器数据设计中明确。

**本课不另开发节奏格。** 若后续用户提出初学节拍可视化/鼓机/多轨节奏需求，可增加同一数据的可选辅助视图；不建立第二份独立节奏作业。旋律线也是谱面的叠加/辅助视图，不作为独立数据编辑器。

### 3.1 “现有 A/B 可用”的证据边界

本轮已读当前源码和已验收卡：`coord/cards/done/2026-10-22-UX-AB-AUDITION-IMPL-1.md`、`2026-10-23-UX-AB-AUDITION-COVERAGE-1.md`。卡面分别记录动态链/拓扑链挂载、双候选渲染、事件/身份路由和 PASS/主管验收；coverage 卡记录过用户实际点选试听。剩余其他路径的自动挂载覆盖仍有待命卡。

所以有现有实现和既往运行/验收依据，可以从已有 A/B 开始复用；本轮未重新启栈，也未验证“任意课堂 MIDI 两版本”已可直接使用。既往通过的混音 A/B 不等于课堂适配已经完成。

### 3.2 教学比较的行为

- 点击 A/B 试听只切候选，不能更改学生作品。
- 选择“更喜欢 A”只记录偏好；是否采用版本、复制成新尝试另有明确动作。
- 结果可为 A/B/都不喜欢/不确定，允许附解释。这里没有默认“A=回滚、B=保留”语义。
- 可比较不同节奏/旋律的同一任务范围；两版本的节奏/长度不同则各自绑定坐标，不能强行套同一个音符时间轴。
- 音乐数据实时改动后，旧 preview 对应旧版本；要重新准备或明确继续听旧版，不能播旧音频却显示新版谱面。

### 3.3 A/B = 两个通用播放器 + 比较控制

该逻辑成立。`AudioPlayer` 独立时是一个文件/预览播放器；`ABPlayer` 使用两个 `AudioPlayer` 实例（A 与 B）并连接 `CompareController`。这三个名字是设计标识，并非现有 API。

比较控制负责：

- 播放互斥：默认同一时刻只响一版，切到 B 时停止/暂停 A，恢复同一逻辑位置或按所选规则从头播放。
- 位置规则：混音前后同源比较可以同时间位置切换；长度/节奏不同的课堂旋律可从各自片段开头播放，或用各自小节映射。同步方式明确选择，不强制同长度。
- 比较设置：共享选区/循环、约定的播放速度和音量控制；特殊响度匹配另作显式能力，不默认用归一化抹去学生要比较的力度差别。
- 结果回流：试听选择、偏好/理由、采用版本分别产生事件。比较组件不自行决定参数回滚或修改工程。

两个播放器是两份呈现实例与资源状态，不要求同时跑两套合成器。播放服务可用统一活动通道或已有内核预览平面；各实例通过适配器引用自己的音频/版本。对当前工程前后两版，仍需已有的快照/渲染或合法预览准备，不能给同一可变工程贴两个标签就当成两份声音。

混音调用方收到结果后按原任务契约处理保留/回滚；教学调用方记录比较与解释，明确采用时再写作品。由此可以替换旧的整体 A/B 界面，而不把每种用途的行为硬编码进播放器。

前端可共用小播放器、播放状态、按钮/进度和比较控制；旧 `AuditionJudgeCard` 的业务裁决部分留在混音适配层。迁移顺序为通用播放器 → 双播放器比较 → 旧混音接入 → 教学接入 → 回归验收后退役重复 UI；不先删除可用链路再补新功能。

## 4. 统一资源接口，保留不同的播放后端

统一的是材料身份、播放控制表现与事件回流，不强行把现有所有播放改成同一个底层引擎：

- 音频文件 → 内核预览平面播放（2026-11-12 更正：音频全部走内核；原资料面板 `<audio>` 预览保留在非乐局场景，不改动其现有行为）。
- 当前工程 MIDI/音频 → 内核活跃工程 transport。
- A/B 候选 → 内核独立 audition preview plane。

上层通过统一适配接口请求播放/停止/定位，获取位置/状态；不支持的操作如特定 preview 的慢放或暂停应显式披露、单独核查，不因 UI 有按钮就假定后端已支持。

本轮源码/测试说明 audition 平面与工程 transport 解耦，因此不应让它误用工程播放时间做光标。各后端分别报告真实时钟与材料版本，上层管理同时发声的互斥/切换，避免双重播放。

拟议统一的资源引用至少携带：source kind、resource/clip/版本、scope/range、音乐坐标或音频时间映射。显示同一资源时可选择 compact audio、score、compare 等呈现，而非重复复制文件和记录。

## 5. 有边界的资源整理

先盘点并提取可复用的音频播放器、试听控制、资源引用与选择结果接口，旧调用者通过适配继续工作；新谱面工作台接共同资源层。当前不借本课实施 App.tsx 全面拆分、混音控制器改写或全量资源迁移。

必要验证包括：资料音频仍可播放；混音 A/B 原来的判定/回滚语义保持；课堂 A/B 选择不触发回滚；谱面编辑与内核一致；播放当前材料与版本正确；普通对话组合这些控件能够完成真实课程旅程。

这些是下一阶段实现卡的划分依据，不代表本轮已开始整理生产代码或已验收可用。
