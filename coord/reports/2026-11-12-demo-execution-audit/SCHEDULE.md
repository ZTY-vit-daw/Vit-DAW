# 11月19日首版、11月30日展演版本：编排建议

## 1. 两个目标分别验什么

### M1：11月19日可手测首版（冲刺目标）

从Godot正常启动 → 在启动页讨论/查看/修改并导入一份实际设计 → 创建正确的乐局工程 → 模型每轮按该设计引导 → 用户在五线谱先写节奏、用Tap选择速度并听鼓轨 → 赋音高后听旋律轨/随谱播放 → “写好了”读真实工程、反馈、修改/推进 → 选定源谱交YuE2纯器乐成曲 → 改有效风格产生第二版 → 双播放器A/B → 保存作品、关键检查和过程索引。

这个首版包含用户确认的三类必需音乐功能和真实生成，限定为本课单声部/首批材料/主要正常路径。材料库22项可先完成主旅程直接需要的片段；未完成的教材部分不伪装已教、未转写材料不显示为可播放。四形态、全部发展方法及完整多题报表属于M2补齐范围；这是一版可体验主链，不宣称完整课程验收。

交付用户之前：技术侧先通过对应的真实栈、渲染/宿主和用户旅程检查，确认没有首次点击就卡住、静音、错工程或假保存，再安排一次完整手测。**不以用户替开发找第一轮功能错误。**

### M2：11月30日前展演所需版本

- 教材知识与三项实践全部可组织，八任务按源文档工作；按任务量推进、可问/重试/保存恢复。
- 22项原谱材料全部完成所选短段的转写、记谱/音频关联、听核和按ID加载；不是22首完整歌曲。
- 四条两小节、原型/变体、八小节主题及生成版本都能保存和核对，恢复后引用正确。
- 两份报告覆盖实际完成内容，帮助/模型示范/待复核可回溯，生成失败不抹掉学生已完成作品。
- 旧混音A/B、资料播放器、普通工程和启动链按受影响范围回归。
- 固定版本和环境，通过技术验收及用户完整体验，产物/录像/截图/报告具备5分钟展演素材。

完整教学安全体系、通用多声部印刷记谱软件、全量生成平台/插件GUI、通用自动识谱和班级后台不进入这两里程碑。内嵌加密规则若不能按窗口实现，可采用先前讨论允许的可携带工程目录；这不免除实际绑定/恢复正确性。

## 2. 三条主要执行线

| 执行线 | 主职责 | 先行/依赖 |
|---|---|---|
| A 界面与谱面 | 组合组件、谱库去风险、music_score、通用播放器/AB、Tap及宿主适配 | 立即做谱库实际往返；按共同音乐数据契约联调 |
| B 文档与教学运行时 | 源格式、包/草稿、每轮上下文、材料加载、作业绑定/检查、启动入口、报表 | 文档schema和事件/引用契约先冻结；与341前端域错峰 |
| C 音频与生成 | 计量、健康音源模板、学生谱→YuE2方言、最小引擎托管、job/落轨/版本 | 用fixture先开发，不等完整UI；早期验证鼓/旋律出声和条件转换 |

教材转写/校对作为独立域任务穿插到空闲执行槽，或在某线等待共用接口/栈时推进。若决策流具备更多独立执行槽，可另开材料流；**不能以多开会话突破共享文件/栈的约束**。在当前Codex 4槽运行环境下，父决策流加3个执行子代理已满，不再额外常驻第四执行子代理。

每天决策流恢复卡池状态→确认最新合入基线→派可执行且文件域独立的小卡→审查回执/测试/差异→串行合入和排真栈→继续派后续授权卡。用户只在M1/M2或修复后形成的新完整里程碑参与手测。

## 4. 三个最早的去风险关口 G0（11/13）

1. **谱面编辑可往返**：选定库实际改一音/时值/休止，映射到fixture或真实内核并回读重绘；证明后续能覆盖附点/延音与计量。真实出声串音源腿验证，不仅展示SVG。
2. **课程音源可用**：固定鼓/打击与旋律预设，正常工程打开→学生式MIDI编辑→声音变化→保存重开仍可用。不用Waves静音件作为首版唯一音源。
3. **学生谱能成为实际请求**：用一份真实保存的八小节输入做专用方言转换/原稿比对，确认实发style/纯器乐/源版本与job结果；鼓点条件路径给明确结论。

三个关口中任一出现架构性阻塞，立即记录事实和可行替代实现，向用户更新11/19风险。允许换谱库、换健康音源、缩小记谱语法或使用固定模板；**不得用预制学生答案、只画界面、手动外部生成或删掉用户必需控件来维持虚假的首版日期。** 范围变更交用户决定。

## 5. 关键路径与工时解释

主要关键路径：共享源/事件/音乐契约 → 谱库选择 → 谱面编辑＋写读/计量＋真实声音 → 文档驱动的教学反馈 → 源谱到真实生成/版本 → 完整旅程与宿主验收。

源格式/课堂内容、播放器/Tap、音源模板和生成任务可分别用共同fixture先行，减少串行等待。22条材料中较长/多声部例先定教学截段再转写，不能把录入工作留到最后一天。

去重估算：M1子范围111–191小时，M2总范围173–293小时（M1包含在M2中），建议约20%返工缓冲，即总208–352小时。区间是专注工程投入，不是按人类开发者或某个模型速度承诺工期。三线并行中仍存在谱面单流、共享接入口、GPU和单真实栈瓶颈；11/19是冲刺目标，不能无条件保票。月底计划需结合首版实际吞吐重估。

## 6. 合入与所有权约束

- A线可拆谱面、播放器、Tap的独立子目录；B线可拆源解析、检查、报告；C线可拆转换和生命周期。但公共App.tsx、types/api、server.go/goalrunner_chat.go、catalog/capability_pack、CommandDispatcher、dev_agent_smoke.ps1各自指定一个接线owner/批次，其他流只交接口/小patch。
- Godot `app/startup/`由341修复与新入口顺序提交，不能同时两流改；不要改既定红线`LLM_Chat_Controller/Window`来迁移整套聊天。
- 273当前owner/分支仍保留；不为本课重写其通用装载桥。若教学接线确需同文件，相邻新文件先开发、公共插点候主管协调。
- 每流独立worktree；新worktree走宿主提供的create_worktree（适用时），领取/同步按共享协议。单卡一个目标、固定文件域，默认30–60分钟/≤5文件，工作包再拆小卡，不将18包一次派成18张超大卡。
- 决策流审查与合入，不兼做已派实现。材料也有owner与校验回执；done不等于最终验收。
- 现有341要求的用户视觉复核可以按用户最新里程碑方式集中到M1；技术侧先提供截图/真实旅程证据。主管需在卡面记录这一安排，未获用户终验前不能把该项写成已PASS。

## 7. 验证与用户手测

每一变更先做有意义的局部检查；定向检查通过后进入所属集成腿。复用现有PS1/驱动体系，使用隔离工程/新run目录。真实栈单owner登记、即时复核、按被测commit构建与二进制hash、finally拆栈；不并行抢端口、不在用户工程预演。

运行前规定LLM/生成次数、成功条件、失败分类和止损；同一确定性断点两次失败先取证不原样重跑。M1一次完整成功只证明主路径可走；M2若要说稳定，另定样本量/比例，不能事后挑一条成功当稳定率。

用户手测唯一入口仍是**用户从Godot拉起前端→启动页进入目标工程**。不把dev_agent_smoke脚本当用户入口。材料、音源、引擎就绪均由交付物准备，原始日志、检查与报告应能回指。
