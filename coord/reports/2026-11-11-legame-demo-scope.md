# 教学乐局展演版：体验交付范围

- 日期：2026-11-11；Codex 辅助设计会话。
- 当前授权：[用户定向](../decisions/2026-11-11-legame-demo-experience-first.md)。
- 状态：展演范围建议，可用于主管拆实现卡；未实现、未验收，不替代全局卡池排序。

## 1. 工作量判断

完整作答隔离的压力较大：当前调用源缺可信区分、Godot 编辑桥与 agent 同进程、旧命令面可直达内核；还要覆盖导入/结构编辑/撤销/恢复、规则保护以及来源留存。完整安全不能用提示词或一个字段补齐，应作为独立开发阶段。

本轮不把未经拆卡的天数作为工期。相对体量：完整隔离/身份/恢复覆盖高；按一课设计的 YAML 装载与 LLM 当前节点引导中；复用 MIDI 工具做真实练习与反馈中、取决于课题判据；先组织现有日志的两份轻量报告中小，但完整逐音来源/防篡改高。优先拿到课程体验的可见成果。

## 2. 当前要做

| 交付面 | 展演最低行为 | 本次控制规模 |
|---|---|---|
| 设计文档 | 明确目标、材料、布局、顺序、分工、提示和完成检查；可在外部 agent 修改后导入 | 保留一种固定源格式；完整安全块不设为展演必填项 |
| 设计入口 | 在启动页发起/继续讨论、查看草稿、导入本地设计，选定后创建进入 | 复用已有对话和文件入口，暂不做完整可视化编辑器 |
| 工程绑定 | 重开后仍加载选定版本，LLM 每轮获得目标/当前任务/材料/真实工程状态 | 可先复制关联设计到本局工程工作区；内嵌加密容器单独后置，不阻塞体验 |
| 教学交互 | 讲解/示范→用户亲自写→试听/提问→反馈→修改，有可见音乐结果 | 明确参考/示范/练习区；采用引导与记录，不宣称已存在内核强隔离 |
| 音乐交互控件 | Tap 速度/节拍面板、五线谱 MIDI 编辑、音频/MIDI 随谱播放三类均必需 | 优先复用成熟音乐组件；模型短调用、前端本地交互，编辑需真实写回工程 |
| 现场音源与成曲 | 学生节奏 MIDI＋鼓/打击乐音源、旋律 MIDI＋旋律音源现场试听；YuE2 依学生谱生成纯器乐全曲，改提示词产生版本 | 复用现有生成接入，补特定谱面条件转换/最小就绪/任务状态；原 MIDI 与生成音频分别保留 |
| 课内检查 | 用户说写好了/提交后读实际工程、检查可核查条件、记录结果再推进 | 保留功能检查；签名回执、身份防伪后置。主观判断留可回溯评议/待复核 |
| 课程材料 | 经人工核实的目标单元谱例、MIDI 与说明可按定位调用 | 首次课预先准备准确素材，不要求先实现通用 PDF 识谱/课程自动编译 |
| 两份报告 | 作业报表＋关键上下文摘要，引用真实对话/工具结果/快照 | 关键版本与可观察模型参与先做；逐音全链归因、班级后台后置 |
| 验证与采集 | 开课→操作→检查→结课真实走通，再采集关键片段 | 单测不替代真实三件套、渲染/旅程检查；用户入口维持 Godot |

源格式与运行卡的映射仍须实际实现；不能把尚不支持的新 YAML 格式直接给旧加载器声称能运行。入口缺文件选择能力时作为小范围产品补齐，不把终端布位留给用户。

控件范围为用户后续明确要求，不再作为可选砍项；组件框架与 token 方案见[音乐控件选型](2026-11-11-legame-music-widgets-options.md)。A2UI 有可复用 SDK/基础组件，采用它或扩展现有 Vit 控件目录仍待集成选型，不需要让模型每次生成页面代码。

用户进一步确认同时支持基础组件动态组合与预制音乐组件调用；控件统计和输入/结果约定见[目录讨论稿](2026-11-11-legame-widget-catalog-draft.md)。新增推荐组件仍待课例范围确认，不把目录全部变成本轮强制实现项。

控件形态按[资源收敛方案](2026-11-11-legame-widget-consolidation-and-reuse.md)精简：轻量音频播放器、谱面工作台、Tap 三个主要组件；谱面内先节奏后旋律，随谱播放与旋律线共用，独立节奏格后置。现有混音 A/B 已有实现与既往验收记录，优先提取共用试听能力、适配课堂比较，不重做引擎或直接触发混音回滚。

用户确认 YuE2 在实际乐局收尾生成，首版为纯器乐完整编曲，突出学生旋律；已有验证的乐谱生成路径直接作为集成基础。具体收尾及待补链路见[按谱成曲方案](2026-11-11-legame-student-score-to-yue2-finale.md)。用户随后要求开始全课设计，本轮已形成[教材共用资料与课例第一稿](../lesson-designs/music-creation-unit2/README.md)，前半段不再仅留空；课例仍待讨论/导师核对。

## 3. 后置范围

教师/学生账户登录与发布权限、YAML 防篡改/教师签名、内核作答区所有写路径隔离、模型调用源认证/受限宿主、严格提示目录输出、可信回执跨身份防伪、完整音符来源图与审计记录保护、班级收发作业/管理后台。

生成通用平台的全部产品化仍不做前置；但本课所需 YuE2 按谱请求、实际任务状态、结果试听/落轨、版本保存和最小引擎就绪已进入本次范围，不再统一后置。

这些设计保留；本课无需同时交付。基础运行仍沿既有工程授权与文件处理规则，不因后置而主动放宽全局安全。

## 4. 模拟课怎样落入框架

1. 先冻结最小字段：音乐/学习目标、材料定位、初始布局、顺序节点、每节点分工/自由度/提示、工程检查和收局。
2. 用它填入教材第二单元：将三项编创实践分别安排为探索、发展和综合创作；具体教法仍交教学设计讨论与导师核对。
3. 每个要求选择实际可用检查；小节长度/节奏等客观约束与情绪表达评议分开。没有判定实现的地方不能假装自动评分。
4. 示范用预制准确谱例也成立；模型必须围绕真实用户回应和作品作引导。短片段生成若是课内必要体验，就作为明确小范围能力补齐，不把整套生成产品化搬进来。
5. 用一段真实交互先检验模型是否看见文档、能调用正确材料、读到学生编辑、给出可用反馈，再扩到整课。

## 5. 证据口径

可以展示：文档自定义、自动按目标引导、用户编辑、真实工具动作/检查、学习过程整理。暂不展示为既成事实：绝对禁止模型代做、教师身份隔离、来源不可篡改、自动证明学生独立掌握。

两份报告中来源证据不足的内容标“未记录/待复核”；模型在对话中先给出具体方案的原文应进入摘要，不能因未做完整归因就全部算成学生独立创作。

原始记录、报告和工程快照需要可相互定位；完整教师管理系统不作为生成这两份本地审阅材料的条件。
