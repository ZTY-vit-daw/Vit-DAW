## 1. 工程进入即生效的乐局约定

用户的 AGENTS.md 类比成立于“工程随附、自动加载、持续约束工作”的语义。建议：

1. 工程绑定确定的乐局设计修订与内容指纹；新会话、模型更换、会话恢复、普通聊天轮均由宿主确认当前 binding，不能只在首轮告知或依赖模型主动找文件。
2. 保留一份 `design.yaml`，宿主直接解析后组织模型上下文/人可读预览。取消额外 Markdown 文件建议；此前文件名仅沿用仓库 `legame` 内部命名，没有额外含义或标准地位。具体目录落点留实现设计确定。
3. 每轮稳定提供总目标、角色、有效权限和当前节点；按需提供材料、后续环节和证据。上下文压缩后从宿主状态恢复，不让聊天摘要替代约定。
4. 模型可改变表达、探索路径、提示方式；不能通过用户一句话改掉目标、判据、角色或强制节点。
5. 工程不绑定乐局时按普通工程工作；自由创作乐局可以允许模型承担大量创作。教学限制是发布者选择的策略，不把整套 Vit 永久变成练习软件。

模型所见优先级：平台与执行边界 → 已验证的发布者策略 → 当前乐局约定与节点 → 用户本轮请求。教材、音频转录、导入文件及其注释作为材料，不能给自己授予指令权。文档中的权限声明只是请求，实际权限由宿主核定。

## 2. 两件事分别处理：允许怎样协作、观察到怎样的贡献

协作策略决定模型可以怎样帮助；贡献记录描述实际发生了什么。模型参与多不自动构成违规：创作乐局可由模型主创，教学示范环节也可公开生成；只有超出该节点已发布规则才是越权。

建议每个节点选择一档，教师可按教学设计调整：

| 档位 | 模型可以做 | 模型不能代替的部分 |
|---|---|---|
| `co_create` 共创 | 提出音乐方案、生成、编辑、编配，与人共同选择 | 文档要求由人作出的审美/意图决定与最终确认 |
| `guided_practice` 指导练习 | 解释、追问、对比；在允许区域做限定示范；按教师规则执行学生已明确指定的操作 | 将本题完整可提交旋律交给学生，替学生完成保留给他的音乐决定 |
| `independent_check` 独立检查 | 操作说明、规则说明、播放、保存；提交后的反馈按节点规则披露 | 提交前给针对答案的提示、生成/改写作答内容、代答说明理由 |

独立检查只表示“在本系统已记录的帮助范围下完成”，不是对系统外行为的证明。获得针对本题的提示后仍可继续学习；该次尝试据实改记有帮助，不抹除帮助来标成独立。

## 3. 强护栏放在模型之外

### 3.1 谁可以改规则

教学局由教师发布规则，发布身份通过教师登录、教师保管的签名或课堂受管服务验证；具体部署机制须另定。学生不能靠聊天里的角色声明成为教师。教师的批准、额外帮助和策略变更都应留记录。

用户提出的“仅教师有该工程 YAML 写权”可作为首版规则编辑机制，但必须是存储或服务端真正拒绝写入：规则文件由教师身份/发布服务拥有，学生与学生所驱动的 agent 无写权；文件替换、删后重建、另存覆盖和换绑定也不能绕过。只在 GUI 中隐藏编辑入口不成立。远程主机是否可改由认证身份、授权范围和工程归属决定，不凭 IP、本机/远程标签判定。教师每次发布新版本，运行时只认选定的发布版本。

用户已明确部署前提：**教师与学生使用不同主机、不同账户**，不再把共享账户兼容作为本轮设计问题。按此分工，教师编辑/发布权威 YAML，学生及其 agent 使用选定发布版本并无权写回；源文件的实际存储权限与发布绑定落实该分工。锁住规则只保证规则不能改，模型写音符仍需下一节的执行检查。

用户提出将 YAML 纳入 `.vit` 工程加密容器，建议作为规则交付方向。术语与源码核查：SHA-256 是摘要而非加密；`VitApp/Source/Core/VitEncryptionCore.cpp` 实际调用 XChaCha20-Poly1305 加密/解密，`VitHeadlessService.cpp:1225` 起规定 `.vit` 使用 app-bound 加密保存，1336 行对工程 XML 加密。当前代码不是已有的“教师规则签名/权限”实现，YAML 入包也尚未实施。入包可防普通外部直接改明文规则，但应用打开工程后仍须禁止学生/agent 经应用修改规则段，保存时保留教师发布版本；加密不能替代该权限。

学生自建/复制的自由创作工程可以更开放，但它是另一份作品或非受验证的练习，不能带着原教学任务的完成凭据提交。退出/暂停教学是合法动作，应保存未完成状态，不以禁止离开代替教学管理。

发布包绑定任务 ID、设计版本、策略版本；学生改本地设计文件不能静默改变教师认定的版本。检测到不一致应显示待核查/暂停验证，保留作品，不直接判作弊。

### 3.2 按节点、动作和音乐区域执行准入

实际可执行权限 = 系统原有授权 ∩ 已验证的教学策略 ∩ 当前节点许可 ∩ 目标对象/区域范围。

- 请求必须解析到规范化的操作、真实目标 clip/轨道/时间范围和参数，执行前检查，写入后回读。不能靠工具显示名称或模型自报“只示范”准入。
- 独立作答区可允许学生 GUI 编辑，同时禁止模型写入。示范区可允许模型写入，但不能把示范结果自动复制为学生独立作业。
- 复制、导入、生成后导入、整段替换、跨轨移动、undo/redo、恢复旧版本、批量操作均要保留来源并受对应规则约束。把写音符改成执行脚本不能绕开限制。
- 普通聊天、其他 agent/子代理、任务委托、直接调用与 GUI/API 写面须服从同一任务策略。若某条写通道尚未纳入检查，就不能把该部署声称为完整强护栏。
- 学生的普通确认与全工程操作授权不能覆盖教师策略；教学策略外的动作应拒绝，不是弹一个学生可点的确认框就放行。

准入由可信宿主给出，不能接收 LLM/请求体自填的 `actor=teacher`、`origin=human` 或 `approved=true` 作为事实。原则上不得通过开新聊天获得更高权限：策略绑定任务实例/工程，恢复时继续生效。

**可实现的写入边界：** 可信宿主分别建立学生编辑会话与模型执行会话；在凭证/进程隔离下，每次请求携带不可由模型伪造或取得的会话凭据。内核或唯一的可信写入网关由已认证会话确定主体，再按当前策略检查真实受影响对象。凭据由调用服务持有，不出现在提示词或交给模型自由构造的参数中。主体、工程、节点、策略版本、目标范围及有效期绑定；旧凭据和跨工程重放不能扩大范围。

例如独立作答轨：学生会话可以写入，模型会话只读；示范轨：按节点允许模型写入。即使模型生成了正确的修改命令，模型会话的写请求也在实际修改之前被拒绝。移动整个 clip、删轨、导入覆盖、撤销别人的编辑等动作都按完整写集合检查，不能只拦音符新增。初次实现宜保护整条作答轨，减少 clip 移动或新建造成的范围漏洞；细粒度到片段/时间范围再扩展。

只在 Go agent 检查而保留可绕过的裸内核写口，无法作上述保证。如果选写入网关，内核只能接受经该网关认证的写入；如果选内核检查，各写入口统一认证。来源不明的写请求在教学受管任务中拒绝，不默认成前端学生操作。

**本轮源码锚点：** `CommandDispatcher.cpp:2331` 所在分发函数将 VSP envelope 与裸命令区分为不同持久化治理来源，注释也说明 Godot 在同一通道发送裸命令；Godot `kernel_command_client.gd` 与 `clip_client.gd` 调用原始 MIDI 命令；Go `kernel/client.go` 也能发送原始命令。`client_id/role` 字符串或 envelope 有无不能据此视作防伪身份。本轮未做全链安全审计/运行测试，现状不足以声称模型已无法写作答区。

#### 3.2.1 以作答区隔离为核心，复用学生现有编辑方式

用户本轮收敛方向合理：**必需的是受保护作答空间，不是专用答题编辑 API。** 学生可以继续使用现有钢琴卷帘/录入功能；这些写入在内核获得允许，agent 的任何写路径对同一对象都被拒绝。此前拟议 `education.answer.edit` 不再作为必须开发项，其名称也不是已存在接口。

- 作答区使用内核持有的受保护对象身份（初版建议整轨），不依赖轨名或 LLM 自报的“这不是答案”。
- 所有实际写入统一检查受影响对象及调用能力；旧的音符新增/修改/导入、clip 移动、删轨、工程替换不能绕过。未纳管写路径不能发布强隔离保证。
- 不要求增加每次作答登录或确认的体验。运行时仍须通过受控连接、进程能力或会话凭据，可靠区分学生编辑链与模型执行链；不可把模型自填身份当事实。具体技术选择留给实现勘察，不把“前端认证界面”当产品前提。
- 模型可按节点读取作答、请求播放/检查，并编辑另设的示范区；不具备受保护作答对象的写能力。
- 普通非教学工程不自动启用该隔离；工程保存保留受保护对象标记及教师策略绑定。

模型“调用后交给用户，自己不能编辑”也成立，但应设计为**委派任务能力**：模型发出“展示题目/定位作答区/请用户操作”的请求，宿主打开或定位现有编辑器；该请求不携带作答写入补丁、不自动填答案、不提交结果。用户随后编辑走原有学生编辑链。模型持有的是请求人完成任务的能力，不是可以转手冒用的学生写入权限。若显示成任务卡，卡片只是承载选择之一，也可以自然对话加区域定位。

### 3.3 不让模型自行跳关或伪造证据

用户“写好了”触发检查，不直接标成通过；模型“我认为完成”也不替代判定。由宿主读取工程证据，或收集可追溯的评议记录。普通回应事件可证明用户回应过，不能证明教师批准或知识掌握。

日志是事后核查依据，不能单独防止跳关。节点推进应是一项宿主操作：验证当前节点及前置条件 → 核实规定证据来自对应工程修订 → 产生检查回执 → 记录转换前后状态、时间与事件 ID。普通对话或模型输出不直接写完成状态；教师例外放行另有身份验证并留痕。模型叙述与宿主节点不一致时显示/记录不一致，不能让一句“进入下一题”充当真实转换。

**检查回执固化为强制门：** 检查服务读取实际作品和规定证据后签发回执；推进服务只接受其可验证回执。回执至少绑定任务实例、学生、节点、规则/策略版本、工程修订、检查器/评议版本、证据引用、结果、帮助状态、序号和时间。缺回执、检查不通过、回执属于其他题/其他学生/旧版本均不得推进；模型自己拼写的回执 JSON 无效。

推进时以当前节点和工程修订核对回执，原子地记录转换，避免重复请求跨过多个节点。检查之后再次改动相关作答，旧回执只能证明旧快照，当前作答须重新检查；保留历史通过记录而不把它自动归到新作答。主观评议或独立性证据不足时可产生“待复核”回执，不能强行判通过。回执的可信出处和引用一致性可强制检查，审美/学习判断的准确性仍须允许教师复核。

#### 3.3.1 检查门与交互卡分开

强制的是程序内部“有有效检查回执才推进”，不是“必须弹卡问是否下一题”。推荐默认节奏：学生说“写好了”或点一次提交 → 宿主检查并保存回执 → 模型给出具体反馈 → 符合课程约定时自然进入下一环节，不再额外追问一次。

未通过时给出定位明确的反馈并留在当前任务；学生还想修改时保留当前尝试/回到相应节点。涉及审美选择、是否需要更多帮助、是否放弃独立尝试而看示范、最终提交/收局等真正需要学生决定的内容，再使用问询或卡片。常规推进不默认新增一次确认；该设计使强护栏保持在运行机制内，而非把每题变成审批流程。

在现行“GUI 编辑后对话告知”框架下触发检查即可，不据此新增后台 GUI 监视或宣称已能自动感知每次编辑结束。模型叙述下一题受真实节点状态约束，但节点转换不要求模型向学生展示内部回执格式。

已核查的现状：`edu_jam_chat.go` 当前提供枚举内事件记录入口，事件名有效不等于事件主体已经认证；`policy/policy.go` 的 direct/undoable/confirm 风险分类也不是教学角色授权。这两者不能直接作为防跳关和教师权限的实现证据。

### 3.4 文字直接泄露答案也要处理

只禁工具写入仍不足以防止模型在回复中给出整段简谱、MIDI 数据、可执行代码或逐音操作清单。因此：

- 教师私有答案、隐含测试、尚未解锁的针对本题的示范，不进入学生模型上下文、不放进学生可读包；需要时由可信判定服务读取。
- 指导练习使用提示阶梯和允许的例子；限定示范最好使用不同材料，并明确与本题的关系，避免变相给出完整可提交内容。
- 帮助预算按当前任务/尝试累计。分多轮“每次只告诉我一个音”、换会话索取及重复示范，不能被当成互不相关的少量帮助。
- 独立检查可采用宿主提供的限定提示/操作说明和受限输出；开放语言输出需做针对任务的检查，检测到疑似代答时改发合规提示或交教师复核，不仅依赖同一生成模型自审。
- 所有已披露的帮助留证；不能把内容屏蔽后从记录中抹去曾经披露的帮助。

语义上的“有没有变相说出完整答案”难以对开放生成作绝对保证。强保证优先落在身份、写入、节点推进、私有答案隔离和证据记录；更严格测验减少开放生成出口，正式学习判断辅以迁移任务/教师复核。

**更严格的首选实现是受控输出协议：** 作答节点中，LLM 只能从教师审核的提示/追问/示范目录中选择 ID，或请求播放学生已有片段、执行已允许的检查。宿主验证结构化输出中的动作和 ID，再用已批准的文案/材料生成所有学生可见内容。动态参数只能取允许的坐标/枚举，不能藏入任意解释或音符数据；错误消息、工具结果、附件/音频/代码等其他出口同样受控。协议中没有自由填写的完整答案字段，未通过校验的候选不展示，也不能流式先显示再撤回。目录缺项则提示规则范围内无法回答或请教师补充，不自动回退开放生成。

这种方式可以强制保证“模型任意生成文本不会直接到达学生”，但提示目录本身仍需教师检查是否泄题，以及跨轮累积是否过量。代价是该阶段自由表达减少。可将讲解节点设为开放表述加审核，练习节点设为受控提示，独立检查节点进一步只允许题面和操作说明。第二个 LLM 审核自由回答可降低风险，不能替代受控出口的强约束。

**没有预置答案不等于不会代答。** 即使教材仅给“写两小节某种旋律线”或“写八小节旋律”的开放任务，模型仍能当场生成一个满足题意的作品。隔离答案材料减少的是材料泄露，不能代替受控输出与贡献记录。严格阶段继续使用受控出口；允许教学示范的阶段可以解释乃至展示完整示范，但必须符合节点策略。

学生不会时，可依已发布规则进入示范/讲解，再返回练习；若当前节点不允许完整示范，不能仅凭学生请求自行放宽。示范被展示后，记录本次尝试已获得示范：可以检查学生是否理解、能否解释或修改，不把同题后续作品直接认定为独立完成。要形成独立证据，使用教师预定的新材料/新任务再次检查，而不是开新聊天清除帮助状态。

若原始日志出现答案，须区分：模型自行披露、学生主动索取、系统拦截而未展示、学生实际采纳/录入。前三者的责任与学习影响不同；“模型说出了答案”本身不能直接证明学生作弊。报告先给出事实与证据，由教师按已发布规则裁定。

## 4. 贡献记录：把发起者、执行者、材料来源分开

不能让模型事后总结“这一段是学生写的”。应由编辑/执行的可信边界，在实际操作成功时产生记录，并与工程修订绑定。

每项成功操作的最小记录建议包含：任务实例与设计/策略版本、当前节点、时间及单调序号、已认证的发起者、实际执行者、操作通道、规范化动作、受影响轨/clip/note/范围、前后修订/差分、父来源、关联提示或方案、判定/教师批准引用。被拒动作单独记录，不记为成功贡献。

| 面向教师的类别 | 依据与显示方式 |
|---|---|
| 学生在界面编辑 | 可信客户端记录的编辑/演奏录入。只证明操作来自学生端，不宣称思想来源已验证。 |
| 学生指定，模型代执行 | 学生明确给出音符/节奏或具体变换，模型负责写入；保留原指令与执行差分。音乐决定是否足够具体按教学准则复核。 |
| 提示后学生修改 | 先披露过提示/对比，随后学生操作；显示关联帮助和时间，不能只凭时间推断一定由提示导致。关系不明显示“同阶段有帮助记录，归因待复核”。 |
| 模型提出/生成，学生采纳 | 模型给出具体音乐内容，用户采纳后写入；点采纳不改记成学生原创。 |
| 导入/来源未核验 | 外部 MIDI/音频、来源未标明的粘贴、无操作记录的状态变化。不能默认归学生，也不能自动定性为作弊。 |
| 混合 | 学生继续修改模型生成材料，保留来源链并显示具体改动。移动、复制、撤销、重做不清洗原始来源。 |

音符/片段的稳定身份和派生关系须跨复制、剪切、重建、撤销和存盘恢复；只记录最后操作者会丢失贡献信息。学生修改生成音符的力度，不能把其音高/节奏都归为独立创作。必要时记录属性级差分，但不把属性编辑次数换算为创作贡献分数。

符号音乐优先记录音符与片段；生成音频等没有音符身份时用素材与变换链追溯，不能伪造逐音归因。

既有轨迹有 `evidence_refs/action_refs/project_revision` 等可用关联面，MIDI 操作也已有 note ID 与回读接口；本轮只读检查未见上述完整教学贡献账本，不能声称现成。

模型给出具体作答方案时，记录方案 ID、所属题/节点、原文或音乐数据、实际展示时间、材料/片段引用和学生采用关系；后续写入保留来源链。可追溯的复制/采纳应确定性归为模型示范后采用。学生手工重输或大幅改写时，保留已见示范状态，音乐相似性仅作教师复核线索，不能仅凭先后顺序就断言全部内容来自模型，也不能自动改回无帮助独立作答。自由对话中无法可靠确定是否给出完整解答时，标记待复核，保留原文。

## 5. 教师检查作业：按目标组织证据

教师打开一次提交，默认先看**答题作业报表**与**工程执行对话流关键上下文摘要**，需要时再查原始记录。两份材料共同引用提交时固定的工程、规则和日志范围。

| 页面内容 | 应能看见什么 |
|---|---|
| 提交身份与版本 | 学生/任务/教师发布版本、本次提交指纹、记录是否完整、是否受管验证 |
| 每个目标 | 判据、当前表现、对应音乐范围和版本、用过的帮助、是否需要人工复核 |
| 作品来源视图 | 片段/音符的来源徽标，混合来源可展开；学生修改相对生成初稿的差分 |
| 关键过程 | 原始尝试 → 提示/示范 → 学生修改 → 再次试听/检查，可播放和比较 |
| 允许与实际帮助 | 该节点允许什么、实际披露什么、教师是否额外放行；任务完成与独立性分别显示 |
| 教师批注 | 针对具体片段/目标反馈，退回修改、要求解释或布置迁移检查 |

例如：“节奏约束已满足；旋律为模型示范后修改；学生能指出并解释自己的两处变化；独立运用暂缺证据，建议换节奏再写两小节。”这比单一总分或“AI 占比”更能说明学习情况。

建议首版不以一个百分比表达学生能力。音符数量、时值与修改次数都不能完整代表构思、审美和学习；若以后展示统计，须显示分母、计量口径和未知部分。

教师评议应能覆核 LLM 建议，并记录理由。作品好听、全节点完成、学会目标是三个不同结论。不得仅因触发过越界请求就自动扣分或判作弊。

### 5.1 答题作业报表

按题目/学习目标排列：任务条件、提交音乐片段与试听、客观检查结果、来源组成及学生修改差分、实际帮助程度、学生说明、证据完整度、待教师裁定项。每项能打开对应工程版本或记录；不把“模型写得好”转写为学生掌握。

### 5.2 工程执行对话流关键上下文摘要

按真实事件顺序提前摘取：开局任务/规则 → 题目与当前目标 → 学生首次尝试 → 模型讲解/提示/示范 → 学生修改 → 检查及节点转换 → 最终提交。每条含时间、节点 ID、关键对话原文片段、帮助是否实际展示、关联操作/工程修订、原始消息或事件引用。遗漏区间和记录缺口显式标注。

题序、时间、次数、通过状态、来源类别和原文摘录由结构化记录产生；LLM 可辅助写阅读摘要，但解释性结论须回指证据，不能让负责教学的模型单独凭记忆编写证明自己的总结。教师可从摘要一键定位原始对话/工具请求结果/宿主转换记录，无需先通读整份日志。

### 5.3 原始记录保留

原始对话、实际发送给模型的乐局上下文版本/相关材料定位、工具请求与执行结果、准入/拦截结果、节点状态转换和工程检查点应按提交范围固定留存。被拦候选与学生已见内容分开，避免把未展示答案误记为学生已获得帮助。摘要不能替代原始记录，也不能因运行日志滚动或对话压缩而丢失可复核依据。

可复用现有 conversation/journal/trajectory 的引用体系，但须核查完整保留策略与前端 GUI 写入覆盖。现有 agent action journal 并不自动等于包含全部学生编辑、模型输入与披露状态的教学原始记录。

## 6. 提交、退回与可验证程度

- 提交时固定工程快照、设计/策略版本、证据与来源记录范围。教师批改针对该次快照；学生后续编辑形成新提交，不覆盖旧批改对象。
- 退回后继续保留生成来源和历史帮助。教师额外提示后，新的尝试以新的帮助状态记录。
- 缺日志或工程与日志不一致，标记“记录不完整/来源待核验”，不捏造完整度，也不据此自动判违规。
- 本机过程记录可帮助教学复盘，但若学生控制程序、磁盘和密钥，单靠同目录文件、内容哈希或本地哈希链不能证明未被重写。更强验证需要教师保管的签名/可信运行端与记录锚点；私有判定材料在相同可信边界内。
- 不能证明学生没有使用系统外 AI，也不能靠连续 GUI 操作证明独立思考。可观察过程结合学生解释和新材料迁移，支持有边界的学习判断。

不必为演示先建设完整学校管理系统；但必须如实说明该部署是本机过程记录，还是教师受管验证。文档里写了教师角色不等于已实现角色隔离。

## 7. 模板需要的扩展

配套模板增加以下设计声明：

1. `governance`：用途、请求的协作档位及可信发布策略引用；源文档不携带教师密钥，也不能自证身份。
2. 每节点 `assistance`：该阶段请求的帮助种类、模型可写区域以及需保留给用户的决定。最终权限由宿主交集计算。
3. `evidence_recording`：所需来源记录粒度、帮助记录和版本检查点；实际完整度由运行时给出。
4. `submission`：提交快照、教师逐目标复核与退回要求；不把存档当成自动证明学会。
5. `answer_disclosure` 和节点 `assistance.reply_mode`：选择受控提示或开放回答审核，禁止未审核内容流式显示；严格方式绑定教师批准目录。
6. `submission.reports`：固定为作业报表、关键上下文摘要两类审阅材料，另附原始证据索引。

这些是未实现的设计字段，不能添加到现有运行卡冒充已支持。拟议格式尚在讨论期，当前扩展不是对已发布 schema 的无声兼容更改。

## 8. 后续实现必须验证的反例

1. 学生要求忽略约定、扮演老师、跳关、重写策略，身份与规则不变，合法学习请求仍可继续。
2. 不同聊天窗/模型/子代理/直接 API 请求不能提高本任务权限；full access 也不覆盖教师策略。
3. 禁止模型写学生作答区时，换工具名、批量写、生成导入、复制示范、脚本旁路都不绕过；未纳管通道明确阻塞强保证。
4. 简谱、代码、逐音指令和多轮拼答案等披露风险有测试；同时验证允许的解释与示范不被全部误封。
5. 学生自报完成/伪造事件不产生教师批准或学习达成证据；实际工程检查失败时不推进。
6. 模型生成 → 学生修改 → 复制 → undo/redo → 重开，来源链和帮助记录均保留；无记录导入显示未知。
7. 教师可对提交快照逐目标查看证据、回放关键版本并退回；新提交保留旧快照和批注。
8. 策略/记录被改或缺失时标记正确，不伪造 PASS，也不自动判作弊；普通共创乐局仍能按其公开规则使用生成能力。
9. 教师与学生独立账户/主机前提下，学生及其 agent 对教师发布 YAML 的写入/替换/重绑定被拒。
10. 受控输出中自由文本、越域 ID、未审核流式片段、附件和工具错误旁路均无法向学生展示；缺提示条目不回退开放回答。
11. 两份报告的题序/时间/摘录/来源与原始记录一致；被拦未展示内容不记成学生采纳，摘要每项可回溯。
12. 学生现有编辑链可编辑作答区，模型任何写路径均被拒；旧 MIDI/clip/工程写接口不能绕过受保护对象，普通工程回归正常。模型请求用户作答可定位编辑器，但不能借此附带答案写入。
13. 缺失/伪造/过期工程修订/跨题回执不得推进；重复推进请求不跳两题；有效检查回执可推动恰当节点并留下状态转换。
14. 已展示模型示范后，采纳、手工重输、修改和重开均保留帮助状态；同题通过不自动形成独立完成结论。
15. 学生一次完成表达触发检查后，可凭有效回执自然推进，无强制额外确认卡；未过、尚待选择、请求示范等分支有对应反馈和记录。

正式测试须遵守仓库真实栈与渲染/旅程验收规则；本稿没有运行这些测试或证明现有系统可抵抗上述情况。
