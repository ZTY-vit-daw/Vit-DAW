## 0. 为什么重做（v4 复盘结论）

v4 两版（`../main-window-v3/v4-1-refined.html`、`v4-2-refined.html`）的问题不在执行细度，在方法：

1. **说明层混进了产品层。** 产品窗口里写着"对话流内状态控件""宏快照 · 一钮多参 · 不暴露原始数值""Z-TOP · 打开态"。这些是写给评审的规格语，真实用户永远不会看到。
2. **广告与杂志修辞代替了界面文案。** "对话即工作台""AI-FIRST 数字音频工作台"是营销口号；"开台白 · 第 40 期 · 冬""图 1""注 1""栏目"是出版物比喻。
3. **结构风被用成了"给每个单元套 3px 黑框"。** 蒙德里安的画面靠极少的线和面成立；一个界面上百个元素都套框，线就从构成变成了噪音，这是"杂乱、信息量过大"的主因。
4. **颜色语义过载。** v4-1 里红色同时表示发送、续听、在线、进行中、完成印章、标题装饰；黄色同时表示当前激活和进行中。
5. **没有图标体系。** 彩色小方块被当成项目符号到处用；唯一的图形资产磁带 icon 只被当成缩略图。

执行者开工前请打开上面两个 v4 文件看一遍，作为反例。

### 用户裁定原话（2026-11-14，不可翻案）

- 「像什么 Vit AI first DAW 之类的这种标语，这都属于是"广告"性质的宣传词。但是我们要设计的是实际产品窗口，所以还是想更产品化。」
- 「对于图形化 icon 的设计和应用还是不足。」
- 「其实蒙德里安也不是一定用红蓝黄黑白作为全部配色对吗？」（结论：保留 11-09 锚定的色值，只重分配比例与角色；暂不引入新色）
- 「我将红黄蓝作为三种等级的信息内容表示，即蓝色是安全态，黄色警示，红色警告。黑白组成边界。但是显然这种设计方案对于成熟的产品还是太简陋了。」（结论：三级语义保留为状态层的核心，升级为分层颜色系统，见 §4）
- 对四项决定回复「没问题」：① 色值不动、重分配角色；② v4-1/v4-2 合并为一条线；③ 产品屏零注记，叙事移到规格板；④ 首批图标约 16 个＋《百老汇爬梯舞》小实验。

## 1. 继承与废止

**继承（不得改动）**

- 令牌色值：`--ink:#090B0E --paper:#F6F4EC --warm:#FBF9F1 --canvas:#E8E4D7 --blue:#065BC7 --blue-lt:#73B8F5 --red:#DB1214 --yellow:#FACC1A --dark:#14181C`。可派生中性灰阶（§4.1），不得新增彩色。
- 磁带 icon：`tapeSVG(w,h,a)` 从 `../main-window-v3/SPEC.md` §3 逐字复制，结构不动；可改尺寸、可传 `a` 参数。
- 双独立 OS 窗口：对话窗（React/WebView）与 DAW（Godot）各自是 OS 窗口。
- 窗口二态：对话窗要么打开在前（大面板主导、DAW 沉后），要么完全最小化退场（OS 原生，任务栏 / Alt+Tab 召回）。无中间态、无把手、无常驻条、无侧栏。
- 宏快照语义：一个宏＝一组预绑定参数的命名快照；教学语言；不显示 dB 等原始数值。
- 投影约束：正文 ≥14px（本文统一定为 16px，见 §6）、对比度 ≥4.5:1、半尺寸缩放仍可辨层级、投影下靠色块不靠细线。
- 全中文真实内容；单文件 HTML、零外部图片、零 CDN、系统字体栈。

**废止**

- "每屏塞进六项必画元素"。产品屏只画用户看到的东西，叙事与说明全部进规格板（§2）。
- v4-1 / v4-2 两变体并行。合并为一条线（§5）。
- 一切口号、杂志修辞、规格语进入产品屏（§3）。

## 3. 文案规则

产品屏里的每一个字都要回答"用户此刻需要知道什么、能做什么"。

**禁止**

- 口号与产品介绍：对话即工作台、AI-FIRST、数字音频工作台、搭档在线。
- 出版物修辞：开台白、第 N 期、本期、栏目、图 1、注 1、上期批注。
- 规格语：一钮多参、不暴露原始数值、对话流内状态控件、宏快照语义、Z-TOP / Z-BOTTOM、打开态、always-on-top。
- 装饰性英文全大写标签：TAPE LIST、STATE、STORYBOARD、PROOF SHEET。
- 用"·"串起三项以上的元信息。一行元信息最多两项。

**要求**

- 窗口标题：标题栏左侧为 `i-vit`（§7.3.1）；对话窗无工程时标题为"Vit"，有工程时为工程名，如"鼓组混音 v2"。
- 按钮写动作本身：应用、对比 A/B、撤销、新建工程、打开文件夹。同一动作全程同名（按钮"应用"→ 回执"已应用"）。
- 状态写"正在发生什么＋用户能做什么"：如"正在打开工程… 完成后可继续输入"。
- Vit 的口吻：第一人称、简短、具体、不夸张；一条消息通常 1–2 句。
- 快捷键用键帽样式显示，只在真正有用的地方出现（如 A/B 的空格键），不在每个输入框下列满。

## 4. 颜色系统：三级语义的升级版

用户原方案（蓝＝安全、黄＝警示、红＝警告、黑白＝边界）保留为**状态层**的核心。升级之处在于：颜色按层分工，每一层只回答一个问题；中性色占绝大部分面积；三原色只在"有状态要表达"的地方出现。

### 4.1 中性层（占屏幕面积 ≥85%）

| 角色 | 值 | 实测对比度 |
|---|---|---|
| 主文字（浅底） | `--ink #090B0E` | paper 17.89 · warm 18.69 · canvas 15.49 |
| 次文字（浅底） | `--text-2 #4A4F55`（派生） | paper 7.51 · warm 7.84 · canvas 6.50 |
| 弱文字（浅底，占位符、时间戳） | `--text-3 #62666B`（派生） | paper 5.25 · warm 5.48 · canvas 4.55（canvas 上只用于 ≥16px） |
| 主文字（深底） | `--paper #F6F4EC` | dark 16.20 |
| 次文字（深底） | `--text-2d #A9ADB1`（派生） | dark 7.90 |
| 弱文字（深底） | `--text-3d #8D9195`（派生） | dark 5.62 |
| 面 | `--paper`（主面）· `--warm`（抬起的面、输入框）· `--canvas`（凹下的面、抽屉、桌面）· `--dark`（DAW） | — |

### 4.2 状态层（用户三级语义＋待机）

| 状态 | 颜色 | 含义 | 典型用处 |
|---|---|---|---|
| 待机 | 中性（`--text-2` 线框） | 没开始、没有需要关注的事 | Vit 空闲；步骤未开始 |
| 变化中 / 需留意 | 黄 `#FACC1A` | 结果还没定：正在进行、等你确认、接近上限、有未保存的改动 | Vit 正在工作；装载中；宏试听中；电平接近上限 |
| 安全 / 已完成 | 蓝 `#065BC7`（深底上用 `#73B8F5`） | 已完成且可回退 | 已应用（可撤销）；快照已存；装载完成 |
| 警告 / 不可逆 / 出错 | 红 `#DB1214` | 出错，或者这个动作做了就回不去 | 失败；削波；录音中；覆盖导出、删除 |

"变化中"归入黄色是本 spec 对用户原方案的一处扩展（原方案里黄＝警示），理由是"结果未定"本身就是需要留意的状态。**用户已认可，并补充：变化中主要靠执行轨迹等动效表现，黄色只是辅助标记**（见 §4.2.1）。

#### 4.2.1 变化中的主表达是执行轨迹（用户裁定）

- Vit 在做事时，界面上要能看出"它正在往前走"：步骤按顺序出现、当前步骤的指示在动、已完成的步骤留下一行轨迹、磁带带量在变（§7.4）。这和 agent 产品里常见的工具调用轨迹同理。
- 黄色只落在"当前这一步"的小面积标记上（状态点、当前步骤的底色条之一），不做整卡黄底。
- 静态产品屏画的是轨迹进行到一半的那一帧：前面几步已完成并收成轨迹，当前步骤在动，后面的步骤还没出现或显示为待机。
- 动效规格（出现方式、节奏、时长、缓动）画在规格板 S2 上，至少 4 帧；HTML 里可以用 CSS 动画实现，但必须尊重 `prefers-reduced-motion`。

**Vit 本体没有品牌色。** Vit 的身份由磁带 icon 和墨色承担；Vit 在界面上的状态指示（任务栏条目、状态卡、对话窗标题栏）一律按上表着色。

**同一套语义贯穿三处：**

1. Vit 自身状态（待机 / 工作中 / 完成 / 出错）。
2. 代理动作的后果等级（人在回路）：蓝＝可撤销的改动，Vit 可直接执行；黄＝影响面大，需要你确认；红＝不可逆，必须用红色按钮显式确认。
3. 信号电平：蓝＝安全区，黄＝接近上限，红＝削波。这是三级语义在 DAW 里最自然的落点。

### 4.3 交互层（不得借用状态色）

| 交互态 | 表现 |
|---|---|
| 当前选中 | 2px 墨框＋`--warm` 底（用户裁定：浅底；墨底反白在投影下太过曝光，不用） |
| 键盘焦点 | 浅底：2px 墨色外框、外偏 2px；深底：2px `#73B8F5` 外框 |
| 悬停 | 底色加深一级（paper → canvas） |
| 禁用 | `--text-3` 文字＋斜纹或虚线边 |
| 主按钮 | 墨底纸字。**主按钮不得用红色**（发送、应用都是墨色） |
| 次按钮 | 纸底＋1.5px 墨边，或纯文字按钮 |
| 危险按钮 | 红底纸字（4.64:1），只用于不可逆动作 |

### 4.4 表面适配（实测得出的硬规则）

- 黄色在 paper 上只有 1.39:1：**黄只能做底色，上面放墨色字或图形**，不能当文字色或细线色。
- 蓝色在 dark 上只有 2.83:1：**深底一律用 `#73B8F5` 表示安全态**。
- 红色在 dark 上只有 3.49:1：深底上的红只能做实心面或 ≥3px 的图形，不能当文字色。
- paper 字在红底上 4.64:1、在蓝底上 5.73:1，可用；墨字在黄底上 12.87:1、在 `#73B8F5` 底上 9.29:1。

### 4.5 用量预算

- 每个产品屏同时可见的状态色区块不超过 5 处，且每处都能说出它表示哪个状态。
- 彩色不得用作项目符号、装饰方块、标题点缀。
- DAW 背景 mock 遵循同一语义：录音键红；削波红；电平表蓝→黄→红；播放头用纸色细线（不用红）；总线以图标区分，不用色带。
- 工程头像色（磁带 icon 的氛围色，由工程名哈希得出）属于身份色，只出现在磁带 icon 内部，不外溢到界面其他地方。

## 5. 结构风的用法（合并后的单一路线）

一句话：**结构风只用在构成层，不用在控件层。** 取 v4-1 的骨架与对比度，取 v4-2 的留白与安静的工作面。

### 5.1 线

- 2px 墨线只用于三处：OS 窗口外框；窗口内主分区（抽屉与对话区之间）；当前选中元素的边界（§4.3）。
- 其余分隔用 1px 浅线（`rgba(9,11,14,.14)`），或者干脆用间距和底色差（paper / warm / canvas）区分。
- 普通的行、卡片、消息不套框。

### 5.2 面

- 每个产品屏最多一处"构成时刻"，即用色面和比例做出画面感的地方。例如 P1 空工程区的磁带 icon 加几块中性色面。
- **构成色面只用中性色**（ink / dark / canvas / warm，参照蒙德里安 1918–1919 年以灰与低饱和色为主的网格构成）。三原色已被状态层占用，拿来做装饰色面会被读成"安全 / 警示 / 警告"。
- 平涂，不用渐变（OS 窗口阴影除外）。

### 5.3 形

- 圆角：面一律 0；交互控件（按钮、输入框、可点选的选项、开关）统一 4px；状态点可以是正圆。除此之外不出现圆角，不用胶囊形。
- 阴影：只有 OS 窗口、弹出层和系统通知有阴影，卡片没有。**用柔影（用户裁定）**，全站只定义一档窗口阴影、一档弹出层阴影，写进令牌。
- 网格：8px 基准，细部 4px；正交、非对称布局。

### 5.4 实验：《百老汇爬梯舞》（只进规格板 S6）

《百老汇爬梯舞》（1942–43）用黄色线网格和红蓝灰小方块画纽约的街道与爬梯舞节奏，形态上接近步进音序器。它和 Vit 的"音乐"属性最贴，但黄线网格与"黄＝变化中"冲突。实验要求：

- 网格线改用中性色（墨或灰），彩色只落在"事件方块"上。
- 推荐题材：**Vit 的改动历史条**。每个方块是 Vit 做过的一次改动，颜色按后果等级（蓝 / 黄 / 红），长度表示持续时间。
- 输出 2–3 个变体，评估它能否在 P3 或 P4 里成为一个真实组件；评估结论写在 S6 板上。

## 6. 字阶

- 字体：`Inter, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`，全站一套。
- 等宽 `Consolas` 只用于时间码、BPM、数值和键帽，不用于标签和元信息。
- 字阶（px / 字重 / 行高）：

| 用途 | 规格 |
|---|---|
| 说明与时间戳（最小字号） | 13 / 400 / 1.5 |
| 次要文字 | 14 / 400 / 1.55 |
| 正文（对话消息） | 16 / 400 / 1.65 |
| 正文强调、按钮 | 16 / 600 |
| 卡片标题 | 18 / 600 / 1.4 |
| 宏名等关键信息 | 22 / 700 / 1.25 |
| 屏级标题（每屏至多一处，如 P1 问候） | 28 / 700 / 1.3 |

- 中文正文字距 0；标题字距不超过 0.05em；不用大字距撑排版。
- 数字用等宽数字（`font-variant-numeric: tabular-nums`）。
- 对话流行宽控制在约 36 个汉字以内。

## 7. 图标体系

### 7.1 构造规则

- 24×24 网格，活动区 20×20（四周各留 2px）。
- **线重分层**：结构 2 / 2.5px，细节 1.5px，引导 1px；16px 最小 1.5px，32px 允许 2.5px。
- **实心 / 空心 / 反白**：物理质量（磁带盘、推子帽、旋钮、录音点）可用实心；选中/激活用反白或实心；不要求每枚都是空心描边。
- **开轮廓与曲线**：文件夹前盖、区间括号、磁带窗口可以断开；磁带盘、旋钮、听耳用曲线。直角留给真正结构化的对象（轨道、推子、机架）。
- **文字入图**：A/B 直接用字母，一黑一白；Vit 品牌用 V 形几何，不硬造具象物。
- 显示尺寸 16（最小）/ 20（界面默认）/ 24（强调）。16px 优先保留一个轮廓 + 一个对比，20/24px 再加细节。
- 状态：默认＝墨描边；选中＝实心形或反白；禁用＝`--text-3`；深底＝纸色描边。状态色只通过图标内一个小实心区或角标表达。整枚图标染红只限危险动作。
- 实现：每个 HTML 内放一份内联 SVG `<symbol>` 雪碧图（`viewBox="0 0 24 24"`），用 `<use href="#i-xxx">` 引用。
- 必须为本系统原创绘制，不得照搬 Material、Lucide 等现成图标库的造型；不用 emoji；不用彩色小方块当项目符号。

### 7.2 首批清单（22 枚＋标志）

> **v5.1 定稿（2026-11-14）**：原 `i-vit` 磁带标志改为 `i-project`（工程）；新增 `i-error`（状态环）与新的 `i-vit`（V 品牌标）。功能图标共 22 枚 + `i-vit`；S3 与 `round2-sprite.svg` 为准。

另有小尺寸工程标志 `i-project` 与 Vit 品牌标 `i-vit`，见 §7.3.1。

| id | 含义 | id | 含义 |
|---|---|---|---|
| `i-new` | 新建工程 | `i-play` | 播放 |
| `i-open` | 打开文件夹 | `i-record` | 录音 |
| `i-minimize` | 最小化窗口 | `i-render` | 渲染 / 导出 |
| `i-send` | 发送 | `i-undo` | 撤销 / 回到快照 |
| `i-stop` | 停止 Vit 当前的生成或执行 | `i-snapshot` | 快照 |
| `i-track` | 轨道 | `i-attach` | 把时间区间或轨道引用进对话 |
| `i-bus` | 总线 / 编组 | `i-idle` | 状态：待机 |
| `i-fx` | 效果器 | `i-busy` | 状态：变化中 |
| `i-macro` | 宏 | `i-done` | 状态：完成 |
| `i-ab` | A/B 对比 | `i-alert` | 状态：出错 |

四枚状态图标要做到不靠颜色也能区分（色盲与黑白投影），颜色只是第二道编码。

### 7.3 磁带 icon 的功能化

磁带 icon 不再只是缩略图。它承担两个角色：

1. **工程头像**：抽屉列表、建议动作里的"继续某工程"。
2. **Vit 工作时的载体**：状态卡里用它表示进度（见 7.4）。

`tapeSVG` 在高度小于约 48px 时窗口区过窄、读不清，因此不在 48px 以下使用。

#### 7.3.1 小尺寸工程标志 `i-project` 与 V 品牌标 `i-vit`

> **v5.1 修订**：磁带标志改名为 `i-project`，归工程对象；`i-vit` 改为 V 品牌标，只用于应用图标、任务栏 Vit 条目与系统通知，**不进入对话窗标题栏**。下文“磁带 logo”的旧描述保留为资产来源说明；现行 symbol 以 `round2-sprite.svg` 与 S3 为准。

- `i-project` 用途：工程卡、工程抽屉、P3 标题栏、任务栏工程条目；保留壳体、窗口、双盘三个要素。
- `i-vit` 用途：应用图标、P4 任务栏 Vit 条目、系统通知、≤32px 的 Vit 身份位置；造型为实心 V + 1px 内槽，和桌面端 `Vit-logo icon.png` 同源。
- 状态叠加：右下角一个小状态点，颜色按 §4.2（变化中时状态点可以动）。不得把整个标志染成状态色。
- 规格板 S3 上把 `i-project` 与 48px 以上的 `tapeSVG` 并排展示，证明两者是一家。

### 7.4 磁带三态：用带量表达进度（不改结构）

`tapeSVG` 的两个带轮是同心圆，转动看不出来；但参数 `a.L`、`a.R` 控制左右带盘上的带量。进度可以表达为"带从左盘绕到右盘"：

- 待机：`L=1, R=0.2`
- 进行中（进度 p）：`L=1-0.8p, R=0.2+0.8p`，例如 p=0.64 时 L≈0.49、R≈0.71
- 完成：`L=0.2, R=1`

`a.c1` 取工程氛围色；没有氛围色的工程（如《ProQ3 裸控实验》）用中性色 `[200,200,196]`。这只改参数，不改 SVG 结构，符合红线。规格板 S2 上画出这三帧，产品屏 P2 的状态卡用"进行中"这一帧。

## 8. 组件

每个组件都要在规格板 S5 上画齐全部状态，产品屏只出现当时那一个状态。

### 8.1 消息

- 用户消息与 Vit 消息只靠一种手段区分（对齐方式或底色，二选一）。不用"你""VIT"色块徽章。
- 时间戳只在跨时段时出现一次，不逐条标注。

### 8.2 状态卡（Vit 正在做一件多步的事）

- 标题直接写在做什么，如"正在打开《鼓组混音 v2》"。
- 以执行轨迹的形式呈现（§4.2.1）：步骤逐条出现；已完成的步骤收成一行轨迹（状态图标＋步骤名＋耗时）；当前步骤有动效；未开始的步骤不提前列出，或以待机态显示。一张卡最多同时显示 3 步。
- 进度只用一种表达：磁带带量（7.4）或进度条，二选一。
- 状态：进行中（当前步骤小面积黄）/ 完成（蓝，整张卡收起为一行回执，轨迹可展开）/ 出错（红，写明原因和"重试"）。

### 8.3 宏卡

- 标题：对象＋宏组名，如"鼓组总线 · 染色"。
- 3 个选项：宏名（22/700）＋一行音乐性描述（14）。
- **只保留一种可视化**：频响轮廓或分频段强度条，二选一。v4 同时放了曲线、强度条、听感引语和"一钮多参"图示，信息过量。
- 动作：应用（主按钮）＋存为我的快照（文字按钮）。
- 状态：默认 / 试听中（黄）/ 已应用（蓝，带"撤销"）/ 失败（红，带原因）。

### 8.4 动作卡（Vit 准备做或已经做了一件改动）

- 必须表达后果等级（§4.2 第 2 条）：可撤销（蓝）/ 需确认（黄，附"确认""取消"）/ 不可逆（红，红色确认按钮）。
- 用状态图标加一个词表达等级，不用色条。

### 8.5 快照回执

- 一行：`已保存快照 14:07 · 撤销`。不另起卡片。

### 8.6 输入框

- 状态：默认 / 焦点 / 禁用（装载中：斜纹底，提示"打开完成后可继续输入"）/ Vit 回复中（发送键变为 `i-stop` 停止键）。

### 8.7 系统通知（用户裁定：需要）

- 只在对话窗最小化（或不在前台）时发出；对话窗打开在前时不弹。
- 采用 Windows 原生通知的版式和尺寸（右下角、系统阴影），内容遵守本 spec：
  - 图标：`i-vit`，带状态点；
  - 标题：工程名，如"鼓组混音 v2"；
  - 正文一行，写结果和下一步，如"已应用「温暖」，A/B 已渲染好"；
  - 动作最多两个，如"打开 Vit""撤销"。
- 三种类型与 §4.2 对应：完成（蓝点）/ 需要你确认（黄点，动作为"去确认"）/ 出错（红点，动作为"查看"）。
- 点击通知本体＝召回对话窗并定位到那条消息；这与任务栏、Alt+Tab 召回同属 OS 窗口操作，不引入中间态。
- 尊重系统勿扰模式；Vit 设置里可单独关闭。

### 8.8 提示音（用户裁定：需要）

- 与系统通知同时触发，同样只在对话窗不在前台时响。
- 三种提示音，与通知类型一一对应：
  - 完成：两个音、上行、明亮，例如大三度上行；
  - 需要你确认：两个音、同音重复或二度，听感是"请看一下"而不是报警；
  - 出错：两个音、下行、偏暗，但不刺耳。
- 每个时长不超过 400ms，音色干净（正弦波或柔和的三角波加短包络），音量低于系统默认通知音。教室投影场景要能一键静音。
- 原型实现：在规格板 S7 用 WebAudio 现场合成，提供三个"试听"按钮，只在用户点击后发声，不自动播放，不引用任何外部音频文件。
- 提示音的乐理参数（音高、时值、包络）写在 S7 上，作为后续实施的依据。

## 9. 工作方式

1. **开工前**：通读本文；打开 `../main-window-v3/v4-1-refined.html`、`v4-2-refined.html` 看反例；从 `../main-window-v3/SPEC.md` §3 复制 `tapeSVG`。`../main-window-v3/direction-a-warm-editorial.html` 只参考执行细度，不参考它的出版物比喻。
2. **先令牌后画面**：S4 令牌与 S3 图标集定稿之后再画 P3。画 P3 时只能用令牌里有的颜色、字阶和图标。
3. **渲染自审，至少两轮**：每轮用 Playwright 在 1440 视口渲染，逐屏元素截图，再缩到半尺寸看一次。对着截图找问题、改、再截。不看截图不交付。
4. **"拿掉一件"**：每屏交付前至少删掉一个没有存在理由的元素，在变更记录里写明删了什么。
5. **遇到"需要解释"的冲动**：产品屏里如果某处必须加注才能看懂，说明要么是设计问题，要么这条信息属于规格板。不得用注记补救。
6. **变更记录**：每轮在 `CHANGELOG-V5.md` 里逐条写改了什么、为什么。

**沙箱渲染环境**（无 root 可用）：

```bash
pip install playwright --break-system-packages
python3 -m playwright install chromium
# 运行时缺 libXdamage.so.1：
mkdir -p /tmp/libs && cd /tmp/libs && apt-get download libxdamage1 && dpkg -x libxdamage1_*.deb /tmp/libs/x
export LD_LIBRARY_PATH=/tmp/libs/x/usr/lib/x86_64-linux-gnu
```

不要在 `D:\Vit_DAW` 根目录跑全盘 `find`，会超时；按已知子目录直接 `ls`。
