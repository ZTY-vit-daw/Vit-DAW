## 必须保留的控件语义

1. 应用整体和正文为黑白灰；复合控件采用蓝色外壳、较深内槽、独立选项与深色图形区。深蓝标题上的文字反白，浅底文字为黑灰。
2. 选中项浅黄，2px 深色轮廓与选择点提供形状编码。蓝色 / 黄色曲线只是选择与普通控件的图形表现，不是原始测量或实际均衡器读数。
3. 红色只用于更高警示、失败、不可逆后果，以及录音 / 削波等已定义状态。宏“温暖”不永久绑定红色。
4. “选择一个宏”与“应用”分开。切换选项显示“已选择”，只有服务端真实成功后才能显示“已应用”。不能由前端样式变化推导成功。
5. 宏为命名参数快照，3 个选项、音乐性描述、单一频响轮廓；不把底层参数数值塞进教学界面。
6. 试听需提供取消；失败显示原因和重试，保留未应用事实；快照是单行回执，撤销必须绑定真实快照。
7. 执行中通过步骤与当前标记推进，最多显示 3 步，完成收成一行，可展开轨迹。未知进度不伪造倒计时。
8. 磁带 `tapeSVG` 源代码来自旧 SPEC §3，逐字冻结。只改变尺寸和参数；48px 以下使用独立小标志 `i-project`（工程）/ `i-vit`（V 品牌）。磁带身份色只在磁带内部。
9. 空间关系按 v5.1：阅读面 `#F0F1F2`；窗口 1px `#5B626A` 边 + 三层柔影；宏卡无四周等重描边，靠接触影 `0 1px 2px 18%` / 浮起影 `0 6px 16px 12%` 与内槽凹入；选中项 2px 墨框 + 1px 外环、投影低于未选项；失败态保留警示边框与底色。不得把所有层重新框成等重矩形，也不得把柔影扩散成雾状。

## 实施切分建议

以下是拆卡建议，没有自动派发、领取或授权修改生产文件。执行者先只读核对真实装配，再由本设计会话 / 用户确认具体卡面、owner 和文件域。

| 切片 | 首选工作域 | 依赖与验收重点 |
|---|---|---|
| A：令牌、图标与复合控件 | `agent/webui/src/` 中的现行样式与组件位置，勘察后固定域 | 先复现 S3 / S4 / S5；不夹带 agent 行为修改。DOM 检查默认、选中、焦点、禁用、失败；选择不等于应用 |
| B：启动台与工程内主界面 | WebUI 当前启动、抽屉、对话与快照的真实装配 | 复现 P1 / P3，消费既有工程 / 会话数据，不用硬编码示例工程冒充真实数据 |
| C：装载与执行生命周期 | WebUI 与现行 agent 事件接口，按代码锚点另定域 | 复现 P2、S2 的状态推进和输入禁用 / 恢复，验证错误和中断，不只测顺利完成 |
| D：OS 窗口与通知 | 对话窗口宿主及 Godot 前端相关桥接；必须先确认当前实现 | 原生最小化 / 召回、前后台检测、窗口层序、通知点击定位、勿扰与提示音。不得用网页 CSS 假冒 OS 级行为已实现 |

样图的 DAW 轨道与机架是背景 mock，**本轮不要求执行者顺带重绘整个 DAW**。生产 DAW 的改动需单独确定范围。分辨率适配、系统缩放与文本长度使用真实宿主约束决定，不能把固定 1440×900 样图直接锁死成用户窗口尺寸。

## 窗口连续性（启动页 = 对话窗，工程沉后）

用户 2026-11-14 明确：产品第一面是 Godot 拉起的启动页，而启动页就是本设计的对话流窗口；打开工程时 DAW 在它后面沉入并落位，对话窗保持在前；最小化时对话窗整体退场。这个叙事不是新提议，留存依据如下：

- [AI-first 启动面设计 v1](../../../../coord/reports/2026-11-09-ai-first-launcher-design-v1.md) §1.1–§1.3「启动即对话窗」「三态一窗」：态 A 启动页对话窗 → 态 B 进入中 → 态 C 工程内同一窗侧挂/常驻。
- [2026-11-09 AI-first 启动面裁定](../../../../coord/decisions/2026-11-09-ai-first-launcher-ruling.md)：启动即对话窗口、单窗常驻、agent 自主路由；展演裁剪红线与双轨降级。
- [2026-11-11 展演体验优先裁定](../../../../coord/decisions/2026-11-11-legame-demo-experience-first.md) §16：双独立 OS 窗口（React/WebView 对话窗 + Godot DAW）、沉降叙事、二态切换；并明确实施前先做「窗口实例跨阶段存活」探针（启动页对话面板与工程内浮窗是否同一实例）。

两份留存文档在承载实现上有差异：332 设计把启动页对话窗写成 Godot 组件并主张单窗常驻；11-11 裁定把对话窗写成 React/WebView 独立窗。探针正是为对齐这个差异：先回答是不是同一实例；若不是，是让 React 对话窗在启动页阶段就存在并跨场景存活，还是保留两个渲染面只做叙事连续。该结论决定切片 B / D 的形态；未出结论前不得把两套窗口同时接上，也不得另建第三个启动器。

## 通知与声音

- 对话窗不在前台时才通知；打开在前不弹。完成、需确认、出错三种类型；工程名为标题，一行结果，最多两个动作。
- 通知本体召回同一窗口并定位到消息；“撤销”消费真实回退能力。无能力时不得放可点的伪撤销按钮。
- 浏览器原型没有发送真实系统通知；当前按钮只展示版式。
- 三种试听基于 WebAudio 正弦波，音高、时段、包络见 S7。315 / 280 / 345ms，峰值增益 0.035，统一静音；重复试听会停止上一组节点，避免叠音。
- 声音只由点击试听触发；实际产品的后台通知音需目标设备校准，不把原型增益当作已验证的系统相对响度。
