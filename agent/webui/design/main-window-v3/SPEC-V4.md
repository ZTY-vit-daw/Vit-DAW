- **窗口二态裁定（2026-11-14 用户澄清，修正"底部横条"误读）**：对话窗口**要么打开在前面（大面板主导、DAW 沉后），要么完全最小化退场（OS 原生行为，任务栏/Alt-Tab 召回）**——没有中间态：无常驻横条、无把手、无侧栏。工程内编辑 DAW＝对话窗最小化；回到对话＝召回窗口。
- 窗口架构裁定：**双独立 OS 窗口**——agent 对话窗（React/WebView）与 DAW（Godot）是两个 OS 窗口。

## 1. 视觉语言（两个变体，用户挑一定稿）

- **v4-1 纯结构风**：Mondrian 原味——3px 黑结构线、正交网格、硬投影、直角零圆角；v2/destijl-dock 的执行基因。
- **v4-2 瑞典极简升级**：De Stijl 的骨＋北欧的呼吸——构成色块与结构骨架保留，结构线降为 1.5–2px 且局部让位给留白，圆角适度（4–8px 仅限交互控件），版面密度放松 15–20%，暖纸底比重加大。结构与色块的可识别度不得低于 v4-1。

## 2. 三态与窗口叙事（双窗口架构）

- **态A 启动台**：桌面上只有对话窗（独立 OS 窗口，默认大尺寸居中）；磁带工程列表为窗口内抽屉；对话流主体。可画一个桌面背景提示（窗口外是 OS 桌面，表现"独立窗口"事实）。
- **态B 进入中**：对话流内状态控件（待机→进行中→完成）＋磁带 icon 三态动画分镜（继承 v3 §2.3）；同时画 **OS 窗口 Z 序分镜**（桌面视角 4 帧）：帧1 对话窗满幅独占 → 帧2 DAW 窗口从对话窗身后升起（部分露出）→ 帧3 DAW 落位（对话窗置顶层、DAW 常驻底层）→ 帧4 对话窗收缩至主窗位。分镜标注 Z 序（对话窗 always-on-top / DAW always-below）与缓动意图。
- **态C 工程内（二态切换）**：
  - **打开态**：对话窗＝**居中（或略偏一侧）的大面板（约 55–62% 宽，主导前景）**，DAW 窗口沉为其四周背景（完整露出、可轻暗化）；对话窗内渲染工程上下文对话流＋控件卡（含效果器宏卡，继承 v3 §6）；磁带抽屉收拢为窗口内边缘抽屉（保留手动新建/打开入口）。
  - **缩起态**：对话窗整体最小化退场（OS 原生动画隐喻），**DAW 全屏成为唯一前景**；画一帧 DAW 独占画面＋最小化召回注记（任务栏条目/Alt-Tab，M2 级轻提示示意）。
  - **切换即 OS 窗口操作**，无任何中间态/把手/常驻条。
- **沉降分镜（态B，桌面视角 4 帧，按二态语义更新）**：帧1 对话窗满幅独占 → 帧2 DAW 窗口从对话窗身后升起 → 帧3 DAW 落位沉后、对话窗保持前景 → 帧4 用户按最小化：对话窗退场、DAW 全屏接管（标注：打开/最小化均为 OS 窗口级操作，对话窗 always-on-top 仅在打开态成立）。

## 3. 新增硬约束：投影友好（校园课堂场景，展演 5 分钟在教室大屏呈现）

1. 正文 ≥14px 不变；关键信息（当前节点/宏名/按钮）字号再上调一档；
2. 大色块面积占比积极使用——投影低亮度环境下靠色块辨识，不靠细线；
3. 对比度 ≥4.5:1 不变；避免暗底上的细灰字（v4-2 尤其注意）；
4. 屏幕截图若被压缩转码，色块与结构必须依然可读（自测：半尺寸缩放后仍可辨认层级）。
