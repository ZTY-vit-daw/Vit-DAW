# Vit-DAW Agent GUI · 三方向初稿设计 SPEC v1（2026-09-02）

> Phase 3 产物（huashu-design 流程）。三方向 subagent 的唯一共同输入 + 本次用户输入沉淀。
> 需求事实源：DESIGN_BRIEF.md v1.1；本文件在其上叠加 2026-09-02 用户两项补充指示。

## 0. 用户输入沉淀（原话）

- 宿主环境：**Godot DAW 前端为浅色**（2026-09-02 问答）。
- 视觉锚点：**延续 Mondrian 硬边风**（纸灰 #f4f4f1 / 墨 2px 边框 / 硬投影 / 蓝 #1557d6），非软阴影浅色层（2026-09-02 问答）。
- 补充①（原话）：「切记，我们改造的重点就是对话流的动态显示，一定要像codex，zocode，dsh一样是具有动态可执行轨迹显示的。」
- 补充②（原话）：「如果可以，现在的风格虽然是结构主义，但是我还是想让整体设计往dsh，codex这种风格上靠。」

**推论**：轨迹流（交互面④）是整个面板的设计主角；三版都携带终端 agent 的实时流式轨迹 DNA（思考动态行 + 逐步执行短句 + 状态/时长 + 可展开）；差异在骨架与气质诠释。

## 1. 产品与画布

- 对象：Vit-DAW AI 混音助手的 Agent 对话面板（内嵌 DAW 窄侧栏，420px 基准）。
- 画布：中性灰底（#8f9399 系）示意内嵌环境，居中一块 420px 面板（高约 920px），背板左上角小字「Vit-DAW · Agent 面板 · 420px 基准」；背板右上角宽度切换器 [360|420|540|720]（呈现层 chrome，非面板内容）。
- **画布内（面板外）不得出现任何 DAW 元素**；面板内不得出现轨道编辑器/调音台/传输条等 DAW 界面元素。
- 面板 360px 不溢出不破版；720px 只留白舒展不结构重排。
- 中文界面（工具名/轨名可保留英文标识）。

## 2. form 推导五问（速答）

- 叙事角色：可交互产品面板原型（非网站整页）。
- 观众距离：桌面 0.5–1m，密集阅读。
- 温度：冷静、专业、可信赖，带一点工程酷（terminal agent 气质）。
- 容量：420px 内塞 2 条用户消息 + 2 个轨迹块（共 9 步 + 思考行）+ 4 张卡（2 待裁 + 2 沉淀）+ 权限开关 + 输入框——行高与留白需克制但可读（摘要 ≥12px，正文 ≥13px）。
- 视觉母题：**「可追溯的轨迹」**（工单/日志/树）×**「人来裁」**（裁决语义）——从 Agent 工作过程本身长出来的结构，不是装饰。

## 3. 内容剧本（三版逐字一致）

头部：标题「混音助手」· 工程「夜航西飞 · demo」· 状态「已连接」· 权限开关 普通/完全（普通默认激活；切到完全显示副注「连续执行试验步 · 每步仍可回滚」）。

T1 用户：「副歌的人声总是糊在鼓里，帮我听听是怎么回事。」

T1 轨迹（全部已完成）：
1. ccb.observation_catalog 目录发现 · 0.3s · 打开观察目录，18 个视图可用｜细节：优先级队列 dynamics / stereo_space 两维度尚未覆盖
2. mix.masking_relationship 掩蔽关系 · 1.8s · 主唱 2–4kHz 与镲片能量重叠｜细节：副歌段 masking score 0.71（阈值 0.60），频段 2.1–3.9kHz
3. track.vocals 频段动态 · 2.4s · 副歌段 200–400Hz 堆积 +3.2dB｜细节：band_profile 真值 62.8dB @315Hz，Q 区间能量持续偏高
4. mix.static_level_relationship 电平关系 · 1.1s · 主唱相对底鼓电平正常，排除电平问题｜细节：Δ −0.4dB，在正常区间内

T1 确认卡【已批准 · 14:32】：卡题「确认 · 第 1 轮试验步」；改动「对 主唱 vocals 做 static_eq：315Hz −5dB（Q 1.8）」；假设「低频堆积让主唱失去轮廓，并与底鼓形成掩蔽」；预期「副歌主唱更清晰，不牺牲厚度」。

T1 执行轨迹：
5. apply static_eq · 0.6s · 已应用并回读校验（−5.0dB 确认）｜细节：单一 mutation，revision +1
6. render A/B · 3.2s · 12s 对照片段渲染完成｜细节：同源同窗同路由，bypass/processed 对照

T1 判定卡【已裁决】：第 1/3 轮 · A/B 试听；摘要 static_eq 315Hz −5dB（Q 1.8）；标识「这是试验步，可一键回滚」；裁决结果「听不出 · 下一轮加码 → 已按此进入第 2 轮」（沉淀态呈现为正常进取路径，非消极态）。

T2 用户：「好，这轮动静大一点，我想明确听出差别。」

T2 轨迹（live）：思考行轮换文案「正在复核掩蔽关系… / 正在规划第 2 轮剂量… / 正在校验回滚边界…」；步骤：
7. 复核 band_profile · 1.2s · 62.8dB @315Hz，与首轮观察一致｜细节：剂量界内余量 −3.5dB
8. 规划加码剂量 · 0.4s · 315Hz −5dB → −8dB，仍在一键回滚界内｜细节：建议保留 Q 1.8 不变，单参数单步
9. render A/B（第 2 轮）· 进行中（spinner）· 渲染新对照片段…

T2 确认卡【待裁】：卡题「确认 · 第 2 轮加码」；改动「对 主唱 vocals 做 static_eq：315Hz −8dB（Q 1.8）」；假设「−5dB 未过可听阈值，加码至 −8dB 让差异可感知」；预期「这轮 A/B 差异应可明确听出；过猛可一键回退一半」；按钮 批准 / 拒绝。

T2 判定卡【待判定 · 本稿主角】：第 2/3 轮 · A/B 试听；摘要 static_eq 315Hz −8dB（Q 1.8）；标识「这是试验步，可一键回滚」；A 播放器「改动前 · original」+ B 播放器「改动后 · processed」（12s，播放键、进度、A/B 快速对比）；四裁决按钮：听得出·保留 / 听得出·更糟·回滚 / 听不出·下一轮加码 / 太过了·回退一半。

输入框：占位「描述你想要的混音…」+ 发送键。

## 4. 五交互面与硬约束（继承 BRIEF §1–2）

① 确认卡×2（T1 已批准沉淀 + T2 待裁）：改动/假设/预期三句必显；批准/拒绝；点击进入对应沉淀态（不消失、视觉沉淀）。
② 判定卡×2（T1 已裁决沉淀 + T2 待判定）：A/B 双播放器（可播放动效+快速对比）、「这是试验步，可一键回滚」视觉权重要够（信任锚）、第 N/M 轮、四裁决按钮（点击进入对应沉淀态）；**与确认卡同构**（同一组件家族，同为「Agent 动作→人来裁」）；「听不出·下一轮加码」呈现为常态/进取路径。
③ 权限开关两档：当前档清晰可辨、可切换、完全档传达更强 autonomy 与边界感。
④ 轨迹流（主角）：淡灰「正在思考…」动态行（呼吸/游标动效+文案轮换）+ 逐步执行短句流（状态符 + 动作名等宽 + 中文摘要 + 时长；点击展开细节；运行中 spinner）；像终端 agent 实时流，但不做塞进对话流的大面积深色块（B/C 版内），不挤占对话流宽度。
⑤ 对话流容器：全部按时间序内嵌；底部输入框。

## 5. 三方向骨架（互异，不许换皮）

- **A 控制室·深色终端**：整面板深色（webui 深色器件基因 #14161b/#181a22 系）；agent 回合=左侧垂直轨迹树（导轨线串步骤，Codex 式 gutter）；卡片=深色面板+顶部状态色条；命令行式输入（等宽 › 提示符）。色彩仅状态语义（蓝进行/黄回滚锚/绿完成/红拒绝）。
- **B 纸面终端·蒙德里安延续**：纸灰 #f4f4f1+墨 #111 2px 边框+7px 7px 0 硬投影+蓝 #1557d6/黄 #ffd42a/红 #e63426；agent 回合=带序号刻度列（01 02 03…）的「流水工单」条；卡片=白底墨边硬投影+文件夹页签标题；纸面输入框。直角/微圆角（0–4px）。
- **C 工业面板·TE 式**：浅暖灰 #e9e8e4 铝面板+近黑 #17181a+单一信号橙 #f57c00；水平粗规则线分割功能区带；轨迹=「系统日志」行式（行首 LED 状态点、行尾右对齐等宽时长、表格对齐）；卡片=内嵌 keyline 面板；判定卡 A/B=硬件传输模块（大播放键）；物理拨杆开关；刻字式大写微标签。

## 6. 交互与动画（vanilla JS，无外部依赖）

载入轨迹步骤错落浮现；思考行文案轮换（~2.8s）+光标闪烁；运行中步骤 spinner；播放器播放态进度动画（12s）+播放/暂停图标切换；A/B 快速对比切换；裁决/批准/拒绝点击进入沉淀态；权限开关切换+副注；宽度切换器 360/420/540/720；URL `?scroll=judge` 自动滚到 T2 判定卡。动画克制（100–300ms 过渡）。

## 7. 红线（反 slop + 任务红线）

- 不用紫色渐变、emoji 图标、「圆角卡+左边条 accent」泛用组合；图标=极简几何 inline SVG（播放/暂停/撤销/勾/叉，数量克制）。
- 无外部资源（字体/CDN/图片全不用）；系统字体栈：中文 Microsoft YaHei；等宽 Consolas, "SFMono-Regular", Menlo。
- 无 Lorem；文案=第 3 节剧本逐字。单文件自包含，UTF-8，lang=zh-CN。
- 交付：`design/gui/directions/direction-{a,b,c}.html`。
